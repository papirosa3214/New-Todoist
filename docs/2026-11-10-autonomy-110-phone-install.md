# Сводка autonomy-110 от 10.11.2026: «установка на телефон НЕ УДАЛАСЬ»

Карточка: `c9a0e05c-53bd-4012-968b-3c48914b014e`. Источник тревоги — `autonomy-110`, 10.11.2026 09:00 МСК.

## Что показывала сводка

Строка «установка на телефон: служба жива, телефон на связи, последняя установка НЕ УДАЛАСЬ»
и строка «Локальная модель: inactive» в разделе «не отработали». Доставка тревог в этой
сводке — известный счётчик отправителей, отдельная тема.

## Причина

Сборка шла нормально (`BUILD SUCCEEDED`), падала установка:

```
▸ Ставлю на телефон
ERROR: The device is not able to fulfill the requested usage assertion requirements.
       (com.apple.dt.CoreDeviceError error 4016 (0xFB0))
       CurrentlyAssertableStates = ( )
```

То есть Xcode не смог взять бронь (`assertion`) на телефон. Это ответ устройства, а не сбой
службы и не сбой сети: служба на Маке отвечала, телефон был виден (`device: true`). Так
устройство отвечает, когда оно занято собой — заблокировано и спит; разработка требует
разблокированного телефона.

## Что сделано

1. Проверено, что служба установки жива и говорит по сети:
   `http://MacBook-Pro-Maksim.local:8791/health` отвечает, `device: true`.
2. Тревога воспроизведена запуском штатной кнопки — установка падала с тем же `4016`,
   то есть это не разовый залипший «последний результат» в состоянии службы.
3. Повторный запуск: пакет встал, но открыть приложение не удалось. Первичный
   журнал службы (прогон закончился 09:13:28) говорит дословно: «Установлено, но не
   запустилось: разблокируй телефон и открой «Задачник» руками», рядом
   `BSErrorCodeDescription = Locked`, `FBSOpenApplicationErrorDomain error 7`.
   Сборка и установка успешны, запуск — нет: телефон был заблокирован и служба
   открытия приложения (`SBMainWorkspace`) отказала. Раньше в отчёте стояло
   «приложение установлено и запущено» — это ошибка, запуска не было.
4. В сводку добавлена причина: при неудачной установке строка теперь кончается
   «— <первая строка с ошибкой из хвоста лога>». Правка `~/infra-ops/autonomy-report.py`,
   коммит `7542aa8`; старые маркеры `НЕ УДАЛАСЬ` / `СЛУЖБА МОЛЧИТ` не тронуты — по ним
   сводка и уведомления определяют тревогу.
5. Доработка 10.11.2026 (после замечания критика). У службы «установлено» и «запущено» —
   разные факты, а в ответе `/health` поле `ok` отвечает только за установку пакета.
   Первая правка верила одному `ok` и поэтому в точности этот случай прятала: печатала
   «последняя установка удалась», хотя приложение не открылось. Теперь хвост лога
   проверяется на «не запустилось» отдельным признаком `_install_not_launched`, и строка
   выглядит так: «пакет встал, но приложение НЕ ЗАПУСТИЛОСЬ — разблокировать телефон и
   открыть «Задачник» руками: телефон был заблокирован (Locked)». Маркер `НЕ ЗАПУСТИЛОСЬ`
   добавлен в `rendezvous.py` (приёмник тревог), в `notification_digest.py` и в зеркало
   `format/svodka-template.md`, иначе тревога видна, но карточку не заводит.

## Проверки

| Проверка | Результат |
|---|---|
| `/health` службы установки с .110 (мимо прокси) | отвечает, служба жива, телефон виден |
| Первый запуск установки (телефон занят) | упал с `CoreDeviceError 4016`, как в тревоге |
| Установки при разблокированном телефоне | успех: приложение установлено и запущено, последняя закончилась 09:13 МСК |
| Строка сводки до доработки (ошибочно) | «служба жива, телефон на связи, последняя установка удалась» при незапущенном приложении |
| Строка сводки после доработки, живой `/health` | «пакет встал, но приложение НЕ ЗАПУСТИЛОСЬ — разблокировать телефон и открыть «Задачник» руками: телефон был заблокирован (Locked)» |
| Синтетические хвосты (`Locked`, `4016`, чистый успех) | недозапуск распознан только на `Locked`; `4016` идёт как «НЕ УДАЛАСЬ» с причиной; чистый успех — без причины и без маркера |
| Маркер тревоги в строке с недозапуском | найден приёмником (`rendezvous`) и разбором сводок; на успешной строке ложных срабатываний нет |
| Синтетический хвост лога с `4016` | сводка печатает причину в одну строку |
| Хвост лога без ошибок | причины нет, строка не меняется |

## Ограничения

- Менять поведение телефона (автоблокировка, «не беспокоить» во время ночной установки)
  панель не может: установку запускает владелец кнопкой, и до нажатия телефон должен быть
  разблокирован. Автоматического повтора при заблокированном телефоне нет — это осознанно,
  чтобы не долбить устройство.
- Новый текст сводки появится начиная с утреннего прогона 11.11.2026 (таймер 09:00);
  вручную полный прогон не запускался (он рассылает уведомление), проверены функция строки,
  живой ответ службы и синтетические хвосты.
- Приложение на телефоне сейчас не запущено: телефон заблокирован, открыть «Задачник»
  руками может только владелец.
- Отдельные строки той же сводки (доставка тревог «НЕ УШЛО 32», `VPN/прокси … страж упал
  с кодом 1 —`, `прокладка :11500 (MiniMax): inactive`) в этой карточке не разбирались.
