# Сводка autonomy-110 от 10.11.2026: «установка на телефон НЕ УДАЛАСЬ»

Карточка: `c9a0e05c-53bd-4012-968b-3c48914b014e`. Источник тревоги — `autonomy-110`, 10.11.2026 09:00 МСК.

## Что показывала сводка

Строка «установка на телефон: служба жива, телефон на связи, последняя установка НЕ УДАЛАСЬ»
и строка «Локальная модель: inactive» в разделе «не отработали». Доставка тревог в этой
сводке — известный счётчик отправителей, отдельная тема.

## Причина

Сборка шла нормально (`BUILD SUCCEEDED`), падала установка:

```
▸ Ставлю на телефон
ERROR: The device is not able to fulfill the requested usage assertion requirements.
       (com.apple.dt.CoreDeviceError error 4016 (0xFB0))
       CurrentlyAssertableStates = ( )
```

То есть Xcode не смог взять бронь (`assertion`) на телефон. Это ответ устройства, а не сбой
службы и не сбой сети: служба на Маке отвечала, телефон был виден (`device: true`). Так
устройство отвечает, когда оно занято собой — заблокировано и спит; разработка требует
разблокированного телефона.

## Что сделано

1. Проверено, что служба установки жива и говорит по сети:
   `http://MacBook-Pro-Maksim.local:8791/health` отвечает, `device: true`.
2. Тревога воспроизведена запуском штатной кнопки — установка падала с тем же `4016`,
   то есть это не разовый залипший «последний результат» в состоянии службы.
3. Повторный запуск при разблокированном телефоне: сборка и установка прошли,
   приложение установлено и запущено (`✓ Готово — задачник на телефоне и запущен`).
   Проверено по `devicectl`: `lockState` — `unlocked`, приложение на месте, установка успешна.
4. В сводку добавлена причина: при неудачной установке строка теперь кончается
   «— <первая строка с ошибкой из хвоста лога>». Правка `~/infra-ops/autonomy-report.py`,
   коммит `7542aa8`; старые маркеры `НЕ УДАЛАСЬ` / `СЛУЖБА МОЛЧИТ` не тронуты — по ним
   сводка и уведомления определяют тревогу.

## Ограничения

- Менять поведение телефона (автоблокировка, «не беспокоить» во время ночной установки)
  панель не может: установку запускает владелец кнопкой, и до нажатия телефон должен быть
  разблокирован. Автоматического повтора при заблокированном телефоне нет — это осознанно,
  чтобы не долбить устройство.
- Новый текст сводки появится начиная с утреннего прогона 11.11.2026 (таймер 09:00).
- Отдельные строки той же сводки (доставка тревог «НЕ УШЛО 32», `VPN/прокси … страж упал
  с кодом 1 —`, `прокладка :11500 (MiniMax): inactive`) в этой карточке не разбирались.
