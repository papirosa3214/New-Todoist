# Сервер TaskFlow: продолжение аудита 22.10.2026

## Результат

Проверены остаточные падения runtime/планов и связка настоящий SDK → серверный адаптер → реальные операции host на временных файлах. Живые карточки и сервис не изменялись.

## Исправления файловых инструментов

| Дефект | Последствие | Исправление |
|---|---|---|
| mkdir реализован записью пустого файла | SDK write не создаёт вложенный файл, EISDIR | Родителей создаёт существующая атомарная host write |
| stat реализован через ls файла | SDK ls скрывает обычные файлы | Проверка каталога и метаданных в родительской папке |
| find возвращает объекты вместо строк и не фильтрует glob | Ошибка endsWith, неверная выдача | Преобразование путей и фильтрация маски в серверном адаптере |
| SDK grep запускает локальный rg даже с custom operations | Ищет на сервере вместо удалённого хоста | Удалённое исполнение grep, чтение файла для контекста, лимиты |
| Сигнал отмены файловых вызовов не передан операциям хоста | Отмена SDK не доходит до gateway | AsyncLocalStorage на каждый вызов, проверка pre-abort |

Общий wrapper подключён в обоих entrypoints: inProcessRun и roleHostAccess. Bash сохраняет явный сигнал. Параллельные вызовы получают собственные сигналы.

Первые пять функциональных проб падали на исходном адаптере: /tmp/audit-host-files-red.log. Затем добавлены позитивные и граничные проверки: чтение/правка, перезапись, literal/case/glob/context/limit/no-match, pre-abort и независимые сигналы. Всего 10 тестов serverHostFiles.

## Почему падала старая тестовая база

- planComplete создавал ручной шаг до создания плана: сервер законно импортировал его в план, но тест не завершал его. Независимая заметка теперь создаётся после утверждения, проверена её отвязка от плана.
- roleToolCatalog ожидал старый FORBIDDEN вместо актуального запрета карточной работы в режиме чата EXECUTION_MODE_RESTRICTED.
- inProcessRun смешивал chat/card режимы, повторно сдавал уже автоматически сданную работу, распознавал критика по тексту промпта и передавал неполный отчёт. Исправлены сценарии, сохранены проверки конечных состояний.
- Mock SDK использовал изменяемый общий callback между сессиями. Теперь callback фиксируется при создании сессии. Между тестами очищаются активные состояния тестовых карточек и очередь; карточки с внешними ключами не удаляются. Test-only ожидание фоновых запусков дожидается последующих подготовок.

Это исправления фикстур и ожидания тестов; отдельные новые production-дефекты runtime/планов из старых падений не заявляются.

## Границы доказательств и остатки

Это интеграционная проверка SDK и реальных host file operations с подменённым транспортом и временной файловой системой. Она не доказывает живой role → WebSocket gateway → Mac сценарий. Нужна отдельная сквозная приёмка и отмена на реальном хосте.

Host find ограничен обходом 5000 записей, глубиной и skip-каталогами; при недостаточном усечённом результате SDK получает ошибку с предложением сузить поиск. Полная совместимость с gitignore и семантикой локального rg не заявляется. Низкоуровневый host find по-прежнему игнорирует собственное поле pattern; SDK фильтрует маску в адаптере. Частично недоступные пути при find требуют отдельного усиления диагностики.

Полный сервер ещё не проверен: остальные API/авторизация, фоновые интеграции, миграции/восстановление БД, общие поверхности безопасности и нагрузка остаются в чек-листе. Push, merge, deploy и restart не выполнялись.
