# JEV в TaskFlow: где его можно подключить

Разбор от 16.10.2026, проверен по коду. Это не решение, а список мест.

Общий принцип: в каждом месте эмбеддинги остаются и делают быстрый отбор,
а JEV получает только верхушку списка и выбирает из неё. Если JEV выключен,
упал или не уложился в тайм-аут, остаётся прежний выбор.

## 1. Подбор исполнителя для карточки — главный кандидат

`server/src/routes/dispatch.ts:100`, `pickRole()`. Сейчас роль выбирается по
косинусной близости к `role_embeddings`, а ручной выбор владельца имеет приоритет.
Функция уже возвращает `score` и `margin`, то есть отрыв первой роли от второй.
JEV: включать, когда отрыв маленький и две роли почти равны. Отдавать ему
3 лучшие роли и карточку, а его `Choice` брать как выбор.

## 2. Кто отвечает в групповом чате

`server/src/routes/chats.ts:1478`, `pickRoleForChat()`. Явное @упоминание
побеждает, иначе роль подбирается по смыслу сообщения. JEV: та же схема, что в п.1.
Его уместно включать только для режима «Авто», когда в чате несколько ролей.

## 3. Память ролей

`server/src/lib/memory.ts:377`, `recall()`. Сейчас это косинус плюс порог
`RECALL_MIN_SIMILARITY`, а результат обрезается до `limit`.
JEV: брать ~20 кандидатов выше порога и через `Score` оставлять 6 действительно
полезных. Здесь он прямо закрывает проблему «похожее, но не нужное».
Минус: `recall` вызывается на каждом ходу роли, поэтому нужен тайм-аут
и кэш по запросу.

## 4. Навыки ролей

`server/scripts/trigger.py:336`, `pi_skill_paths_for_role()`. Сейчас список
навыков статический и задаётся в профиле роли: роль получает все свои навыки
независимо от задачи. JEV: выбирать под конкретную карточку из навыков роли.
Это то же, что «JEV для навыков Ekko» на скриншоте.

## 5. Роль по модели для ручных карточек

`server/src/routes/ai.ts:340`, `pickRoleByModel()`. Здесь уже работает
локальная модель-судья (qwen), а запасным вариантом служит подбор по словам.
JEV: либо заменить её (он быстрее локальной 27B), либо сверять с ней
и при расхождении отправлять выбор владельцу. Решать надо после замера на п.1.

## 6. Построение плана: какой состав команды

`server/src/routes/task-collaboration-plans.ts:659`, `proposalFor()`. В режиме
`auto` профиль плана (`full_cycle` / `delivery` / `research` / одиночный исполнитель)
выбирается **регулярными выражениями по словам** («экран», «сервер», «исслед»).
Это самое слабое место: «поправь текст экрана» уже считается полным циклом.
JEV: `Choice` из профилей по карточке. Здесь выигрыш наибольший, а риск
нулевой: черновик плана всё равно утверждается.

## 7. Командная работа: раздача подзадач по ролям

`server/src/runtime/subtaskRoleFanout.ts:62`, `suggestFanoutFromSubtasks()`.
Каждая подзадача сопоставляется с ролью по эмбеддингу (top‑1), а всё, что ниже
`FANOUT_CONFIDENCE`, молча остаётся текущему исполнителю.
JEV: для неуверенных подзадач выбирать роль из трёх лучших и через `Score`
решать, стоит ли вообще параллелить. Работа идёт при подготовке, а не на каждом
ходу, поэтому задержка некритична.

## Чего здесь нет

`resolveAssignee()` (`runtime/coordinationResolver.ts:327`): это не выбор,
а вычисление по правилам «кто отвечает сейчас», и JEV там не нужен.

## Предлагаемый порядок

Начать с п.6 (профиль плана): сейчас там регулярки, выигрыш наибольший,
а план всё равно утверждается. Затем п.1 и п.7: исполнитель и раздача по ролям.
Потом п.3 (память). Пункты 2, 4 и 5 — после того как будут видны реальная
точность и задержка.

## Разбор раздела Ekko «JEV для памяти / навыков» — что нам нужно (16.10.2026)

Сверено с живой базой: в памяти ролей 49 записей (3 вида: факт, урок,
предпочтение; файлов 0), `recall()` отдаёт роли до 6 записей по косинусу ≥ 0.35
на каждый ход. Навыки: `role_skills` (2–3 на роль) — только подпись для экрана; фактически Pi грузит каждой роли все 39 навыков из `~/.pi/agent/skills`. Профили Гермеса (58 навыков) роли сейчас не используют — движок ролей `pi_runtime`. Инструментов TaskFlow у роли 26–27 — сужать не предлагаем: отрезанный нужный инструмент останавливает работу.

| Функция Ekko | Нам | Почему |
| --- | --- | --- |
| Семантический выбор категорий памяти | **не нужно** | видов всего 3, записей 49 — сужать нечего |
| Фильтр нерелевантных воспоминаний | **нужно** | ровно наша беда: косинус приносит «похожее», JEV выкидывает ненужное |
| Переранжирование кандидатов | **нужно, слить с фильтром** | один запрос: оценить ~15 кандидатов, оставить уверенные, отсортировать |
| Проверка записи в память | **полезно, отдельной галочкой** | роли сами пишут предпочтения (23 шт.) — JEV отсеет разовое и мусор |
| Лимит кандидатов, 3 разных порога, свой тайм-аут памяти | **лишнее** | хватит одного порога уверенности; лимит фиксированный (15), тайм-аут — общий из подключения |
| JEV для навыков (подбор под задачу) | **нужно** | роли идут через Pi и получают ВСЕ 39 общих навыков из `~/.pi/agent/skills` (+2 у дизайнера) на любую задачу; JEV выбирал бы 3–5 нужных под карточку |

Итого к добавлению: две галочки — «Отбор памяти для роли» (фильтр + сортировка
одним запросом, с порогом) и «Проверка записи в память». Третья — «Навыки под задачу».
