# Напоминание ролям о памяти и базе знаний

По запросу владельца 23.10.2026 сервер считает вызовы инструментов с начала запуска роли. Если среди первых десяти нет taskflow_recall или taskflow_kb_search, в активную сессию через steer поступает одно внутреннее указание выполнить поиск по смыслу задачи и учесть результат.

Работает в чате (PiRuntimeAdapter) и в карточке (inProcessRun). Новый запуск получает свой счётчик. Обращение к любому из двух источников, включая десятый вызов, отменяет напоминание. Неуспешная попытка поиска тоже считается обращением: при недоступном сервисе повторного давления нет. Discover/describe, запись в память и упоминание инструмента в аргументах других инструментов поиском не считаются.

Указание не создаёт отдельного сообщения владельцу, не запускает новый ход и не прерывает текущий инструмент. Оно просит продолжать работу при недоступном поиске и не пересказывать внутреннюю подсказку в чат. Фактический вызов остаётся решением модели; это напоминание, а не блокировка исполнения.

## Проверка

Unit-тесты сначала выполнены с пустым guard: 4 ожидаемых падения. Интеграционный тест с отключённой передачей указания в SDK обнаружил отсутствие steer. Покрыты граница 9/10, поиск десятым действием, оба инструмента, gateway invoke против discover/describe, однократность и отдельный счётчик нового запуска. Интеграционный сценарий использует настоящую очередь чата и runtime с подменой SDK: указание появляется в steer, в публичных сообщениях его нет.

Внешние CLI-агенты не получают эту подсказку: у них нет общего session.steer; изменение касается встроенного рантайма ролей. Живое поведение модели требует наблюдения после выкладки.

Итог: 47 профильных тестов PASS, tsc --noEmit PASS.
