# Host на Mac доступен всем ролям
16.10.2026. Прямое поручение владельца: все роли ходят на Mac без назначения этапа и согласования плана.

## Изменения
- Общий taskflow содержит taskflow_hosts и taskflow_host_bash/read/write/edit/grep/find/ls. Это операции того же реестра, а не отдельный набор инструментов чата.
- Все роли видят список машин/проектов и онлайн. Ключи машины не раскрываются.
- Можно работать из чата без task_id. При одном доступном проекте machine/project_id не нужны. При нескольких сервер требует явный выбор.
- Автоматически создаётся worktree roles/<task_id>, а без задачи — постоянная рабочая копия роли/проекта. Исполняется через существующий hostOperations и sandbox-exec на Mac.
- Для рабочих задач машина проекта теперь выбирается для любой роли, а не только builder/qa/designer. Явное назначение host_id сохраняет приоритет.
- Чтение разрешено в планировании и обсуждении; команды и правки — в рабочем режиме. Утверждение плана для доступа к машине не требуется.
- Приватные/архивные проекты и недоступные задачи остаются недоступными. Пути read/grep/find/ls ограничены проектом; write/edit — рабочей копией. Команды остаются в существующей песочнице хоста.
- Техническая роль HTTP вызывает /api/role-host/execute с собственной серверной личностью; обработчик общий с операциями taskflow. Управление ключами машин не расширено.

## Проверка
Сборка TypeScript и основное чтение на настоящем host под учёткой роли, без вызова модели. Расширенные тестовые прогоны не запускались по указанию владельца.
