# Восстановление выбора моделей — 04.11.2026

## Причина и восстановление

После обновления Pi до 1.5.0 процесс работал со старым dist/runtime/thinkingLevels.js. Файл импортировал удалённый pi-ai/dist/compat.js, из-за чего GET /api/runtime/models возвращал 400. Исправление уже было в исходниках commit 7f4edfc9, но dist не пересобрали.

Очередь ролей и чатов проверена: 0/0. Снята SQLite backup server/backups/pre-model-catalog-20261104.db. Typecheck и сборка прошли; служба перезапущена при повторно пустой очереди. Авторизованный запрос API: 200, 1593 модели, 143 доступны, 7 провайдеров подключены. Ключи и токены не выводились.

## Обновление каталогов

Раньше singleton ModelRuntime создавался один раз без сетевого обновления; refresh вызывался только на пустом каталоге. Zen пересекался с живым списком, но основной каталог новых моделей не получал.

Теперь при запросе каталогов моделей подключённые провайдеры и публичный Zen обновляются через SDK с allowNetwork. TTL 6 часов, сетевой deadline 15 секунд. Параллельные запросы используют общий Promise, включая создание ModelRuntime. При сбое остаётся кэш; повтор через 5 минут. Сторож ошибок и суточная дедупликация уведомлений описаны в docs/watchers.md. Фонового таймера нет: обновление запускает первое обращение после TTL.
