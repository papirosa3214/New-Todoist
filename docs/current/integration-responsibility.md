# Ответственный за интеграцию в карточке

Структурированные поля tasks.integration_mode (auto/manual/not_required) и integration_owner_id. Черновики сохраняются без назначения. Ответственность для ветки хранится на её корневой карточке; список кандидатов берётся из действующих планов всей ветки, без Критика. Автоматический приоритет: code_orchestrator, architect, единственный исполнитель. При нескольких исполнителях без этих ролей выбор обязателен. Свободный ввод запрещён.

GET/PATCH /api/tasks/:id/integration-responsibility — представление и выбор из участников. В native поле в Сведениях; неброский questionmark.circle открывает пояснения. В web поле рядом с исполнителем. Явный вариант «Не требуется» предназначен для задач без правок репозитория.

Проверка стоит в транзакции утверждения одиночного командного плана и всей ветки, до материализации слотов. Поэтому действует для карточек, созданных любым источником, включая Linear, чат и MCP. Создание и сохранение черновиков, сдача результатов и ревью не ограничиваются этим полем. Назначение включено в task.start/task.plan для ролей. Отдельного обязательного слота не создано.

Проверка на изолированном снимке: 13/13 integration + coordinatorAdmission, серверный tsc успешен. В исходном дереве посторонняя ошибка notesFolders.ts; web build и на чистом HEAD содержит существующие ошибки MarkdownInline и неиспользуемого Icon. Эти файлы не менялись. Нативная сборка успешна; сценарий XCUITest и кадры дополняются после живой проверки.
