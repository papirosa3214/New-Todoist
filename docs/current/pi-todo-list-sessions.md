# To Do List Pi в сессиях владельца: что есть, что нужно клиенту

14.11.2026. Относится к сессиям разговора владельца
(`server/src/routes/owner-sessions.ts`, `runtime/ownerSessionRuntime.ts`) и к
нативному iPhone. Чатов ролей и замороженного веб-клиента не касается.

## Задача

В новых сессиях владельца нужен To Do List, который ведёт агент, и показ
этого списка в существующем интерфейсе TaskFlow. Не параллельная система:
берётся готовое расширение Pi.

## Что реально есть (проверено 14.11.2026)

| Что | Факт |
| --- | --- |
| Официальное расширение Pi | `@juicesharp/rpiv-todo` 2.10.0, стоит пакетом Pi (`~/.pi/agent/settings.json` → `packages`, файлы в `~/.pi/agent/npm/node_modules/@juicesharp/rpiv-todo/`) |
| Что даёт | инструмент `todo` (`create`/`update`/`list`/`get`/`delete`/`clear`), оверлей в терминале, команда `/todos` |
| Где живёт список | в памяти процесса по номеру сессии (`state/store.ts`, `Map<sid, TaskState>`), в транскрипт — как `details` результата `todo` (`tasks` + `nextId`) |
| Как восстанавливается | расширение переигрывает ветку и берёт **последний** результат `todo` (`state/replay.ts` → `replayFromBranch`) |
| Изоляция | по номеру сессии: у отдельной сессии свой слот, чужой слот не читается и не затирается |
| `~/.pi/agent/extensions/taskflow-todo-mirror.ts` | обратное направление: вызовы `taskflow_*` (карточки) → список Pi. Зеркало карточек, не источник списка; в сессиях владельца не грузится |
| Было ли это в сессиях TaskFlow | **нет.** Сессии владельца грузят только явно перечисленные расширения (`hesitation-gate`, `verify-before-claim`) и явный список инструментов — `todo` в него не входил, списка не было вовсе |

Проверка загрузки без терминала (headless): расширение грузится через
`DefaultResourceLoader.additionalExtensionPaths` в обычной серверной
`AgentSession`, инструмент `todo` активен и выполняется, результат приходит с
`details: { tasks, nextId }`. Терминальный интерфейс для этого не нужен.

## Что сделано сервером

1. **Инструмент включён в сессиях владельца** — `runtime/ownerAssistantProfile.ts`:
   расширение Pi добавляется в `SESSION_PI_EXTENSIONS`, имя `todo`
   добавляется в список инструментов профиля и в `keepNames`
   (`installNativeToolCore` иначе сузил бы активный набор). Только для
   собственной сессии владельца (`ASSISTANT_ROLE === "secretary"`);
   субагентам-ролям — как раньше, без него. Нет пакета на машине — нет
   инструмента: сессия работает как прежде, ничего не падает.
2. **Готовый список читается маршрутом** —
   `GET /api/sessions/:id/todos`
   (`routes/owner-session-todos.ts`, разбор — `runtime/ownerSessionTodos.ts`).

Ответ:

```json
{
  "todos": {
    "sessionId": "…",
    "available": true,
    "entryId": "…",
    "updatedAt": "2026-11-14T10:02:00.000Z",
    "nextId": 5,
    "tasks": [
      { "id": 1, "subject": "Собрать факты", "status": "completed" },
      { "id": 2, "subject": "Проверить маршрут", "status": "in_progress", "activeForm": "проверяю маршрут" },
      { "id": 4, "subject": "Сдать отчёт", "status": "pending", "blockedBy": [2] }
    ],
    "counts": { "pending": 1, "in_progress": 1, "completed": 1 }
  }
}
```

Правила ответа:

- `available: false` — в ветке ещё не было вызова `todo` (новая сессия). Это
  не ошибка и не «пустой список по сбою».
- `deleted` (надгробие) в `tasks` не отдаётся; `counts` — по живым задачам.
- `entryId` / `updatedAt` — из какой записи взят список: клиенту есть к чему
  привязать замену, чтобы старый список не лёг поверх нового.
- Неизвестная сессия — `404 session_not_found`, а не пустой список.
- Права — как у остальных сессий владельца: владелец или агент сессий.

Чтение — только файл сессии (`SessionManager.open`, read-only). Второй
`OwnerSessionRuntime` не создаётся и в состояние расширения сервер не лезет.

## Что нужно от занятых файлов (не правил — файлы на момент работы заняты)

Сейчас `routes/owner-sessions.ts`, `runtime/ownerSessionEvents.ts`,
`runtime/ownerSessionRuntime.ts` заняты другой работой по курсору и снимку.
Отдать список в них можно так (обе правки — по одной строке, без смены
смысла):

1. **Снимок.** В `snapshot(id)` (`runtime/ownerSessionRuntime.ts`,
   `readSnapshot`) добавить поле `todos: sessionTodosFromEntries(id, entries)`.
   Клиент тогда получает список вместе со снимком, без второго запроса.
2. **Живое событие.** В `runtime/ownerSessionEvents.ts` для
   `tool_execution_end` с `toolName === "todo"` (`normalizePiEvent`, ветка
   `tool_execution_end`) и для `entry_appended` такой записи добавить в
   `payload` готовый `todos`. Клиент обновляет список по событию, а не по
   разбору `details` у себя (правило «тонкий клиент без нагрева»,
   владелец 13.11.2026).

До этих правок живое обновление возможно существующими событиями:
`entry_appended` с записью и `tool_end` уже несут результат `todo` с
`details`. Это запасной путь, а не обещанный контракт: разбор на телефоне
противоречит правилу тонкого клиента.

## Что нужно iPhone

1. Экран сессии (`Sources/Features/Sessions/OwnerSessionScreen.swift`,
   `Packages/NewChatCore` — `SessionModels` / `SessionReducer`) — место под
   список: компактная панель над полем ввода, как оверлей в терминале Pi.
   Раскладку задаёт владелец; сервер её не выдумывает.
2. Загрузка: `GET /api/sessions/:id/todos` (готовые `tasks` + `counts`),
   показ статусов `pending` / `in_progress` / `completed`, `activeForm` для
   идущей задачи, `blockedBy` — как зависимость.
3. Пусто: `available: false` — панель не показывается вовсе, а не пустой
   блок.
4. Живое обновление — после правки событий (выше) по `todos` в событии; до
   неё — по `message_end`/`agent_settled` перечитывать маршрут.
5. Чаты ролей (`Sources/Chat`, `TaskChatSheet`) не трогаются: списка там нет
   и не должно быть.

## Проверено

`server/test/ownerSessionTodos.test.ts` — три точечных теста:
ветка без записи `todo`; последняя запись побеждает, надгробия и чужие
инструменты не попадают, счётчики верны; маршрут отдаёт список и `404` на
неизвестную сессию. Прогон: `npx vitest run test/ownerSessionTodos.test.ts
--maxWorkers=4`. Типы: `npx tsc --noEmit -p tsconfig.json` — чисто.

## Ограничения (не выдаётся за решение)

- Список читается из файла сессии: пока ход не записал результат `todo` в
  транскрипт, маршрут его не видит. Pi пишет результат инструмента записью в
  транскрипт, а не только в память расширения, поэтому на практике список
  отстаёт максимум на запись.
- У сессий, начатых до включения инструмента, списка нет — `available:false`.
- Заголовок файла сессии ищется по каталогу сессий владельца: если каталог
  когда-нибудь разъедется с `routes/owner-sessions.ts`, маршрут ответит `404`,
  а не пустым списком (тихий отказ не изображается).
