# Координация не блокирует старт общего плана

08.10.2026. Активный task-level Оркестратор корневой карточки мог читать и утверждать план, но собственный запуск делал can_use_plan=false, а approveBranch дополнительно отвергал agent_state=in_progress.

Исправление: общий предикат hasOnlyBranchCoordination разрешает согласование только для корня существующей ветки с черновиком, назначенным аккаунтом с действующим orchestrate и без утверждённого плана. Все живые заходы должны быть координаторами без subtaskId. Рабочие слоты/attempts, второй исполнитель, review-job и отозванные права сохраняют блокировку. Дочерние карточки не получают исключение. busy остаётся true; can_launch и смена исполнителя не разблокируются. Согласование материализует рабочие узлы и запускает их только по зависимостям. Координатор не останавливается.

Триггер пилота: комментарий в назначенной Оркестратору родительской карточке породил role_run_jobs(reason=commented). Это координационный заход, а не прохождение узла общего графа.

Проверки: до правки воспроизведён отказ; после 20/20 (branchPlan, taskExecutionState, coordinatorAdmission), дополнительные проверки review-очереди и отзыва права. Нативный клиент не меняется. Новый общий план: 7156f0a1-d6d3-454a-9391-1e5d7166abba. Импортированная старая ветка оставлена под удаление.

Назначение и комментарий имеют разные эффекты: назначение не запускает работу само по себе; комментарий может разбудить назначенного агента. Поэтому подготовительные заметки пилота записываем в документацию проекта.
