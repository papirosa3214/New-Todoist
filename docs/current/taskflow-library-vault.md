# TaskFlow Library как волт Obsidian: файловый слой и мост БД ↔ .md

**Дата:** 01.11.2026. **Основа:** код в `main` и живая база `server/taskflow.db` на .110.

## Что это

TaskFlow Library (корневая папка `journal_folders` с `is_kb_root=1`, id=182) — **виртуальные
папки в SQLite**, а не папка на диске: дерево папок в `journal_folders`, заметки — в
`user_notes` (на 01.11.2026 в Library 934 заметки). Obsidian читает только каталог с
`.md`-файлами, поэтому указать ему на «папку библиотеки» нельзя.

Решение: над базой появился **файловый слой** — папка `kb-files/` в корне репозитория,
зеркалящая дерево Library файлами `.md` с frontmatter-свойствами. Мост
`server/scripts/kb-files-sync.ts` держит базу и файлы согласованными в обе стороны.

## Раскладка

| Что | Где |
|---|---|
| Файлы библиотеки (волт) | `~/Проекты/New-Todoist/kb-files/` (в `.gitignore`) — только `.md` и `.obsidian` |
| Служебное (вне волта) | `~/Проекты/New-Todoist/kb-state/` — состояние, логи, бэкапы, чёрный список (тоже в `.gitignore`) |
| Мост | `server/scripts/kb-files-sync.ts` (запуск: `npx tsx scripts/kb-files-sync.ts`) |
| Автозапуск | systemd **user**-юнит `kb-files-sync.timer` — каждые 2 минуты |
| Обсидиан на .110 | `~/apps/obsidian/` (AppImage 1.14.5, распакован), systemd-юнит `obsidian-headless.service` (Xvfb :99) |
| CLI обсидиана | `~/bin/obsidian-cli` (работает без DISPLAY — через `~/.obsidian-cli.sock`) |
| Волт на Mac | `~/TaskFlow-Library/` — зеркало через `~/bin/taskflow-kb-mirror.sh`, launchd-агент `com.taskflow.kb-mirror` (раз в минуту) |
| Шара для телефона | WebDAV :5010, шара `/taskflow-library` → `kb-files/` (в конфиге `webdav-obsidian/config.yaml`) |
| Корзина зеркала | `~/TaskFlow-Library/.trash-mirror/` |

Служебные файлы вынесены из волта намеренно: телефон тянет волт по WebDAV, и растущий
лог моста в нём означал бы постоянную пересинхронизацию на телефоне.

Волт «Хранилище» (`~/Хранилище` на Mac, `~/Проекты/Хранилище` на .110) не затронут:
Library — отдельная папка и отдельная шара WebDAV.

## Как работает мост

1. **Импорт (файл → база).** Хэш тела файла и свойства `title` сверяется с
   `.sync-state.json`. Если файл менял человек — текст переводится в TipTap и пишется в
   `user_notes` (заголовок берётся из frontmatter). Новый файл без `id` создаётся как
   новая заметка, и в его frontmatter дописывается `id`.
2. **Экспорт (база → файл).** `user_notes.content` переводится в markdown и пишется в файл
   с frontmatter: `id`, `title`, `category`, `source_task`, `folder`, `created`, `updated`.
   Чужие ключи frontmatter (свойства обсидиана) сохраняются.

Порядок в прогоне: **сначала импорт, потом экспорт**. Иначе правка человека и запись роли
в одной заметке затирали бы друг друга.

Тонкости, которые стоит знать:

- **Удаление файла в обсидиане не удаляет заметку.** Заметка переживает удаление файла;
  пропавший файл попадает в лог моста как предупреждение.
- **Постоянную категорию** (`kb_category`) мост при импорте не перезаписывает — её
  проставляет Помощник владельца (`server/src/lib/kbCategories.ts`). В файл категория
  только выгружается.
- **Имя файла** — по заголовку из базы, но если человек переименовал файл в обсидиане,
  его имя сохраняется: файл с совпадающим телом и совпадающим свойством `title`
  считается «переименованным человеком».
- **Правка человека, которую мост перезаписывает**, сохраняется в `kb-files/.backups/`
  (папка с точкой — обсидиан её не видит).
- **Конвертация TipTap ↔ Markdown** берётся из готовых модулей сервера
  (`server/src/lib/tiptapToMarkdown.ts`, `markdownToTiptap.ts`) — свои не писались.

### Переименования и «протухшие» копии

Переименование заметки в базе = файл на сервере переезжает на новое имя. Старый файл
мост убирает и записывает его путь в **чёрный список** `kb-state/stale-files.txt`.
Зеркало на Mac читает этот список и не возвращает такие файлы на сервер — иначе
заметка задваивалась бы (старый файл возвращался бы пушем, мост снова его убирал, и
это повторялось бы по кругу). Файлы, убранные зеркалом, лежат в
`~/TaskFlow-Library/.trash-mirror/` (восстановимы).

### Телефон

Волт отдаётся телефону тем же WebDAV, что и «Хранилище» (плагин Remotely Save на
айфоне). Отдельная шара `/taskflow-library` → `kb-files/`.

**Имя папки волта на айфоне должно быть `taskflow-library` — строчными, без
заглавных.** Причина в плагине: он берёт имя волта как «удалённую базовую папку» и
проверяет, что каждый путь из ответа сервера начинается с `/<имя>/` — сравнение
**регистрозависимое**. А wsgidav отдаёт имя шары всегда в нижнем регистре (с
заглавной буквы в ключе конфига служба вообще не стартует: `ValueError: Invalid
path`). Поэтому «TaskFlow-Library» с большой буквы даёт на телефоне ошибку
`"/taskflow-library" after stripping doesn't starts with "/TaskFlow-Library/"`.

Проверено экспериментом (клиент `webdav-client`, как в плагине): при базовой папке
`taskflow-library` пути сервера совпадают с ожиданием плагина.

Правки с телефона идут тем же путём: телефон → .110 → мост → БД.

### Синхронизация Mac ↔ .110

`~/bin/taskflow-kb-mirror.sh` (launchd, раз в минуту) работает в три шага:

1. **уборка** — локальные файлы, которых на сервере больше нет, и пути из чёрного
   списка сервера уезжают в `.trash-mirror/`; свежие правки (младше 2 минут) не
   трогаются — их пуш идёт следующим шагом;
2. **пуш** — правки человека с Mac на .110 (`--update`: затирается только то, что
   новее на сервере);
3. **пул** — изменения агентов и моста с .110 на Mac (`--delete --update`).

Конфликт «человек и агент правят одну заметку» решается по mtime: побеждает более
свежий, проигравший вариант остаётся в бэкапах на .110.

## Как агентам пользоваться

Роли работают с библиотекой через `taskflow_kb_search` / `taskflow_doc_write` (это БД).
Файловый слой добавляет живой обсидиан на .110 — из роли доступно:

```bash
obsidian-cli vaults                                  # список волтов
obsidian-cli search query="координация" limit=10     # поиск по индексу обсидиана
obsidian-cli backlinks file="<имя заметки>"          # обратные ссылки
obsidian-cli tags sort=count counts                  # теги
obsidian-cli properties path="<путь/к/заметке.md>"   # свойства заметки
obsidian-cli read path="<путь/к/заметке.md>"         # текст заметки
```

Ограничение: CLI ходит в запущенное приложение (`~/.obsidian-cli.sock`). Если обсидиан на
.110 упал — CLI вернёт ошибку; поднимает его `systemctl --user start obsidian-headless.service`.

## Что не сделано (по решению владельца)

- Роли **не переведены** на чтение из файлов: их `taskflow_kb_*` работают как раньше, с БД.
- Поиск ролей (`taskflow_kb_search`) идёт через RAGFlow, а не через индекс обсидиана.
- Одноимённые папки в Library («wake watcher probe» и подобные) дают одинаковые имена
  файлов в разных ветках — различаются они путём, а не именем.
