# Рутины (крон-задачи) — пакет реализации

Дата: 23.10.2026. Автор: Разработчик (слот delivery).
Карточка: `c14e6335-6157-4691-ab54-b922b643ef17`, шаг `2494178c-fa77-41b6-b990-96ea7d422859`.
Вход: `feature_spec` (аналитик), `architecture_decision` (архитектор), `feature_ux_spec` (дизайнер).
Ответственный за перенос в `main`: архитектор.

## Что сделано

Пять точечных правок из решения архитектора от 22.10.2026 плюс правки по двум
критичным дефектам разбора дизайнера (`docs/2026-10-22-routines-ux-review.md`).

1. **Единый якорь запуска.** Первый `next_run_at` при создании рутины и при
   превью считается от даты создания в зоне рутины, а не от фиксированного
   1 января 1970 года. Раньше рутина «еженедельно», созданная в понедельник,
   первый раз срабатывала в четверг, а «ежемесячно» — первого числа.
   Явный выбор дня в правиле (день недели или число месяца) главнее якоря.
2. **Контракт меток.** В шаблоне задачи метки задаются именами, а ручка
   создания карточки принимает только идентификаторы: рутина падала с ошибкой
   «карточка не создана». Теперь имена переводятся в метки владельца рутины
   (`server/src/runtime/schedules/labels.ts`), а несуществующая метка
   отвергается сразу при создании рутины, а не в момент запуска.
3. **Граница «cron не в первой версии».** Произвольное расписание — нерешённая
   развилка владельца, поэтому ручки `POST /api/schedules`, `PATCH /api/schedules/:id`
   и `GET /api/schedules/preview` отказывают ему явной ошибкой.
4. **Два выключателя рутин** (`server/src/runtime/schedules/feature.ts`):
   `TASKFLOW_ROUTINES_ENABLED=0` гасит механизм целиком, `TASKFLOW_ROUTINES_TICK_ENABLED=0`
   — только запуск по расписанию (ручной запуск «Запустить сейчас» работает).
   Значение по умолчанию — «включено»; откат делается переменной окружения,
   без новой выкладки.
5. **Мёртвый код расписания на Python** (`server/scripts/scheduler.py`) удалён
   отдельным коммитом — вторая реализация правил путала чтение кода.

По разбору дизайнера: веб-экран «Мои рутины» переписан по его замечаниям
(форма с выбором дня недели и дня месяца, «Запустить сейчас» с понятным
исходом в каждом из трёх случаев, история по-русски с причиной, «показать
все», «следующий запуск» словами, радиогруппа правила, кнопка «Отмена»,
подтверждение «Рутина создана»). Сервер отдаёт причину пропуска или ошибки в
ответе ручного запуска (`run.detail`).

## Ограничения

- Код не перенесён в `main` и не выложен на боевой сервер: перенос делает
  архитектор после ревью, выкладка — отдельный шаг Инженера .110.
- Веб-сборка (`npm run build`) падает на 10 ошибках типов в файлах, которых
  эта работа не касалась (`LibraryScreen.tsx`, `CollaborationPlanPanel.tsx`,
  `DayHours.tsx`, `UpcomingCalendar.tsx`, `LabelTasksScreen.tsx`,
  `AttachmentViewerSheet.tsx`): ошибки те же, что на коммите 22b74254, до
  этой работы.
- Боевой прогон «ждать реального срабатывания по расписанию» не делался:
  тесты идут на копии базы.
- Клиент на телефоне в эту карточку не входит — он ведётся отдельно.
