## Единственный допуск: сдача интегратором

При живой проверке после включения обнаружен ещё один обход: sweepUnmergedBranches автоматически ставил любую неслитую roles/* в очередь. Так в прогон попала старая заблокированная диагностика df3d2c61-eac8-4bfa-9c06-1996595ba671, trigger=sweep. Режим снова выключен, процессная группа фонового прогона завершена.

По прямому уточнению владельца удалены sweepUnmergedBranches и вход через финальный шаг Оркестратора. Единственный вызывающий enqueueMerge в сервере — сдача isIntegrationPlanStep в routes/subtasks.ts. enqueueMerge отвергает другие trigger; processMerge не запускает тесты для старых sweep/orchestrator записей. Повторное предъявление сданного шага интегратора может заменить старую недопущенную запись. requeueMerge не возрождает записи без интеграционного допуска.

Три регрессионных теста падали до правки: завершённая ветка без допуска не должна подхватываться; sweep/orchestrator не могут создавать очередь; старая sweep-запись не должна запускать тесты, новая сдача интегратора допускает её штатно. После правки очередь+гейт: 32 PASS. tsc PASS.
