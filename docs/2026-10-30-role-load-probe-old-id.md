# Проба загрузки ролей: «no such column: OLD.id» (карточка b2ac0a43)

Дата: 30.10.2026. Роль: Инженер .110. Карточка: `b2ac0a43-cad0-4038-bdf0-261630c748f2`
(инцидент сторожа `role-load-alert`).

## Симптом

Карточка-инцидент «Гант учитывает завершённую работу как текущую нагрузку» с
причиной `Проба readRoleLoad не прошла: no such column: OLD.id`. Проба
`checkRoleLoad` (`server/src/lib/roleLoadWatcher.ts`) падала на первых же
записях — вставка пробной карточки и шага.

## Хронология

| Когда | Что |
|---|---|
| 25.10.2026 22:02 | Коммит `d96358f9` — журнал изменений карточки (дельты). Триггеры журнала созданы с условием «что-то изменилось» (`NEW."col" IS NOT OLD."col"`) и на INSERT, и на DELETE. |
| 25.10.2026 22:09 | Проба впервые упала с `no such column: OLD.id` — сторож завёл карточку-инцидент. |
| 25.10.2026 22:18 | Коммит `030b9f18` — починка: условие только на UPDATE и **DROP перед CREATE**. |
| после выкладки 25.10 | Каждый старт сервера пересоздаёт триггеры (`ensureTaskChangesLedger()` при регистрации маршрутов задач) — боевая база починена сама. |

## Причина

В триггере INSERT строки OLD не существует: SQLite отвергает ссылку
`OLD."id"`, когда триггер сработал на вставке. У `subtasks`, `task_events`,
`comments` колонка `id` есть — вставка в них падала; проба начинается с
вставки в `tasks` и `subtasks`, поэтому первая же запись роняла её с той же
ошибкой. `CREATE TRIGGER IF NOT EXISTS` не заменяет тело триггера, поэтому
сломанный триггер в боевой базе пережил бы правку кода — отсюда DROP перед
CREATE.

## Проверки

1. **Воспроизведение причины.** На свежей базе поставлены триггеры версии
   `d96358f9` → `checkRoleLoad` = `{ok:false, reason:"no such column: OLD.id"}`;
   затем поставлены триггеры нынешнего кода → `{ok:true}`. Причина подтверждена.
2. **Проба на копии боевой базы** (`server/backups/pre-deploy-20261030-1433.db`,
   снят штатным бэкапом; живая база не открывалась и не менялась): приложение
   поднято на копии, с временными триггерами реальтайма, `checkRoleLoad` —
   3 пробы из 3 зелёные; число карточек до и после пробы одинаковое, пробных
   карточек (`role-load-probe-%`) — ноль.
3. **Данные для Ганта с той же копии:** 24 ч — 8 интервалов, 0 активных,
   0 открытых; 3 дня — 50; неделя — 182. Активной работы нет, завершённые
   интервалы остались в истории.
4. **Регрессии:** `test/coordination` — 7 файлов, 98 тестов, все зелёные
   (включая `roleLoadWatcher.test.ts`).
5. **Живой сервер:** `GET /api/coordination/role-load?window=24h` — 200,
   ответ за ~10 мс; трекер пишет в боевую базу штатно (карточка создана,
   шаг назначен, записи попыток и событий пишутся) — сломанного триггера на
   боевой базе нет.

базы (слепок 14:33, сервер перезапущен в 14:34) — схема и код совпадают с
