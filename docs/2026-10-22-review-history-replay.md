## Как запускалось

Одна команда, ровно три теста:
npx vitest run test/reviewHistoryReplay.test.ts

Прогон в отдельном worktree /home/maksim/.local/state/taskflow-runs/worktrees/codex-review-history-replay/server, на Node 22.23.1. Основа — 3e463ee3, с той же логикой runtime, которая выложена на сервер. Производственный runtime при этой работе не менялся.

База тестовая и изолированная. Историческая фикстура снята чтением живой базы и резервной копии; изменённые карточки создавались только в тестовой базе. Внешние модели, JEV и поиск контекста заменены записанными ответами/пустой справкой. Настоящие: worker очереди с defaultExecutor, admission, runtime обработки ответа SDK, блокировка, API планов/сдачи результатов/ревью, граф доработки, сохранение версий, проверка повторного запуска в новом процессе.

Дополнительно восстановлены семь исторических узлов и подшагов плана tcp_dcf5dddd-e4ad-441b-9c7c-cda4ed948e0d; незавершённый итоговый проверяющий восстановлен в todo. - 359 ожидавших записей взяты из server/backups/pre-review-budget-deploy-20261022-002609.db. В резервной копии они уже cancelled после остановки цикла. Только при воспроизведении их состояние восстановлено как queued. Это не утверждение, что все исторические задания одновременно были queued с самого начала дня.
- Ответ SDK — настоящая запись сессии critic_verifier, 22.10.2026 00:14:43 МСК: HTTP 400 invalid params, context window exceeds limit (2013), stopReason=error. Ответ воспроизводится без исключения из SDK, как это происходило в инциденте.
