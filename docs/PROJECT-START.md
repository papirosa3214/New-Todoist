# Запуск нового проекта — стандарт

Решение владельца 28.10.2026. Только для проекта, который заводят с нуля по поручению владельца. Старые проекты без этих файлов не переделываются: в них работают по их собственным правилам. Образец — сервер TaskFlow и iOS-клиент `TaskFlowNativeBuild`.

## 1. Папка и репозиторий

- Папка: `~/Проекты/<Имя-проекта>` на той машине, где проект живёт (.110 — серверное, мак — Apple-приложения).
- `git init -b main` → репозиторий на GitHub `papirosa3214/<имя>` (приватный) → remote `github`.
- Секреты — сразу в vault, в репозиторий не попадают (`.env` в `.gitignore`).

## 2. Первые файлы (первый коммит)

| Файл | Зачем |
|---|---|
| `README.md` | Что это, как запустить, как собрать — три-пять строк. |
| `AGENTS.md` | Правила проекта для ролей TaskFlow (их загрузчик читает именно его): где что лежит, как собирать и проверять, процедура git (раздел 4). Коротко, без истории. |
| `CLAUDE.md` | То же для Claude Code — ссылкой на `AGENTS.md`, своего не дублировать. |
| `AGENT-WORK-SCOPES.md` | Реестр работ: строка на каждую задачу — что чиним, какие файлы разрешены, исполнитель, как проверено, статус `IN_PROGRESS` → `REVIEW`. |
| `.gitignore` | Сборка, зависимости, `.env`, локальные артефакты. |
| `.github/workflows/ci.yml` | Проверка + автослияние (раздел 3). |
| `docs/` | Артефакты задач (раздел 5). |

## 3. CI до первой продуктовой правки

- Проверка по размеру проекта: TS — `tsc --noEmit` и тесты; iOS/macOS — сборка на `macos-26`; Python — тесты.
- Job `automerge`: зелёный PR без конфликтов вливается сам. Шаблон — урок KB `2026-10-28-standart-zapuska-proekta-pr-ci-automerge.md`.
- Первый PR — сам CI: убедиться, что он прошёл и влился сам. Без этого проект не считается запущенным.

## 4. Как вести работу

1. Завести строку в `AGENT-WORK-SCOPES.md` (`IN_PROGRESS`).
2. Своя ветка (`roles/<taskId>` у ролей, `fix/…`/`feat/…` у остальных), лучше в своём `git worktree`.
3. Коммит на каждую независимую правку; у роли первая строка коммита — её имя.
4. `git push github <ветка>` → PR. Зелёный вливается сам; красный или конфликт — чинишь сам в той же ветке.
5. В `main` напрямую не коммитить и не пушить. Метка `no-automerge` или черновик — ждать владельца.
6. Строку реестра перевести в `REVIEW`: что сделано, что сверх задачи, как проверено.
7. Влитые ветки и worktree убрать.

## 5. Документы, которые ведутся

- **Артефакт задачи** — `docs/ГГГГ-ММ-ДД-<тема>.md` по серьёзной задаче: цель, что сделано, грабли, что осталось. Коммитится вместе с работой.
- **Новое правило проекта** — одной строкой в `AGENTS.md` (с датой и почему), не отдельным файлом.
- **Заметки** — своим внутренним инструментом заметок (у ролей `taskflow_doc_write`), в проект карточки.
- **Повторяемый рецепт** — урок в KB; короткий факт — в Mnemosyne.
- **Граф кода** — `graft build`, когда проект перерос пару десятков файлов; дальше поиск начинать с `graft ask`.

## 6. Если проект живёт сам (служба, наблюдатель, выкладка)

- Выкладка или установка берёт код из `github main` сама, а не из локальной копии.
- Наблюдатель на тихий отказ и регистрация в infra-panel — сразу, иначе настройка не закончена.
