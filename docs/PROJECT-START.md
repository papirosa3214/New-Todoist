# Запуск нового проекта — стандарт

Решение владельца 28.10.2026. Только для проекта, который заводят с нуля по поручению владельца. Старые проекты без этих файлов не переделываются: в них работают по их собственным правилам. Образец — сервер TaskFlow и iOS-клиент `TaskFlowNativeBuild`.

## 1. Папка и репозиторий

- Папка: `~/Проекты/<Имя-проекта>` на той машине, где проект живёт (.110 — серверное, мак — Apple-приложения).
- `git init -b main` → репозиторий на GitHub `papirosa3214/<имя>` (приватный) → remote `github`.
- Секреты — сразу в vault, в репозиторий не попадают (`.env` в `.gitignore`).

## 2. Первые файлы (первый коммит)

| Файл | Зачем |
|---|---|
| `README.md` | Что это, как запустить, как собрать — три-пять строк. |
| `AGENTS.md` | Правила проекта для ролей TaskFlow (их загрузчик читает именно его): где что лежит, как собирать и проверять, процедура git (раздел 4). Коротко, без истории. |
| `CLAUDE.md` | То же для Claude Code — ссылкой на `AGENTS.md`, своего не дублировать. |
| `AGENT-WORK-SCOPES.md` | Реестр работ: строка на каждую задачу — что чиним, какие файлы разрешены, исполнитель, как проверено, статус `IN_PROGRESS` → `REVIEW`. |
| `.gitignore` | Сборка, зависимости, `.env`, локальные артефакты. |
| `docs/` | Артефакты задач (раздел 5). |

## 3. Проверки и доставка без CI

## Доставка TaskFlow напрямую в main — решение владельца 05.11.2026

- Pull Request не требуется: не создавать PR и не ждать внешнего ревью. GitHub CI и автослияние остаются отключёнными.
- Штатный путь: актуализировать main → исключительно точечные локальные проверки изменённой логики и файлов → отдельный коммит только своих изменений → прямой push main в GitHub. Коммит прямо в main разрешён. Если работа велась в отдельной ветке/worktree, агент сам локально сливает её в main и пушит main, без PR.
- Публикация и локальное слияние — часть уже порученной работы: владелец не нажимает Merge и не даёт повторное разрешение. Конфликт разрешить с сохранением обеих правок; без force-push и потери чужой работы.
- Только точечные локальные проверки. Полные и глобальные тестовые прогоны, весь test suite, общий регрессионный прогон и тесты несвязанных модулей запрещены. Сервер: явные файлы тестов и --maxWorkers=4. Общий typecheck/сборка не подменяет точечную проверку; штатная сборка сервера при выкладке — отдельный шаг доставки.
- Новая логика — целевой RED → GREEN. Документация и косметика — diff и относящиеся к правке статические проверки, без придуманных тестов. Симулятор, UI-тесты и установка на iPhone — только по отдельному прямому поручению.
- Не коммитить чужие изменения и не использовать git add -A/git commit -a в общем грязном дереве. Основное дерево .110 оставлять на main; изоляция worktree разрешена, но не создаёт обязанности открывать PR.
- Сервер после push: проверить доставку. Перед перезапуском — пустая очередь ролей/чатов и резервная копия БД; затем штатная сборка, health и затронутый API. Push в GitHub ещё не доказывает выкладку.
- Отчёт: SHA опубликованного main, что точечно проверено, что выложено/установлено и что осталось. Удалять только свои уже влитые ветки/worktree. Точечные подсказки при работе/ошибках инструментов сохранять; замена постоянного промпта не является поручением отключать их.

## 4. Как вести работу

1. Завести строку в `AGENT-WORK-SCOPES.md` (`IN_PROGRESS`).
2. Своя ветка (`roles/<taskId>` у ролей, `fix/…`/`feat/…` у остальных), лучше в своём `git worktree`.
3. Коммит на каждую независимую правку; у роли первая строка коммита — её имя.
4. После точечных локальных проверок: коммит своих файлов, локальное слияние рабочей ветки в main при необходимости, прямой git push github main без PR. Конфликт или падение — исправить только своё.
5. Коммит в main и прямой push разрешены. Только явный запрет владельца на публикацию требует ожидания.
6. Строку реестра перевести в `REVIEW`: что сделано, что сверх задачи, как проверено.
7. Влитые ветки и worktree убрать.

## 5. Документы, которые ведутся

- **Артефакт задачи** — `docs/ГГГГ-ММ-ДД-<тема>.md` по серьёзной задаче: цель, что сделано, грабли, что осталось. Коммитится вместе с работой.
- **Новое правило проекта** — одной строкой в `AGENTS.md` (с датой и почему), не отдельным файлом.
- **Заметки** — своим внутренним инструментом заметок (у ролей `taskflow_doc_write`), в проект карточки.
- **Повторяемый рецепт** — урок в KB; короткий факт — в Mnemosyne.
- **Граф кода** — `graft build`, когда проект перерос пару десятков файлов; дальше поиск начинать с `graft ask`.

## 6. Если проект живёт сам (служба, наблюдатель, выкладка)

- Выкладка или установка берёт код из `github main` сама, а не из локальной копии.
- Наблюдатель на тихий отказ и регистрация в infra-panel — сразу, иначе настройка не закончена.
