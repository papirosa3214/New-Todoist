# Рабочий чек-лист исполнителя — 10.10.2026

Поручение владельца: исполнитель до работы составляет небольшой список этапов внутри одной подзадачи, отмечает текущий и выполненные. iOS сначала; веб отложен в Linear MAK-126. Ревью подзадачи не вводится, обычное исполнение и сдача сохраняются.

## Контракт и инструмент

GET /api/subtasks/:id/work-plan → {plan:null} либо сохранённый план с subtask_id, revision, items [{id,title,state}], updated_at, author_id.
PUT того же маршрута → {base_revision,items}. Запись только текущему исполнителю слота in_progress и done=0; чужой слот отклоняется, сменившиеся session/attempt при переданных заголовках отклоняются. Проверены 1–20 этапов, уникальные id, непустые названия до 200 символов, состояния pending/in_progress/done, максимум один текущий этап. Устаревший base_revision → 409, без перезаписи.

Инструмент taskflow_work_plan привязан замыканием к текущему subtaskId: без items читает, с полным списком и base_revision записывает. Он добавлен в taskflowTools, которые входят в финальный customTools. Инструкция приложена к фактическому prompt каждого запуска слота, в том числе продолжениям: обычно 3–7 этапов, один текущий, выполненные не обнулять, список актуализировать. Инструкция доступна в слое tool.runtime.taskflow_work_plan через resolver; индивидуальные промпты ролей не перезаписаны.

Миграция 129_subtask_work_plans: отдельная таблица, FK ON DELETE CASCADE. Новый список не меняет tasks/subtasks state/done, не создаёт узлы, не добавляет gate для сдачи. Изменение публикует task:updated для существующих слушателей.

Сторож checkWorkPlanStore при старте и каждые 15 минут делает две записи и чтение этапа внутри полностью откатываемой пробы. Уведомление о сбое — в проекте «Серверные уведомления», устойчивый ID по дате ограничивает до одной задачи в сутки, включая перезапуски. Реестр docs/watchers.md обновлён.
