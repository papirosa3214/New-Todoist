# Диагностика стека инструментов TaskFlow

20 октября 2026, 11:24 МСК. Диагностика по поручению владельца. Production-код и настройки не менялись, службы не перезапускались.

## Вывод

Главный очаг — переходник между Pi SDK на .110 и Mac host: часть файловых операций не соответствует контрактам SDK. Хост и серверные тесты отдельно дают зелёный результат, хотя полный путь роли не работает.

Найдено **10 воспроизводимых дефектов/несогласованностей**. Исправления в ходе этого аудита не вносились.

## Подтверждённые находки

### F01 — P1: host_write не создаёт файл

Ролевая проба с правильными path/content: HTTP 409, mkdir: EISDIR при rename временного файла на путь родительской папки.
Причина: server/src/runtime/hostOperations.ts, hostWriteOperations.mkdir вызывает write с path=dir и content="". SDK ожидает mkdir перед writeFile; адаптер пишет файл вместо создания каталога.
Контроль: прямой write через gateway на том же Mac создал файл.
Исправление: правильная подготовка каталога и сценарии нового файла, вложенной папки, обновления существующего файла через полный role-host путь.

### F02 — P1: host_ls скрывает обычные файлы

Папка содержит alpha.txt, beta.log, child/. Ролевой ls возвращает только child/. Прямой host ls возвращает всё.
Причина: hostLsOperations.stat использует ls; для файла low-level ls возвращает ENOTDIR, SDK пропускает элемент.
Исправление: stat-контракт для файлов и каталогов, проверять полный состав, а не HTTP-успех.

### F03 — P1: host_grep запускает поиск на .110 вместо Mac

На папке: rg сообщает No such file or directory для Mac-пути. На существующем файле: Path not found.
Причина: SDK GrepOperations подменяет isDirectory/readFile, но сам SDK spawn-ит локальный rg на .110. Дополнительно isDirectory адаптера вызывает ls и не умеет проверять файл.
Контроль: прямой host grep на Mac находит подготовленную строку.
Исправление: удалённое выполнение самого поиска, с проверкой файла/папки/glob/ignoreCase/literal/context/limit.

### F04 — P1: host_find нарушает форму результата SDK

Проба: resultPath.endsWith is not a function.
Причина: SDK ждёт string[], хост отдаёт entries: {path,type}[], а hostFindOperations.glob только объявляет тип string[] без преобразования.
Исправление: согласовать форму и относительные пути, проверить фактический результат SDK.

### F05 — P2: low-level find игнорирует pattern

Прямой find с pattern="*.txt" возвращает также beta.log.
Причина: host/src/operations/find.ts читает pattern, но не фильтрует walkResult.
Исправление: заявленная glob-семантика и тест с txt/log в одной папке. Исправление F04 само по себе этого не исправит.

### F06 — P1: отмена bash теряется

Контрактный тест: переданный AbortSignal не попадает в runOperation; forwardedKeys=["timeoutMs","onChunk"].
Причина: hostBashOperations.exec не передаёт options.signal в gateway. Сам gateway отмену поддерживает.
Последствие: остановка роли не гарантирует остановку её команды на Mac. Живой долгий xcodebuild в аудите не запускался.
Исправление: довести сигнал и проверить остановку короткой живой тестовой команды.

### F07 — P1: host_push выдаёт succeeded при ошибках обоих remote

Тест без настоящего push: обе операции возвращают ok=false. Универсальный ответ: ok=true/state=succeeded; внутри текст "gitea: ошибка … / origin: ошибка …".
Причина: hostRoleTools.ts возвращает ошибки обычным текстом.
Исправление: ошибка/частичный исход вместо succeeded. Реальные push/merge не выполнялись.

### F08 — P2: taskflow_project_tasks выдаёт бизнес-ошибку как успех

Факт из живой истории: внешний ok=true/state=succeeded, внутри {"ошибка":"нужен project_id или project (название)"}.
Исправление: согласовать schema и валидацию проекта с форматом отказа. Не угадывать ошибки по произвольному слову в любом тексте; проверять конкретные адаптеры.

### F09 — P2: неверный invokeTemplate для nullable-поля

Инвентаризация: taskflow_assign требует assignee_id: string|null, но шаблон содержит assignee_id={}.
Причина: генератор после выбора anyOf-ветки добавляет properties={} и считает строковую ветку объектом.
Это дефект моей сегодняшней правки шаблонов; отдельные примеры и 44 теста его не покрыли.
Исправление: генератор и проверка всего каталога, включая nullable/anyOf/oneOf.

### F10 — P2: операции чтения размечены write

Проба: COMPOSIO_SEARCH_TOOLS и COMPOSIO_GET_TOOL_SCHEMAS получают effects=write и MODE_RESTRICTED в plan, хотя runtime отдельно разрешает их для планирования. taskflow_slot_status также отсутствует в READ-наборе.
Причина: эффект определяется отдельным ручным списком имён.
Исправление: согласованная классификация; смешанные Things/work_plan нельзя просто целиком объявлять чтением.

## Почему «вчера работало»

Несоответствия host-адаптера появились 15–16 октября. Смена MiniMax не создала mkdir/stat/glob-ошибки. read/edit/bash действительно работали; это не доказывало write/ls/grep/find. Доказательств прежнего полного прохода всех файловых операций не найдено.

В SDK активны локальные read/bash/edit/write/grep/find/ls плюс универсальный taskflow. «Один инструмент» описывает только серверные операции, а не весь активный набор. Локальные команды идут на .110, host-команды — на Mac.

Taskless host-копия привязана к роли и проекту, а не ко всем ролям сразу, но разные чаты одного Разработчика её делят. host_push/host_attach добавляются в рабочем host-контексте, а в обычном чате их нет. Это различие контекста следует показывать явно.

## Порядок исправления и единая приёмка

1. F01–F05: файловый host-адаптер. Через реальный путь роли создать папку/файл, записать, прочитать, изменить, получить полный ls, найти строку и файл по маске, сравнить результат, убрать временные данные.
2. F06–F08: отмена и честный исход. Команда прекращается после отмены; неудачный/частичный push отражён соответствующим состоянием; бизнес-отказ не выглядит succeeded.
3. F09–F10: формы и режимы на полном каталоге. Не возвращать смягчение типов, синонимы и подстановку версии.
4. Обновить устаревшие тестовые утверждения и добавить сторож полного SDK → gateway → host пути.
5. Отдельно разобрать сохранение SYSTEM.md и проверку сдачи Mac-работы. Утверждение Разработчика про проверку коммита только на .110 одним этим аудитом end-to-end не подтверждено.
