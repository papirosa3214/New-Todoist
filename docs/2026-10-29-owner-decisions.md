## Как доставляются правки

- [x] **Мелкая правка → прямой push в `main`.** Проверенные целевыми
  тестами, не ломающая приложение (надпись, кнопка, багфикс). Так владелец
  сразу видит результат вживую, не дожидаясь долгих CI-прогонов.
- [x] **Крупная или рискованная правка сервера → ветка + Pull Request** на
  GitHub. Правило записано в `INDEX.md`.
- [x] **Триггер CI на `push: main` не добавляем** — владелец сознательно не
  хочет ждать прогоны ради прямых пушей.
- [x] **Каждый коммит Hermes начинается с `Hermes:`** в первой строке
  сообщения. Учётка в репозитории общая (`Maksim`), поэтому авторство
  указывается в тексте коммита.

## Субагенты: модель работы

- [x] **Субагент одноразовый.** Набирает контекст → сжимает в **выжимку** →
  отдаёт вызывающей роли → исчезает. Первичные источники перебирает он, а
  не вызывающая роль. Промпт и описание инструмента это проговаривают.
- [x] **Комната новая на каждый вызов** (вариант «а», не переиспользование по
  паре «сессия + роль»).
- [x] **Комната закрывается сама**, когда выжимка ушла в главную сессию;
  статус — `open` / `finished` / `failed`.
- [x] **Комнаты не показываются в списке сессий** — живут в боковой панели
  сессии, по ролям, со статусом. `GET /api/chats` их не отдаёт,
  `GET /api/chats/:id/subagent-rooms` — отдаёт.
- [x] **Кнопку «открыть комнату» в карточке НЕ делаем** — владелец отклонил
  28.10.2026: комната и так достигается из панели роли.
- [x] **Кнопка «Остановить обращение» на карточке субагента работает** —
  маршрут `/api/chats/:id/coordination/:messageId/stop` гасит ход роли
  напрямую (`cancelChatRunsFor`).

## Субагенты: что переделать

- [ ] **Вызов роли — фоновый, не блокирует чат.** Сейчас `taskflow_call_role`
  делает `await` на ход субагента: ход Помощника стоит до 10 минут, твой
  чат «висит», три роли идут по очереди. Нужно: старт роли в фоне, возврат
  сразу; ответ — в карточку и сообщением в чат вызывающей роли (доставка
  будит Помощника); «лёгкое ожидание» — короткие проверки с прерыванием на
  любой входящий запрос.
- [ ] **Корректировка субагента на ходу.** Головной агент должен уметь
  докинуть уточнение работающему субагента, и тот принимает его сразу и
  продолжает с учётом правки. Механика прерывания с сохранением наработки в
  проекте есть: `applyOwnerBoundary` + `carryCheckpoint` (см.
  `server/src/runtime/chatCheckpoint.ts`).
- [ ] **Первый живой прогон.** В боевой базе ноль карточек и ноль комнат:
  фича не работала ни разу, все выводы сделаны по мокам.
- [ ] **Клиентская часть комнат на iOS** — боковая панель роли, шторка со
  списком комнат, статусы. Спецификация:
  `docs/2026-10-29-subagent-rooms-ios.md`. Делает Claude Code на маке.
