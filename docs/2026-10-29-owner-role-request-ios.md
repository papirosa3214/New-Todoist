# Обращение владельца к роли — клиентская часть (iOS)

**Владелец:** 29.10.2026. **Серверная часть готова** (ветка
`feature/async-subagent-call-20261029`, коммит `dac79ebf`). Этот документ —
задание для клиента (делает Claude Code на маке).

## Что изменилось в поведении

Раньше владелец мог обратиться к роли только если она **уже участник чата**:
собачка подставляла участников (`chat.members`), а упоминание роли, которой в
чате нет, сервер отбрасывал тихо — сообщение ложилось в ленту как контекст,
роль не просыпалась, ошибки не было.

Теперь роль, которой нет в чате, тоже доступна:

- **роль уже в чате** → всё как было: обычное сообщение, роль отвечает в том
  же чате, оформление прежнее;
- **роли в чате нет** → сообщение уходит в **комнату роли** (личную переписку
  владельца с ней — там у роли свой контекст), а в чате владельца появляется
  **карточка «владелец → роль»**: тот же вид, что у обращения роль→роль, с
  статусом, ответом роли и кнопкой «Остановить обращение».

## Что делать в клиенте

### 1. Собачка показывает все роли

Сейчас (`RoleChatsScreen.swift`, `mentionCandidates`) список = участники чата
минус ты. Нужно:

- список = **все доступные роли** (`GET /api/roles`, фильтр `canJoinChat`),
  плюс участники чата, которых нет среди ролей;
- роли, которые **уже в чате**, показать первыми и помечать (например, подписью
  «в этом чате»);
- поиск по имени работает как сейчас (сначала с начала имени, потом вхождения).

### 2. Отправка

- выбрана роль **из чата** → текущее поведение: `POST /api/chats/:id/messages`
  с текстом и `@Имя роли` (как сейчас);
- выбрана роль **не из чата** → новый вызов:

  ```
  POST /api/chats/:id/role-requests
  { "role": "<role_key>", "text": "<текст сообщения>" }
  ```

  Ответ сервера: `{ chat_id, question_id, room_chat_id, role }`.
  Текст из поля ввода отправляется в теле `text` — **без** `@Имя роли`.

  Что покажет сервер:
  - в чате владельца — его сообщение с текстом вопроса;
  - следом — карточка «владелец → роль» (системное сообщение с
    `steps.coordination`, рисуется существующим `RoleCoordinationCard` — новых
    видов карточек не нужно);
  - ход роли идёт в фоне, ответ придёт в карточку и в комнату роли.

### 3. Что менять НЕ надо

- `RoleCoordinationCard` — уже умеет карточку с адресатом, статусом, ответом и
  кнопкой «Остановить обращение». Ответ приходит обновлением карточки
  (`chat:new` с обновлённой строкой) — как у обращения роль→роль;
- обычные сообщения в чат — не трогаем.

## Крайние случаи

- сервер может ответить `400` (неизвестная роль / пустой текст), `403`
  (обращаться может только владелец), `404` (чат недоступен), `409`
  (такое обращение уже создано) — показывать текст ошибки как обычно;
- `409` с текстом «Обращение уже создано» показывать как «Уже отправлено»,
  без страшного тона;
- если запрос ушёл, а ответ придёт позже — карточка сама обновится; отдельного
  «ожидания» в UI не нужно.

## Проверка (живая, на .110)

1. Открыть чат, в котором нет Лайф-тестировщика.
2. Написать `@` → в списке все роли, «Лайф-тестировщик» помечен как «не в
   чате».
3. Выбрать его, написать вопрос, отправить.
4. В чате: сообщение владельца + карточка «владелец → Лайф-тестировщик» со
   статусом.
5. Дождаться ответа: карточка закрывается ответом роли.
6. Нажать «Остановить обращение» на карточке, пока роль ещё работает: статус
   «Обращение остановлено».
