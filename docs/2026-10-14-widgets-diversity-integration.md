## Круг 2: возврат с ревью (дефект D1)

Итоговая проверка вернула работу с одним блокирующим дефектом: в строке инструкции роли
тепловая карта была описана как `heatmap (weeks, cells: date, value, max)`, то есть `max`
уходил внутрь ячеек. Словарь валидатора секретаря и контракт для клиента требуют `max`
в корне блока, поэтому роль, собравшая блок по инструкции, получала от своего же
валидатора две ошибки, а клиент не получал шкалу плотности. Флаг выдачи новых типов по
умолчанию выключен, поэтому пользовательских поломок ещё не было — но включать флаг до
правки было нельзя.

Исправление Разработчика, коммит `9908000b`:

- `server/src/lib/widgetContract.ts` — один каталог полей восьми новых типов, смысловых
  тона и состояния. Строки инструкции собираются из него, имена типов для нормализатора
  и для фиче-флага берутся из него же. Раньше проза, список имён и словарь валидатора
  жили тремя независимыми списками, и на прозу не было ни одного теста.
- `server/src/runtime/instructionDefaults.ts` — рукописных строк о типах не осталось,
  перечень генерируется.
- `server/src/lib/widgetNormalize.ts`, `server/src/lib/widgetFeatureFlag.ts` — список
  типов из каталога.
- `server/test/widgetContract.test.ts` — строка инструкции разбирается ровно в поля
  контракта для всех восьми типов; пример по контракту принимает словарь валидатора
  секретаря (условно — файл вне git); `max` внутри ячейки heatmap словарь отвергает.
- Попутно исправлен второй расхождение того же класса: у `compare` поле `verdict` было
  подано как поле элемента, хотя это поле блока.
- `docs/2026-10-14-widget-server-contract.md` — дополнено: где лежат поля и где `max`
  у heatmap.
