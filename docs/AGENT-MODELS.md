# Модели исполнителей для автономной работы (будильник)

Как выбирается модель, на которой агент пойдёт по карточке, что нужно настроить у
каждого исполнителя и как проверить, что заход действительно ушёл туда, куда задумано.

Речь только про **автономный режим** — `server/scripts/trigger.py`, служба
`taskflow-trigger.service`. В интерактивном режиме (MCP из IDE) модель выбирает сам
клиент, доска в это не вмешивается.

Проверено на живых заходах 27.08.2026.

---

## 1. Правило одно: модель задаёт МЕТКА НА ЗАДАЧЕ

Решение владельца 21.08.2026: «меткой гораздо гибче и проще менять, чем каждый раз
заходить в настройки перед назначением». Метка вешается и снимается в один тап, в том
числе с телефона и уже после назначения.

Понимаются два вида метки:

| Вид                     | Пример                             | Кому                                        |
| ----------------------- | ---------------------------------- | ------------------------------------------- |
| короткое имя уровня     | `Fable`, `Opus`, `Sonnet`, `Haiku` | всем — значит одно и то же для всех агентов |
| явная форма с префиксом | `модель: gemini-3.1-pro`           | когда нужно конкретное имя модели агента    |

### Порядок уровней — по прайсу Anthropic

Имена меток взяты у моделей Anthropic, и порядок у них ровно ценовой (проверено
27.08.2026 по `platform.claude.com/docs`, $ за миллион токенов):

| Уровень    | Модель Anthropic | Вход | Выход | Смысл метки     |
| ---------- | ---------------- | ---- | ----- | --------------- |
| **Fable**  | Claude Fable 5   | $10  | $50   | самая мощная    |
| **Opus**   | Claude Opus 5    | $5   | $25   | сильная рабочая |
| **Sonnet** | Claude Sonnet 5  | $2   | $10   | обычная рабочая |
| **Haiku**  | Claude Haiku 4.5 | $1   | $5    | самая дешёвая   |

Каждая ступень вдвое дешевле предыдущей. ⚠️ `Fable` — САМАЯ ДОРОГАЯ, а не «лёгкая»:
на этом уже ошиблись один раз, и раскладку пришлось разворачивать.

Регистр не важен. Прочие метки владельца (`Важно`, `UX/UI`, `Дом`) будильник пропускает
мимо — метки его инструмент, заводить их он должен свободно.

**Метки нет — ничего не подставляем**: у каждого CLI своё умолчание, и подменять его
догадкой значит менять поведение там, где никто не просил.

Две метки моделей сразу — берётся первая, в журнал пишется предупреждение.

Код: `model_of()` в `trigger.py`.

## 2. Что настроено у каждого исполнителя

| Исполнитель            | Как получает модель                                | Что понимает                                                              |
| ---------------------- | -------------------------------------------------- | ------------------------------------------------------------------------- |
| **Claude_Bot** (u2)    | флаг `--model` у `claude`                          | `opus`, `sonnet`, `haiku`, `fable` — родные псевдонимы CLI                |
| **Оркестратор-Claude** | флаг `--model`                                     | то же                                                                     |
| **Гермес** (u3)        | флаг `-m`                                          | свои имена моделей через `модель:` (напр. `модель: deepseek-v4-flash`)    |
| **Antigravity**        | флаг `--model` + карта `ANTIGRAVITY_MODEL_ALIASES` | уровни переводятся в его имена (`sonnet` → `claude-sonnet-4-6`)           |
| **DeepSeek Harness**   | **подменный `DSH_HOME`** (флага модели нет)        | уровни по карте `DSH_MODEL_ALIASES` + любая модель из его `settings.yaml` |

### 2.1. Метки уровней у DeepSeek Harness

| Метка    | Провайдер | Модель                       | Замечание                                     |
| -------- | --------- | ---------------------------- | --------------------------------------------- |
| `Fable`  | minimax   | `MiniMax-M3`                 | миллионный контекст, быстрее жжёт общий лимит |
| `Opus`   | minimax   | `MiniMax-M2.7`               | рабочая по умолчанию                          |
| `Sonnet` | minimax   | `MiniMax-M2.7-highspeed`     | быстрая                                       |
| `Haiku`  | ollama    | `qwen3.6-27b-iq4-16k:latest` | локальная, подписку не тратит                 |

Форма `модель: <id>` принимает **любую** модель, объявленную в
`~/.dsh/settings.yaml` → `llm-pi-ai.providers.*.models[].id`, например
`модель: deepseek/deepseek-v4-flash-0731`. Провайдер определяется по этому же файлу,
руками указывать его не нужно.

Подписка MiniMax общая с Гермесом: метка `Haiku` (локальная Qwen) — способ прогнать
длинную или черновую работу, не трогая общий лимит.

У Antigravity модели уровня Fable нет, поэтому `Fable` и `Opus` у него ведут на одно и
то же — самое сильное, что ему доступно (`claude-opus-4-6-thinking`).

## 3. Почему у DeepSeek Harness всё иначе

**У `dsh` нет флага модели вообще.** Он берёт её только из секции `agent-default-model`
в `~/.dsh/settings.yaml`.

Проверено фактом 27.08.2026:

- `dsh --profile headless --patch <файл>` с `- id: agent-default-model` — composition
  entry в `--dump-config` меняется, **а живой заход всё равно идёт на модель из
  settings.yaml**. Настройки перекрывают патч профиля;
- подмена `DSH_HOME` — работает.

Поэтому `dsh_home_for()` собирает на модель отдельный дом в
`~/.local/state/taskflow-trigger/dsh-homes/<провайдер>-<модель>/`:

```
profiles          → симлинк на ~/.dsh/profiles       (патч-слой, MCP доски)
sessions          → симлинк на ~/.dsh/sessions
storages          → симлинк на ~/.dsh/storages
.credentials.yaml → симлинк на ~/.dsh/.credentials.yaml
AGENTS.md         → симлинк на ~/.dsh/AGENTS.md      (инструкции агента)
settings.yaml     → копия настоящего, где заменена ОДНА секция
```

Симлинки, а не копии: `.credentials.yaml` обновляется, когда Гермес перелогинится в
MiniMax, а `profiles` несут патч-слой с MCP доски — застывшая копия увела бы заход на
старую конфигурацию молча.

Дом переиспользуется, но `settings.yaml` пересобирается на каждый заход из настоящего.

### Грабля, которая стоила захода: `off:` → `false:`

Настройки правятся **текстом**, а не `yaml.safe_dump`. Разобрать и записать обратно
нельзя: в файле есть ключ `off:` (уровень раздумий у моделей Polza), в YAML 1.1 это
булево, и при записи он превращается в `false:`. Плагин моделей отвергает такой блок
целиком, и заход падает с `NO_ADAPTER: no adapter registered for provider "..."`.

## 4. Защита от тихого отказа

Подмена может не удаться, и это НЕ должно выглядеть как обычная работа: заход спокойно
ушёл бы на прежней модели, метка на карточке ни на что не влияла бы, а по журналу не
понять почему.

Поэтому `dsh_home_for()` **перечитывает то, что записал**, и сверяет модель. Не сошлось
— возвращает пустую строку: заход идёт на умолчании, но в журнал пишется предупреждение:

```
⚠️ метка модели «xxx» неизвестна dsh — иду на умолчании из настроек
⚠️ подменный дом dsh собран неверно (...) — иду на умолчании
⚠️ в настройках dsh нет секции agent-default-model — дописываю
```

Окружение захода собирается на месте (`run_env`), а не правкой общего `agent["env"]`:
иначе две задачи с разными метками увели бы друг друга на чужую модель.

## 5. Как проверить, что заход пошёл на нужной модели

Четыре независимых способа, от дешёвого к надёжному:

```bash
# 1. Журнал будильника — что он собирался сделать
tail -20 ~/.local/state/taskflow-trigger/trigger.log
#   зову «DeepSeek Harness» на задачу 7da67dea, модель fable

# 2. Окружение живого процесса — какой дом ему достался
for p in $(pgrep -f "dsh/lib/bin.js|\.bin/dsh"); do
  tr '\0' '\n' < /proc/$p/environ | grep '^DSH_HOME='
done

# 3. Куда реально ушёл запрос (для локальной модели)
journalctl --user -u ollama --since "-5min" --no-pager | grep chat/completions

# 4. Спросить самого агента карточкой: «напиши в ленте, какая ты модель»
```

Способ 4 — единственный, который проверяет всю цепочку целиком, и именно им принималась
работа: агент ответил «модель qwen3.6-27b-iq4-16k:latest, провайдер — локальный Ollama».

## 6. Как добавить модель или исполнителя

**Новая модель существующему dsh:** объявить её в `~/.dsh/settings.yaml` внутри
`llm-pi-ai.providers.<провайдер>.models` — и она сразу доступна как
`модель: <id>`. Ничего в коде менять не нужно. Захотелось повесить её на уровень
(`Opus`/`Sonnet`/…) — правится карта `DSH_MODEL_ALIASES` в `trigger.py`.

**Новый исполнитель:** запись в `EXTERNAL_AGENTS` (`trigger.py`) — учётка, ключ в vault
(`token_env`), команда запуска. Если его CLI умеет флаг модели, добавить `model_flag`;
если нет — нужен свой способ, как у dsh, и его стоит описать здесь же.

**Метка новая:** заводится владельцем в интерфейсе TaskFlow. Метки принадлежат
владельцу (`labels.owner_id = u1`), агент чужую метку на задачу не повесит.
