# Разовая зачистка остатков уведомлений `incident` (22.10.2026)

Карточка TaskFlow `6dee5bc3-d750-493d-a69f-69f98780ba55`, шаг
`builder_legacy_cleanup` (замечание Критика №5).

## Зачем

Правка `ef62ab79` удаляет уведомление о поломке в момент архивирования
карточки починки. Карточки, отправленные в архив до выкладки правки, сохранили
своё уведомление: запись поломки оставалась в базе, и критерий «архив →
запись исчезает» на такой карточке не сходился. Обратного заполнения правка не
делала.

## Чем чистили

`server/scripts/cleanup-archived-incident-notifications.ts` — скрипт в
репозитории приложения. По умолчанию сухой прогон (только список), с флагом
`--apply`:

1. снимает полную резервную копию базы через `better-sqlite3.backup()`
   (корректно при работающем сервере, база в WAL) в `server/backups/`;
2. удаляет `notifications` типа `incident`, чья карточка уже в архиве;
3. печатает контрольный остаток.

Границы: трогаются только `notifications` типа `incident` у архивных карточек.
Уведомления живых поломок, задачи, лента событий и остальное в базе не
меняются. Модуль `src/db.ts` намеренно не импортируется — он при импорте
прогоняет миграции, разовой уборке это не нужно.

```
cd server
DB_PATH=/home/maksim/Проекты/New-Todoist/server/taskflow.db \
  npx tsx scripts/cleanup-archived-incident-notifications.ts           # сухой прогон
... --apply                                                            # бэкап + удаление
```

- уведомлений `incident` без карточки — 0;
- уведомлений `incident` у живых карточек — 8 (не тронуты).

Затронута одна карточка — `0868938a-8e24-4d30-8c70-149391859e07`.

- бэкап: `server/backups/taskflow.db.backup-pre-incident-cleanup-20261022-1526`;
- удалено уведомлений: 1 (`cdb13f8b-a385-480d-a46d-f804f46fccb4`);
- после удаления у архивных карточек осталось 0, у живых — по-прежнему 8;
- карточка `0868938a` остаётся в архиве со статусом `active` и ключом

| количество `incident` в ленте | 8 (живые поломки) |
| `/api/health` | 200 |
| повтор поломки: `raiseIncident` с новым ключом на снимке живой базы | карточка и уведомление создаются; повтор при открытой карточке дубля не даёт |

Повторное возникновение проверено на снимке живой базы, а не на живой службе:
настоящий вызов завёл бы в трекере владельца новую служебную карточку починки
по несуществующей поломке. Снимок снят тем же `backup()` уже после зачистки.

## Ограничения

- Во время прогона (15:26 МСК) кто-то под учёткой владельца вернул карточку
  `0868938a` из архива (15:26:22) и снова архивировал (15:26:32) — в ленте
  событий это `task:restored` + `task:archived`. Скрипт к этому отношения не
  имеет: он трогает только `notifications`. Удаление уведомления в этом же
  окне (одна строка, `changes = 1`) прошло; повторный архив по новой правке
  удалил бы уведомление сам, если бы оно к тому моменту существовало.
- Скрипт не заводит обратного заполнения на будущее: он про уже накопленные
  остатки. Новые архивы обрабатывает сама правка `ef62ab79`.
- Клиентская половина (строка суточной сводки в iOS) этим шагом не
  проверялась — правка клиента уже в `main` TaskFlowNativeBuild (`7faa0197`),
  живая проверка экрана за Лайф-тестировщиком.
