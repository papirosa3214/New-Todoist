# Apple-уведомления о событиях TaskFlow — 29.10.2026

## Договорённость владельца

Обычные напоминания: блок задачи или шага, сдача задачи на проверку, выполнение задачи, автоматическое пробуждение оркестратора по событию «Заминки». Старты исполнителей по планам, обычная переписка и вызовы ролей сами по себе не уведомляются.

Срочное напоминание со звуковым сигналом до отключения: открыт структурированный вопрос владельцу (chat_questions.status=open). После ответа, отмены или истечения ожидания соответствующее Apple-напоминание закрывается; если вопрос решён до доставки, создание пропускается. Роли также имеют инструменты taskflow_notify_owner и taskflow_notify_owner_urgent. Срочный требует причины, почему нужно решение владельца. Уже автоматически отправленный вопрос повторно не уведомлять.

## Схема

Служба systemd пользователя на .110 читает существующий task_events и chat_questions каждые 10 секунд. Живая база открывается read-only, кроме диагностического уведомления при сбое. Событие orchestrator_woken берётся из штатного механизма orchestratorWake; привязки к любым стартам ролей нет.

Отдельная SQLite-очередь: ~/.local/state/taskflow-apple-reminders/queue.db. Первый старт сохраняет дату активации: старые события не рассылаются. Стабильный ключ события предотвращает повторную постановку. Ошибки доставки сохраняются, повтор с задержкой до 5 минут; один недоступный Mac не вызывает десять одинаковых SSH-попыток подряд.

Доставка: SSH .110 → max@MacBook-Pro-Maksim.local → /Users/max/.local/share/taskflow-apple-reminders/receiver.py. JSON передаётся через stdin; заголовки, даты и заметки не интерполируются в команды. Получатель сериализует вызовы и ищет маркер события в Apple Reminders до создания, что защищает от дубля после потери ответа SSH.

Обычные напоминания — AppleScript в системном списке по умолчанию (сейчас Things в Apple Reminders; это список, не приложение Things 3). Срочные — нативная команда Shortcuts GeoPhotoMarks Urgent Failure с включённым Urgent и временем из ISO 8601. Из её VTODO-ответа берётся ID; только созданное напоминание переименовывается и получает текст роли/события. Копия этой команды сохранена в приватном репозитории papirosa3214/GeoPhotoMarks, automation/GeoPhotoMarks Urgent Failure.shortcut.

Mac должен быть включён, доступен по SSH, иметь пользовательский доступ к Reminders и Shortcuts. Если он недоступен, очередь хранится на сервере. Для создаваемого напоминания срок по умолчанию — через минуту после доставки. Телефон должен синхронизировать iCloud; срочный сигнал сейчас настроен на iPhone Air.

## Два скрипта

Из server/scripts/apple_reminders:

```sh
python3 normal.py --title 'Название' --notes 'Контекст' --at '2026-10-30T10:00:00+03:00' --key 'stable-event-id'
python3 urgent.py --title 'Нужно решение владельца' --notes 'Вопрос и задача' --key 'another-stable-id'
```

Без --at — через минуту. Возвращается JSON фактического результата Mac. Ошибка срочного вызова не превращается молча в обычный.

Нативные инструменты ролей:
- taskflow_notify_owner: title, notes?, at?, key?
- taskflow_notify_owner_urgent: title, reason, notes?, at?, key?

Для вопроса с ожиданием ответа — taskflow_ask_user_question; срочный сигнал создаётся автоматически.

## Установка и диагностика

Код службы копируется в ~/.local/share/taskflow-apple-reminders/ на .110. Unit: ~/.config/systemd/user/taskflow-apple-reminders.service, источник рядом с Python-файлами. Receiver копируется на Mac в указанный выше путь. Отдельная служба не перезапускает API и не прерывает роли. Новые нативные инструменты и инструкция оркестратора становятся доступны после штатной выкладки GitHub main.

```sh
systemctl --user status taskflow-apple-reminders.service
journalctl --user -u taskflow-apple-reminders.service -n 30
systemctl --user stop taskflow-apple-reminders.service
```

Проба работоспособности: запись/чтение собственной очереди при запуске, heartbeat при каждом проходе, фактический результат доставки в outbox.result. После трёх неудачных доставок — уведомление apple_reminders_delivery_failed в «Состоянии системы», не чаще раза в сутки. При ошибке сканирования — то же диагностическое уведомление. Никаких карточек для аварий доставки не создаётся.
