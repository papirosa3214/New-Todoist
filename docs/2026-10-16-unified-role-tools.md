# Единый taskflow: план и выполнение
Основание: согласованный проект на Mac docs/2026-10-16-unified-role-tools-design.md.
Цель: один серверный вход для ролей, общий реестр, сохранённые права и совместимость истории.
Реализация в codex/unified-role-tools-20261016 на .110.

- [x] Регрессии: обнаружение, схема, авторизация, режимы, повторы и подмена request_id.
- [x] Универсальная обёртка и долговечный журнал запросов с миграцией и пробой.
- [x] Общая сборка операций; убрать дубли chatTools; передать контекст мессенджеру.
- [x] Подключить taskflow к чату, работе, обсуждению; совместимые старые имена.
- [x] Изоляционные тесты и tsc, проверка diff.
- [ ] Интеграция и развёртывание при пустых очередях, живая проверка.
Ограничения: Node22, тестовая БД и пустая авторизация Pi; не запускать живые роли из тестов.
Проверки: отсутствующий контекст, чужой слот, старое имя, рестарт с pending, параллельный повтор.
Файловые инструменты SDK сохраняют свой хостовый механизм; предметные операции мигрируют на общий вход.

## Реализация
Один активный серверный инструмент taskflow в SDK: discover/describe/invoke.
taskflowTools собирает общее ядро и дополнительные определения из chatTools; повторные consultation/plan_request и мессенджер из chatTools удалены.
roleToolCatalog выдаёт один реестр; старые имена зарегистрированы только как совместимые адаптеры, в активных инструментах SDK их нет.
Встроенные read/bash/edit/write/grep/find/ls сохраняют существующий механизм исполнения; их миграция не входит в этот этап.
Экран Команда получает актуальные имена из серверного runtime вместо старых MCP-профилей.
Инфрапанель подключена также в чат и обсуждение этапа.
Проверка roleToolAllowed применяется ко всем операциям, включая дополнения чата.
В обсуждении единый режим чтения/сообщений/консультации; запись документов требует рабочего хода, прежний отдельный список этапа удалён.

## Проверено
- Node22, tsc без ошибок.
- До просьбы владельца прекратить расширенные прогоны успели завершиться 64 теста / 11 файлов, все PASS. Дальнейшие прогоны не запускались.
- Основная проверка на копии живой БД: вызов taskflow_comment через общий реестр/API записал комментарий; повтор с тем же request_id вернул результат, второго комментария нет.
- Настоящий SDK подтвердил getActiveToolNames() == [taskflow].
- Настоящая модель builder не смогла пройти ход: MiniMax HTTP429 Token Plan usage limit reached. Это внешний блокер, работа модели через новый инструмент не объявляется подтверждённой.
- Живые пользовательские сообщения и рабочие карточки для проверки не создавались. Использована отдельная SQLite-копия в /tmp/taskflow-unified-smoke-*.
- Логи: /tmp/taskflow-unified-tests.log, /tmp/taskflow-unified-smoke.log.

## Границы и оставшееся
Журнал сохраняет результаты изменяющих операций и не повторяет запрос с неопределённым исходом. requests.status читает состояние. Автоматическая сверка внешних систем пока не реализована: requests.reconcile честно сообщает об отсутствии сверки, повтор не делает.
Поиск сейчас текстовый по имени и описанию; повтор коротким запросом или просмотр каталога доступен без модели поиска.
Новые версии операций помимо v1 пока не добавлены. Неподключившийся внешний адаптер не расширяет реестр; общие операции TaskFlow продолжают работать.
