# Жизненный цикл QA-процессов, 23 октября 2026

## Что сломалось
В cgroup taskflow-server.service накопились браузеры и dev-серверы пользователя tfrole. Они запускались через bash/nohup/setsid и не были привязаны к запуску роли. SDK завершал внешнюю команду, но detach-потомки оставались. user-systemd пользователя maksim при остановке API не мог убрать часть процессов другого UID — журнал содержит Operation not permitted.

История панели показывает пять сохранённых точек TaskFlow выше150%CPU, максимум502,8% в03:24:07. В это время журнал фиксирует очередной браузерный QA и параллельный поиск по рабочему дереву. Долю каждого процесса восстановить нельзя. Перед исправлением по поручению владельца остановлены212 QA-процессов.

## Изменение
UUID запуска и команды наследуются всеми локальными role-shell процессами, включая сам bash через exec. Lease хранится в /tmp/taskflow-role-leases-1000, принадлежит серверу, содержит PID+starttime владельца и heartbeat каждые30с. Окончание роли закрывает lease и убирает процессы; отмена/таймаут/ошибка отдельной команды убирает её детей. Фоновые серверы между успешными командами одной роли остаются доступны.

Helper от tfrole посылает TERM, затем KILL только своим размеченным процессам и сверяет starttime. Отдельный минутный сторож ловит смерть владельца и stale heartbeat>180с. Старые неразмеченные браузеры/Vite/esbuild tfrole в cgroup TaskFlow старше120с тоже не остаются невидимыми. Ни обычные браузеры пользователя maksim, ни другие службы этим правилом не затрагиваются.

В scripts/qa/browser.mjs добавлены finally и обработчики SIGTERM/SIGINT с browser.close().

## Контроль
Сторож проверяет себя настоящим detached-процессом; пишет счётчики, PID и причины в состояние и journald. Обнаруженная утечка/сбой дают системное уведомление владельцу в TaskFlow(type role_process_watch), максимум раз в сутки, без карточек. Telegram резервируется для недоступного API. Стандартная autonomy-сводка проверяет timer и свежесть результата.
