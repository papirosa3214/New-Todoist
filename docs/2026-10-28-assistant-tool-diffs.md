# Дифы под ответами Помощника — 28.10.2026

**Задача владельца.** Под ответом роли в чате iOS показывались файлы и `+ / −`
правок хода, а у Помощника владельца (`u-secretary`) — пусто. В трёх последних
чатах (34 ответа) Помощник менял файлы, сохранённых дифов — ноль.

**Причина.** Сборщик хода (`server/src/lib/turnFileChanges.ts`) запоминал вид
файла только перед локальными `edit`/`write`. Помощник правит через
`taskflow_host_edit` / `taskflow_host_write` / `taskflow_host_bash` (на Маке) и
локальный `bash` — эти правки мимо.

**Что сделано.**
- `server/src/lib/toolFileCapture.ts` — снимки «до/после» вокруг одной
  операции там, где она идёт: `edit`/`write` — один файл по пути; `bash` — по
  git (грязные файлы до и после команды + файлы новых коммитов). Снимки
  уходят в `details.taskflow_file_changes` результата инструмента.
- `server/src/lib/localCaptureIO.ts` — чтение и команды на .110.
- `roleHostAccess.ts` — хостовые `edit`/`write`/`bash` снимаются на Маке через
  шлюз хоста (`read`, `bash`).
- `PiRuntimeAdapter.ts` — локальный `bash` роли снимается в её папке.
- `turnFileChanges.ts` — принимает снимки (событием или из
  `tool_execution_end`), склеивает первый «до» и последний «после» по каждому
  файлу каждой машины. Путь показывается как `машина:путь`.

**Пределы.** `bash` вне git-репозитория не виден. Правки bash в другом
репозитории, чем рабочая папка команды, не видны. Двоичные файлы и файлы больше
1 МБ в диф не идут. Сбой снимка правку не роняет.

**Проверка.** RED → GREEN: `test/turnFileChanges.test.ts` (снимки с машин),
`test/toolFileCapture.test.ts` (файл, bash с коммитом и новым файлом, bash вне
git, передача через результат инструмента). Целевые тесты хоста и чата —
зелёные, кроме двух, которые падают и на чистом main
(`chatExecutionMode` — голосовой шлюз, `hostToolRequestId` — request_id).
`tsc --noEmit` чистый. Живой ход Помощника на Маке после выкладки не проверен.
