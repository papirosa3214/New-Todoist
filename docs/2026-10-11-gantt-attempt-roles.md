# Гант: восстановление ролей заходов — 11.10.2026

## Причина и исправление
Во всех 580 исторических attempts поле routing_role было NULL. API возвращал его напрямую, поэтому iOS и веб группировали историю в «Без роли». Фактический executor_id сохранён, соответствующие пользователи имеют role_key.

Общий API теперь использует сохранённую routing_role, затем role_key фактического исполнителя. Текущий assignee задачи не используется для восстановления истории. Для текущей занятости фактический исполнитель также имеет приоритет. Неизвестный исполнитель остаётся без роли. Новые attempts узлов плана сохраняют routing_role при создании.

Историческая БД не переписывается, клиенты не изменены. Роль старого захода восстанавливается по текущей записи пользователя; при изменении role_key пользователя такая история может измениться. Новые узлы плана имеют собственный снимок роли.
