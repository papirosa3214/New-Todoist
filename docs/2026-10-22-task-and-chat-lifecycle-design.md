# Цикл результата: карточки задач и самостоятельная работа в чате

Дата: 22.10.2026. Владелец одобрил схему в чате; Уточнение владельца: обязательные автокритик и автоинтегратор относятся к карточкам задач; в чате роль завершает поручение сама, помощь коллег подключается по решению владельца. Это согласованное направление, не отчёт о внедрении.

## Назначение

Независимые работы выполняются параллельно. Зависимости этапов и перенос в общий main имеют свои ограничения; неопределённое «в очереди» не скрывает их. Результаты документов не превращаются в Git-изменения автоматически.

## Входы

1. Карточка задачи: постановка, план и версии результата.
2. Поручение в чате после явного разрешения выполнить работу. Роль ведёт существующий чек-лист и сама выполняет завершающие действия по существу: проверку результата, сохранение, коммит и прочие действия в пределах поручения. Карточка задачи для этого не обязательна. Ни обсуждение, ни завершённое поручение в чате сами по себе не запускают обязательного автокритика или автоинтегратора.

## Помощь коллег в чате

Роль работает в своей специализации самостоятельно. Если есть конкретная нехватка компетенции, сомнение или необходимость дополнительной проверки/интеграции, она предлагает помощь интерактивной карточкой: кого подключить, зачем, какой вопрос или результат ожидается. Предложение даёт владельцу выбор: подключить предложенного участника либо продолжить с текущей ролью. Критик и архитектор — возможные участники, а не обязательный скрытый конвейер. До выбора владельца предложение не запускает коллегу и не создаёт для него задание или запись очереди.

После согласия контекст и конкретное поручение передаются выбранному участнику, ответ возвращается в исходный разговор. Если участник уже в комнате, используется обычная коммуникация; для обращения к коллеге вне комнаты применяется существующая карточка координации. Предложение подключить помощь и карточка статусов уже отправленного обращения — разные состояния, принятие предложения не подменяется статусом «доставлено».

Используется существующий чек-лист чата; новый обязательный план, версия результата или отдельная карточка не навязываются. Работа может уточняться сообщениями в том же разговоре. Обычное продолжение беседы не получает окно межагентной координации. Все действия с Git сохраняют существующие ограничения репозитория; отсутствие обязательной роли-интегратора не разрешает обходить проверки и одновременно менять main.

## Тип работы

- Документы и анализ: пользовательские записки, исследования и отчёты сохраняются в документах TaskFlow; Git-интеграции нет.
- Действия в системе: изменения настроек/сервисов/данных в пределах поручения; Git-интеграции нет, если репозиторий не менялся.
- Изменение репозитория: код, конфигурация и техническая документация в репозитории; интеграция требуется.

Для карточек задач тип отражается в постановке и контексте участников. Для чата тот же смысл помогает роли выбрать завершающие действия чек-листа, но не включает автоматические роли. Для первых двух типов поле ответственности за Git-интеграцию не отображается. Если объём меняется и требуется изменение репозитория, это явно фиксируется в пределах авторизации владельца. Самовольное сохранение документа в рабочей копии не делает Git необходимым.

## Проверка

Каждый завершённый результат карточки задачи проходит финальную проверку. Это требование не включает автоматическую проверку обычных поручений из чата. Если последний критик уже принял именно текущую версию результата, повторный запуск не нужен. Промежуточные критики по решению владельца остаются самостоятельными этапами. Новые изменения после принятия требуют проверки новой версии.

Для документов критик сопоставляет поручение, критерии и предоставленный результат. Он не повторяет всё исследование и не запускает не относящиеся к результату тесты. Для кода использует изменения и доказательства, дополнительная проверка имеет конкретную причину.

Возврат, по 2-3 предложения на проблему:

Проблема: что не работает и где.
Исправить: кому и что изменить.
Ожидается: проверяемый результат.

Одобрение: «Принято: результат соответствует задаче. Интеграция: не требуется / разрешена для указанных коммитов». Контракт report_markdown также принимает этот компактный формат и не требует отдельного длинного отчёта. Публичный вердикт краткий, без дублирования большого отчёта в ленте, шагах и карточке. Содержательные доказательства при необходимости хранятся отдельно.

## Интеграция

Для карточек задач с изменениями репозитория автоинтегратор по умолчанию — архитектор. В чате он участвует только по решению владельца после предложения роли. Он подключается независимо от состава исходной команды; его отсутствие в одиночной задаче не является причиной пропустить этап. Недоступность показывается конкретным ожиданием, автор карточки не становится незаметным запасным интегратором. Для репозитория после критика он получает принятую версию и точные коммиты, проверяет совместимость и доводит разрешение конфликтов. Детерминированный обработчик выполняет Git-механику после разрешения; не дублирует решение ролью и не делает ручное слияние одновременно с ней.

В очередь принимается конкретный разрешённый набор изменений. Поиск неслитых веток только обнаруживает хвост и сообщает, но не авторизует интеграцию. Изменение принятых коммитов не покрывается старым разрешением. Документ/операционная работа без репозитория после критика возвращается владельцу без архитектора и Git-очереди.

## Наблюдаемость

У карточки задачи видно фактическое состояние: выполняется, проверяется, возвращено на исправление, интегрируется, результат готов. Для ожидания — причина, начало ожидания, конкретная зависимость/адресат; для готовой к исполнению очереди — её размер и позиция. Это не обещание точного времени завершения. Очереди сообщений, слотов и Git различаются.

Для чата сохраняются существующий чек-лист и его прогресс. Ожидание выбранного владельцем коллеги отображается в исходном разговоре; обязательные стадии карточки задачи к чату не добавляются.

## Устойчивость автоинтеграции

Выделенный обработчик не задерживает общий планировщик. Блокировка проверяет владельца/живость и не отбирается у работающего процесса только по возрасту. После падения восстанавливается конкретное обязательство, повторная доставка не создаёт второго слияния. Ошибка отдельной карточки не останавливает независимые готовые результаты.

## Проверка реализации

Только логические unit/integration проверки, без UI-тестов, симулятора и iPhone — прямое указание владельца. RED на прежнем поведении, GREEN после. Фикстуры: одиночный секретарь без кода; документ; операции; репозиторий; промежуточный критик; последний критик с актуальной/устаревшей версией; approved/rework; архитектурный интегратор; неразрешённая ветка; несколько параллельных поручений; работа из личного и группового чата; обсуждение без поручения; завершение поручения в чате без автоматического критика/интегратора; предложение помощи без запуска; выбор участника/продолжения самостоятельно; повторный клик без двойного запуска; уточнение во время действия; сбой/повторная доставка; возврат в исходный чат. Живые пользовательские задачи для проверки не создавать.
