# Egress после Secret Broker cutover

## Причина

Secret Broker перевёл маршруты моделей на локальный broker, но исследовательские инструменты остаются отдельными Python-процессами и используют HTTP(S) proxy службы TaskFlow.

После cutover сервер наследовал старый общий xray-вход. Он был доступен локально, но все его внешние upstream-каналы были недоступны. Поэтому `web_search` (Tavily и Brave) и `web_get` завершались тайм-аутом, хотя модель через broker отвечала успешно.

## Исправление

- Перезапущен `xray-claude`, чтобы применить существующий конфиг и поднять выделенный HTTP-вход ролей на `127.0.0.1:10818`.
- Существующие drop-in службы `taskflow-server` переведены на этот вход для всех вариантов `HTTP(S)_PROXY`.
- Broker-маршруты моделей не менялись.

## Проверка

- RED: запросы через прежний proxy зависали; журнал роли содержал тайм-ауты Tavily, Brave и Wikipedia.
- GREEN: через `10818` Wikipedia вернула HTTP 200, Tavily и Brave ответили без тайм-аута.
- Реальные вызовы `research_server.py --call web_search` и `web_get` вернули результат.
- `taskflow-server` перезапущен после пустой очереди ролей и штатного снимка БД; `/api/health` вернул `ok: true`.
- Текущий маршрут модели Исследователя через Secret Broker продолжает возвращать HTTP 200.

## Граница

Активная маршрутизация ролей использует broker-подключённые `opencode-go`/`opencode`/MiniMax. Неактивные OAuth-провайдеры Anthropic, OpenAI Codex и xAI намеренно не переключались: для них требуется отдельная проверка refresh-протокола и действующей учётной записи.
