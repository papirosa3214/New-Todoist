# 50 концепций виджетов секретаря

**Источник:** SYSTEM.md роли secretary + схема `server/src/runtime/instructionDefaults.ts:79-87`.
**Типы:** metrics, progress, checklist, card, chart, weather (только готовый блок из `taskflow_weather`).
**Уже есть 7 рецептов** (task_stats, my_overdue, weather, release_progress, task_card, agent_activity, interactive_chart) — пересечения не повторяют их один в один, а дополняют новым сценарием.

## SYSTEM.md — разделы, к которым привязаны виджеты

| Раздел SYSTEM.md | Зачем там виджет |
|---|---|
| «Как ты отвечаешь → Короткая сводка в чате» | Заменяет три строки «Сделал/Повлияло/Результат» нативной карточкой |
| «Как ты отвечаешь → Виджет вместо пересказа» | Прямой источник правила: «Если результат ложится в виджет — вставь блок как есть» |
| «Как ты работаешь → Отвечаешь за результат» | Виджет показывает итог без пересказа |
| «Как ты работаешь → Не выдумывай» | Виджет привязан к источнику данных, не к выдумке |
| «Командная работа → Когда звать коллегу» | Сводки по агентам и блокировкам |
| «Командная работа → Как звать» | Визитка коллеги перед обращением |
| «Командная работа → Когда нужно второе мнение» | История консультаций |
| «Командная работа → Чтобы не потерять вывод» | Объём памяти, записанное в базу |
| «Границы» | Без правок сервера/MCP — только шаблоны в папке templates/ |

## 1. Финансы — 5 виджетов

### 1.1. metrics — Сводка расходов за месяц
- **type:** metrics
- **system_section:** Виджет вместо пересказа
- **scenario:** «сколько я потратил в октябре», «расходы за месяц»
- **поля:** items: 6–8 категорий с value (строкой), delta «vs прошлый месяц», trend
- **источник:** выписка банка/CSV; суммы по категориям, готовое сравнение

### 1.2. chart — Расходы по дням
- **type:** chart
- **system_section:** Виджет вместо пересказа
- **scenario:** «как я тратил в этом месяце», «динамика трат»
- **поля:** kind: line, points: x=день, y=сумма, unit: ₽
- **источник:** те же данные, агрегация по дням

### 1.3. progress — Цель накопления
- **type:** progress
- **system_section:** Виджет вместо пересказа
- **scenario:** «сколько осталось до цели», «накопления на отпуск»
- **поля:** items по 1–3 целям, value 0–100, note «осталось N дней» / «ежемесячный взнос»
- **источник:** цель (целевая сумма), текущий остаток

### 1.4. checklist — Забытые платежи
- **type:** checklist
- **system_section:** Виджет вместо пересказа
- **scenario:** «что я не оплатил», «незакрытые счета»
- **поля:** text + done, до 8 пунктов, помечать личное «(моё)»
- **источник:** регулярные платежи, помеченные «не оплачено» в этом месяце

### 1.5. card — Последняя крупная покупка
- **type:** card
- **system_section:** Виджет вместо пересказа
- **scenario:** «что я покупал вчера», «последняя операция по карте»
- **поля:** title (название/магазин), subtitle (категория · дата), body (зачем), rows (сумма, способ оплаты), link
- **источник:** последняя операция выше порога N ₽

## 12. Команда / агенты — 2 виджета

### 12.1. metrics — Активность ролей
- **type:** metrics
- **system_section:** Командная работа (расширяет agent_activity)
- **scenario:** «кто что закрыл», «сводка по агентам за период»
- **поля:** items по ролям, value = закрыто, delta «vs прошлая неделя»
- **источник:** taskflow_project_tasks + история, отличается от agent_activity тем, что фильтрует по периоду (неделя/месяц) и показывает тренд

### 12.2. card — Визитка агента
- **type:** card
- **system_section:** Командная работа → Как звать
- **scenario:** «расскажи про агента X», «кто такой Разработчик»
- **поля:** title (имя роли), subtitle (последняя активность), body (зона ответственности), rows (открытых задач, закрыто за неделю, в работе), link
- **источник:** taskflow_agents + открытые задачи исполнителя

## Что важно для следующего шага (исследователь → разработчик)

1. Все сценарии разные. Дубля один в один с 7 существующими нет — расширения/новые ракурсы.

4. Для chart kind — bar для распределений, line для динамики.
5. `value` в metrics — строка; в progress — число 0–100.
