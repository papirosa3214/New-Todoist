# Рецепт: приёмка принятого результата и передача в очередь автослияния

Рецепт роли Аналитика для шага плана «Интеграция принятого результата в основную ветку».
Навык в папку роли положить не удалось — папка ролей закрыта для ролей, поэтому рецепт лежит здесь.

## Что делаю за один шаг

1. **Прочитать карточку и передачу.** `taskflow_task` по id карточки: шаги, лента, версия результата,
   вердикт проверяющего. Сверить, что версия, которую проверяли, всё ещё актуальна.
2. **Сверить ветку роли с `main`.** Рабочая копия карточки: `git status --porcelain` (пусто),
   `git log --oneline`, `git rev-list --count main..HEAD`. Каждый коммит принятой версии — в какой он
   ветке: «уже в main» или «к переносу». Проверить, что к переносу только файлы этой карточки.
3. **Проверить миграции и совместимость.** Если коммиты трогают только документацию — перенос не может
   конфликтовать. Если трогают код — прогнать тесты на живой машине и сравнить с базой падений.
4. **Перепроверить живой результат.** Что в базе знаний ищется первым (контрольные запросы), одна ли копия
   заметки, совпадает ли текст заметки с файлом в репозитории, существуют ли пути из карты, сходятся ли
   числа пересчётом, отвечают ли порты. Числа — только пересчётом, не по памяти.
5. **Отделить дефект карты от живого состояния машины.** Счётчики служб и документов в карте — снимок на
   дату; если реестр пульта или папка `docs/` изменились, это не дефект, но это надо сказать в отчёте.
6. **Записать разбор в рабочую копию карточки** (docs/analysis/…), закоммитить только свой файл.
7. **Сдать шаг обычной сдачей** с настоящими SHA ролевых коммитов: `taskflow_subtask_done` с `artifact`
   (контракт `integration_result`: обязательны непустые `summary`, `evidence`, `document_refs` в payload).
   `main` руками не править, merge не делать.

## Грабли, на которые я наступал

- **Очередь автослияния не встанет сама.** Сдача с артефактом очередь не ставит (её ставит только
  `PATCH /api/subtasks/:id` с `done=true`), а проход обслуживания пропускает карточки, у которых строка
  очереди уже есть. У карточки, которую сливали раньше, строка остаётся `merged` — новые коммиты в `main`
  не доезжают. Проверять: `SELECT state FROM worktree_merge_queue WHERE task_id=…` и
  `git rev-list --count main..roles/<id>`. Лечение — вернуть строку в `queued` (Инженер .110), руками в
  `main` не вливать.
- **Массивы в аргументах инструментов приходят обёрнутыми** в `{"item": [...]}`, числа — строками.
  Для `taskflow_work_plan` это ломает запись: писать свою строку чек-листа прямо в `subtask_work_plans`.
  Для сдачи с артефактом верхнеуровневый `evidence` не передавать, а данные положить в `payload` строками.
- **Заметка в библиотеке хранится как ProseMirror-JSON**, а не как markdown. Сверять текст заметки с
  файлом нужно, разобрав JSON и склеив текстовые узлы, иначе получится ложное расхождение.
- **Пути на MacBook с `.110` не проверяются** (процесс агента не может перечислить `/Users/max/Проекты`).
  Это ожидаемо, а не дефект, если карта это оговаривает.
- **У карточки может не быть темы** — тогда `taskflow_topic_send` отвечает «У задачи пока нет темы».
  Передачу по очереди тогда оставлять в комментарии карточки и в отчёте шага.

## Что писать владельцу

Одним предложением: что переносится (SHA), что проверено, что мешает переносу и кто это чинит.
Отдельно: «разработано / проверено / перенесено в main (SHA) / выложено» — не смешивать эти статусы.
