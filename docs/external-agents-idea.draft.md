# Внешние агенты как роли TaskFlow (19.10.2026)

План сверен с кодом. Сам код пока не меняли.

## Как устроено сейчас (по коду)

- Роль запускается внутри сервера движком Pi: `runRoleInProcessUnserialized` вызывает `createAgentSession` (`server/src/runtime/inProcessRun.ts`, около строки 1482).
- Инструменты TaskFlow — объекты `defineTool`, которые собирает `buildRoleToolCatalog` (`roleToolCatalog.ts`). Они вызывают маршруты сервера через `app.inject` от учётки роли, поэтому ключи наружу не выдаются.
- Файлы и команды — встроенные инструменты Pi; на маке их выполняет `host/` через шлюз (`hostOperations`).
- Ход в карточке стримится через `beginTaskLiveTurn` → `liveTurn.onEvent(event)` (формат событий Pi) → WebSocket `tasks:live`.
- Чат: отдельная сессия на пару (чат, роль), `chatSession.ts`; запуск через `startChatRun` в `PiRuntimeAdapter.ts`.
- Рантайм пока только один: `types.ts` жёстко задаёт `RUNTIME_ID_PI`, а валидаторы `isAgentProfile`, `isModel`, `isAgentRun` отвергают всё, кроме Pi. Расширение на ClaudeCode/Codex там прямо помечено как «отложено».
- На .110 установлены: `claude` 2.1.266, `codex`, `gemini` (`~/.npm-global/bin`).

## Где встраивать

1. **Тип рантайма.** Добавить в `types.ts` второй вид, `runtime:cli` (агенты `claude`, `codex`), и расширить валидаторы. Где хранится выбор рантайма для роли — уточнить в `roleRouting.ts` / таблице ролей.
2. **Развилка на запуске.** В `runRoleInProcessUnserialized` до `createAgentSession` выбирать ветку: Pi или новый `cliRun.ts`. Всё, что идёт до развилки (промпт, worktree, план, снимок инструкций, `activeRuns`, `liveTurn`), использовать как есть.
3. **Процесс.** `cliRun.ts` запускает CLI в `cwd` worktree карточки:
   - `claude -p --input-format stream-json --output-format stream-json --verbose --mcp-config <временный> --append-system-prompt <промпт роли>`, продолжение через `--resume <session_id>`;
   - Codex — `codex exec --json` (вариант `app-server` проверить отдельно).
     `abort` — kill процесса, `steer` — запись сообщения в stdin. Так `activeRuns`, сторож зависших заходов и отмена работают без изменений.
4. **Инструменты без MCP наружу.** Те же объекты из `buildRoleToolCatalog` отдаются агенту через stdio-MCP-мост: дочерний процесс, который сеть не слушает и живёт ровно один заход. Инструменты исполняются в процессе сервера: мост пересылает вызов по локальному каналу (pipe или unix-сокет с правами 0600), сервер выполняет `tool.execute` с тем же контекстом роли и карточки. Встроенные инструменты CLI ограничить флагом `--allowedTools`.
5. **Поток событий.** Перевести события stream-json (assistant text, tool_use, tool_result, result) в формат событий Pi для `liveTurn.onEvent` — тогда веб и iOS не меняются.
6. **Чат.** Добавить такую же развилку в `startChatRun`, сохранять `session_id` CLI в той же таблице чат-сессий.
7. **Обнаружение.** Эндпоинт статуса рантайма: `which`, `--version`, проверка входа. В настройках ролей — выбор «Pi / Claude Code / Codex».

## Ограничения и грабли

- **Мак.** Хост сейчас выполняет только файловые и git-операции, запускать агентов он не умеет. Первый этап — только на .110. Для мака нужна новая операция `agent_spawn` в `host/` (отдельная задача).
- **Модель и лимиты** у внешнего агента свои, на подписке Максима. `providerFailover` к нему не применяется; для него нужна своя обработка отказа «лимит».
- **Вливание серверного кода** — только при пустой очереди ролей (правило проекта).
- **Сторож** (правило приборов): пробный заход внешней роли раз в сутки и тревога в «Состояние системы», если CLI разлогинен или исчез. Добавить в `docs/watchers.md`.
