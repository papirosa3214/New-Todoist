# Уборка лишних чатов: право убирать, архивирование вместо стирания, действие уборки

Карточка 0b7a8b81-1c67-45e9-9b53-8c8ac2ce97d0, шаг «fix». Реализация в
`server/src/lib/chatArchive.ts`, `server/src/routes/chats.ts`,
`src/screens/ChatCleanupSheet.tsx`, `src/lib/chatRights.ts`.

## Зачем

В списке чатов копится визуальный мусор: пустые темы задач (0 сообщений,
часто осиротевшие после закрытия карточек). На 21.10.2026 их было 173 из
260. Убрать их было нечем:

- `DELETE /api/chats/:id` сносил строку чата каскадом (сообщения, вложения,
  сессии) — это стирание, а не уборка;
- правило «удалить может только создатель» (`chats.created_by`) к темам задач
  неприменимо: темы заводятся сервером при создании задачи
  (`lib/projectTopics.ts`, `created_by = project.owner_id`), то есть создатель
  у всех тем проекта один, а участников много. Право было мёртвым;
- массового действия в приложении не было вовсе.

## Три правила

### 1. Право убирать

| Комната | Признак | Кто убирает |
|---|---|---|
| Тема задачи (системная) | `task_id` и `parent_chat_id` заданы | любой участник проекта |
| Личная переписка | `room_kind` = `dm` / `personal` / `handoff` / `wake` | только создатель |
| Груповая переписка | обычный чат, созданный человеком | только создатель |
| Общая комната | `room_kind` = `common` | никто (постоянная) |

Правило живёт в `server/src/lib/chatArchive.ts:archiveRight`. Проверка
членства (участник ли вызывающий этой темы) — на маршруте, в `isMember`:
тема задачи доступна тому, кто видит её задачу.

### 2. Убрать = архивировать

Строки не стираются. Чату ставятся две отметки:

- `closed_at` — чат закрыт: уходит из общего списка (`GET /api/chats`), новые
  сообщения в него не принимаются (`409 «Чат задачи закрыт»`);
- `archived_at` — отметка уборки человеком (миграция 162). Нужна, чтобы
  отличать «тема закрылась вместе с задачей» от «чат убран насовсем»: возврат
  задачи в работу (`projectTopics.setTaskTopicClosed`) не открывает убранную
  тему заново.

История, счётчики и статистика по задачам остаются в базе; архивный чат
виден в карточке своей задачи (`GET /api/tasks/:id` отдаёт `chats` без
фильтра по закрытости).

Маршруты:

- `DELETE /api/chats/:id` — убирает в архив (было: стирал строку);
- `POST /api/chats/:id/archive` — то же другим методом. Нужен потому, что
  DELETE в TaskFlow закрыт для делегированных ролей (`auth.ts`), а тему
  задачи убирать вправе и роль.

### 3. Действие уборки

Два шага, оба владельцу (`isOwner`):

- `GET /api/chats/cleanup/candidates` — предпросмотр: сколько чатов и какие;
- `POST /api/chats/cleanup` — сама уборка, только с `confirm: true` в теле.

Кандидат — тема задачи, у которой:

- ни одного сообщения и ни одной строки в `chat_message_queue`;
- `updated_at` старше двух часов (`CLEANUP_MIN_IDLE_HOURS`);
- у задачи нет живой попытки (`attempts.ended_at IS NULL`);
- тема ещё не закрыта и не убрана.

Отбор делается в момент уборки, а не берётся из тела запроса: список мог
устареть между предпросмотром и подтверждением, а правило «не трогать живое»
должно соблюдаться на самом моменте архивирования. Личные и групповые
переписки в кандидаты не попадают никогда — по построению запроса.

## Интерфейс

- Список чатов: кнопка «Убрать лишние чаты» в шапке (только владельцу) →
  шит с количеством и списком кандидатов → подтверждение → уборка.
- Комната чата: кнопка «Убрать чат» (иконка архива) — показывается там, где
  сервер действительно разрешит: `src/lib/chatRights.ts:canArchiveChat`
  (то же правило, что на сервере).

## Проверки

- `server/test/chatCleanup.test.ts` — 13 тестов: право убирать (тема задачи
  участником, личная переписка только создателем, общая комната никогда,
  чужой → 404), архивирование (строка и сообщения остаются, `closed_at`

  кандидат; недавняя, с живой попыткой, с сообщениями и личная переписка —
  нет; без подтверждения уборка не выполняется).
- `src/lib/chatRights.test.ts` — 5 тестов на правило права на экране.

## Границы

- Массовая уборка — только владельцу: это действие сразу по всем темам.
  Уборка одной темы доступна участнику проекта.
- Комната проекта (родитель тем задач) под правило системной комнаты не
  попадает: её создатель — владелец проекта, и убрать её может он же.
- Гонка: тема, выбранная кандидатом, может быть взята в работу секундой
  позже — тогда роль получит `409` при первой записи в убранную тему.
