# Светлая тема веба — кадры для аудита контраста

Снимки экрана веба в светлой теме (MAK-46, критерий приёмки №2).
Лежат рядом с iOS-кадрами из этого же аудита (`docs/2026-10-04-light-contrast-audit/`
в репозитории `TaskFlowNativeBuild`) для прямого сравнения одной
платформы с другой на одних и тех же экранах.

## Вьюпорт

402×874, deviceScaleFactor=2. Браузер Chromium, headless, мобильный
профиль (touch, mobile=true). Запуск: `node scripts/screenshot-light-theme.mjs`
при поднятом dev-сервере `npm run dev` (требует `TASKFLOW_LAN_NO_AUTH=1`
на backend, чтобы RequireAuth пустил без пароля из домашней сети).

## Кадры

- `today-light.png` — экран «Сегодня» (Понедельник, 5 окт.), секция
  «Ждут вас» с активной задачей и бейдж «на проверке» (синий акцент).
  Таббар внизу, FAB по центру, иконка активной вкладки «Сегодня» —
  в красном (--color-red), остальные иконки таббара в --color-sub.
- `task-detail-light.png` — карточка задачи `ad4a56a9…` (MAK-57).
  Видны: id мелким `text-sub`, проект «TaskFlow - NewTodoist» в синем
  акценте (#246da3), заголовок задачи в --color-text, описание с
  `## Работа` (--color-text), иконки действий в шапке
  (Activity/закладка — --color-sub, корзина — --color-red). Бейдж
  счётчика в таббаре — белый card2 с тёмным цифрами.
- `projects-light.png` — список проектов. Шесть карточек с цветными
  аватарами: «TaskFlow - NewTodoist» (синий), «Серверные уведомления»
  (красный), «Apple Напоминания» (жёлто-оранжевый), «TaskFlow Native
  iOS» (синий), «Архив» (нейтральный), «Без проекта» (без цвета).
  Это наглядный тест: ни один светлый акцент не ушёл в неразличимый
  на card2.

## Что НЕ менялось

Темы (тёмная) эти кадры не касаются — `:root[data-theme="light"]` это
только светлый набор токенов, и проверять тут тёмную бессмысленно.
`@theme` остаётся как был, тёмная палитра не задета ни в одном
токене (см. `src/index.css`, строки 1-90 и 156-180).

## Скрипт съёмки

`scripts/screenshot-light-theme.mjs` — отдельный Node-скрипт без
test-runner. Перед загрузкой кладёт `taskflow-ui` в localStorage
с `settings.theme="light"`, открывает корень, RequireAuth делает
LAN-логин (без пароля), затем переходит по `/today`, `/task/<id>`,
`/projects` и снимает PNG.

В скрипте подменены ТОЛЬКО ответы `/api/tasks/<id>/collaboration-plans`
и `/api/tasks/<id>/role-slots` на пустые — CollaborationPlanPanel
на живой задаче MAK-57 падает в ErrorBoundary из-за бага, не
относящегося к этой задаче (роли приходят в неожиданной форме).
Панель плана в шапку аудита цветов не вносит, а остальная карточка
(шапка, проект, описание, таббар, FAB) — на 100% живая, с настоящими
данными владельца.
