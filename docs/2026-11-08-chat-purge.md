# `POST /api/chats/:id/purge` — удаление чата насовсем

Дата: 08.11.2026. Решение владельца: «есть архив, есть просто удалить… если
удалил, уже возвращать нечего».

До этой работы в API было только архивирование (`DELETE /api/chats/:id` и
`POST /api/chats/:id/archive` = `closed_at` + `archived_at`, строки остаются).
Окончательного удаления не существовало.

## Контракт

- Метод: `POST`, тело пустое, ответ `{ ok: true, deleted: true, messages,
  attachments, queue, questions }`.
- 404 — чат не найден или не виден вызывающему.
- 403 — отказ по праву с текстом причины:
  - «сначала убери чат в архив» (нет `archived_at` и нет `closed_at`);
  - «общую комнату удалить нельзя» (`room_kind='common'`);
  - «личная комната роли не удаляется» (`room_kind='personal'`);
  - «комнату задачи удаляет владелец» (`room_kind='task'`);
  - «удалить чат может только его создатель».

## Что делает

1. `stopRoomRuns(chatId, "owner_purge")` — ходы чата останавливаются: удалять
   комнату из-под работающей роли нельзя, её ответ писать будет некуда.
2. `purgeChat()` в одной транзакции: `DELETE FROM chat_questions` (у таблицы нет
   FK на `chats`), `pinned_message_id = NULL` (ссылка на сообщение мешает
   каскаду), затем `DELETE FROM chats WHERE id = ?` — сообщения, вложения,
   участники, сессии, очередь доставки, `chat_room_topics`, обсуждения, выжимки
   и настройки уходят каскадом по FK.
3. Файлы вложений удаляются с диска после транзакции; ошибка файла удаление
   строк не отменяет.
4. Счётчики пишутся в журнал сервера.

Восстановления нет: удалённый чат не восстанавливается, а комната задачи при
следующем обращении заводится заново и уже без прежней переписки.

Проверки: `server/test/chatPurge.test.ts` (5 проверок, RED → GREEN), `tsc
--noEmit`. Клиентская часть — `docs/2026-11-08-chat-archive-and-delete.md` в
репозитории iOS.
