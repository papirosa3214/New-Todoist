### Связанное

Секретарь при разборе **не удаляет** ничего: мусор помечается и остаётся
видимым. Окончательное решение принимается по факту обращений ролей —
см. сторожа №1.

## Как добавить сторожа

1. Создать сторожа рядом с прибором, в той же задаче.
2. Проверка — **пробным ходом**, не «структура есть».
3. Тревога — задачей в «Серверные уведомления», не чаще раза в сутки.
4. Запись сюда: что, зачем, где код, как должно работать, что было.
5. Тест на живой схеме: «сторож молчит, когда всё хорошо» — обязателен.
   Сторож, который молчит всегда, хуже отсутствия сторожа.
## Рабочий чек-лист исполнителя

`server/src/lib/workPlanWatcher.ts`: при старте и раз в 15 минут пишет пробный план, обновляет этап, сверяет чтение. Все служебные строки откатываются одной транзакцией. При сбое — одна задача в «Серверных уведомлениях» в день (устойчивый ID по UTC-дате). Хранение не должно молча терять этапы. Тесты: `server/test/subtaskWorkPlan.test.ts`. Добавлен 10.10.2026.

## 4. Wake-канал вебхуков

| | |
| --- | --- |
| **Что смотрит** | Цепочка `event → durable delivery → подписка → wake_queue` отрабатывает на изолированной пробе |
| **Зачем** | Владелец ждёт, что новый чат Codex просыпается по подпискам; если цепочка рвётся на любом шаге (нет ключа, миграция 128 не накатилась, runner не парсит `FOLLOWUP=`) — никто не узнает, пока не придёт событие вживую |
| **Где код** | `server/src/lib/webhookWakeWatcher.ts`, подключён в `server/src/index.ts` |
| **Как проверяет** | Пробный ход: создаёт служебную подписку с произвольным UUID (`00000000-0000-4000-8000-000000000001`), пишет синтетическое событие `plan_subtask_started`, прогоняет `processWebhookDeliveryPass` (на `127.0.0.1:0` — ошибка ожидаема) и `processWakePass` под фейковым runner'ом, который возвращает `codex_followup_id`. Затем снимает подписку каскадом. **Не будит живой чат**: пробный UUID изолирован, доставка идёт на заведомо несуществующий endpoint, и никакого SSH в Codex из пробы нет |
| **Как часто** | При старте сервера и далее раз в 30 минут |
| **При поломке** | Задача в «Серверные уведомления», не чаще одной в сутки |
| **Что НЕ делает** | Не будит живой чат каждые 30 минут (это могло бы задеть владельца), не хардкодит продовый UUID 01a123bf-… (это требование ведущего 2026-10-10). Реальный переход на новый чат — отдельная задача по согласованию с владельцем |
| **Тесты** | `server/test/webhookWakeWatcher.test.ts` |
| **Добавлен** | 10.10.2026 |

### Что должно работать

- На старте `bootstrapSecrets()` прогревает кеш расшифрованных секретов из БД
- `createSubscription` / `updateSubscription` шифруют секрет колонкой `secret_encrypted` (AES-256-GCM)
- `resolveSecret` читает из БД и расшифровывает, fail-closed без ключа (без падения всего сервера)
- `processWakePass` парсит `codex_followup_id` из stdout `codex queue` и пишет в `webhook_wake_queue.codex_followup_id`
- `wake_acked_at` остаётся NULL до явного callback чата через `POST /api/integrations/webhooks/_wake_ack` или будущего turn_started события от app-server
- Тестовая ручка `/api/integrations/webhooks/:id/test` возвращает nested `wake.{codex_thread_id, has_thread, queued, codex_followup_id, acked}` (HTTP ≠ queued ≠ acked)
