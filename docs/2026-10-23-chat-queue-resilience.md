# Очередь чата: ожидание, восстановление и единый бюджет повторов

Запрос владельца 23.10.2026: реализовать пункты 1–3 из разбора очереди. Механизм выкладки и инструкции ролей в эту работу не входят.

## Поведение

- Ожидающая FIFO доставка остаётся pending. В picked она переходит атомарно только перед выполнением. Живой писатель сессии не отбирается.
- Ожидание ограничено 5 минутами. Просроченное задание становится failed, сохраняет исходное сообщение и не исполняется позднее, когда освободится очередь.
- Подготовка контекста и подготовка сессии имеют отдельные пределы по 5 минут. Ресурсы, пришедшие после истечения срока, закрываются; опоздавшая сессия не запускает модель. Это не таймаут размышления модели.
- Heartbeat включается только после FIFO admission. Учитывает события модели и работающие инструменты. Голый таймер без активности не продлевает аренду бесконечно.
- Контроль тишины модели по-прежнему выключен по решению владельца; существующий 30-минутный потолок выполнения сохранён. Долгие инструменты и размышление не прерываются новым таймаутом подготовки.
- Независимые пары чат/роль восстанавливаются параллельно; общий предел — 4. Внутри пары сохраняется FIFO. Перекрывающиеся проходы восстановления и повторов ошибок делят этот предел и защиту от повторного запуска.
- Возврат после ошибки, потерянной аренды и перезапуска сервера расходует один бюджет — по умолчанию два автоматических повтора. Исходный запуск в этот бюджет не входит.
- Для прежних записей берётся сумма retryCount + reclaimCount; история повторов сохраняется.
- При исчерпании бюджета доставка остаётся failed с expired/retryExhausted. Однократное уведомление владельцу содержит причину, чат, сообщение и способ продолжить вручную — повторить сообщение. Новое сообщение получает собственный бюджет.
- Синхронная регистрация восстановления сохраняет защиту передачи интегратору до первого await, без ложного picked во время ожидания.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| TASKFLOW_CHAT_QUEUE_WAIT_MS | 300000 | Срок ожидания в FIFO |
| TASKFLOW_CHAT_PREPARATION_TIMEOUT_MS | 300000 | Предел отдельной фазы подготовки контекста/сессии |
| TASKFLOW_CHAT_RECOVERY_CONCURRENCY | 4 | Общий предел восстановления и повторов, максимум 16 |
| TASKFLOW_CHAT_DELIVERY_MAX_RESTARTS | 2 | Единый бюджет автоматических повторов |
| TASKFLOW_CHAT_DELIVERY_LEASE_MIN | 5 | Срок аренды выполнения |

При отсутствии MAX_RESTARTS сохранено чтение прежних DELIVERY_RECLAIMS / DELIVERY_MAX_ATTEMPTS. Это больше не независимые бюджеты. Периодический проход восстановления остаётся прежним: по умолчанию 600 секунд, поэтому истечение аренды не означает мгновенного возврата ровно через 5 минут.
