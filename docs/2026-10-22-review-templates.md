# Разовые проверки из чатов TaskFlow — 22.10.2026

## Договорённость

Роли получают два инструмента существующего механизма командных шаблонов:
- `taskflow_review_result`: критик проверяет готовый результат; Git-интеграция не требуется.
- `taskflow_review_code`: критик проверяет код; только approved открывает архитектору существующий этап интеграции.

Каждая проверка разовая. approved / changes_requested / blocked завершают её без автоматического возврата исполнителю и нового цикла проверки. Повторная проверка — отдельный запрос.

## Запуск

По умолчанию `launch_mode=propose`: существующая карточка предложения с кнопкой запуска владельцем. `launch_mode=authorized`: немедленный запуск по предварительному разрешению владельца в исходном чате. Инструмент требует ID сообщения владельца; сохраняет ID и цитату разрешения. Например: «Если посчитаешь нужным, вызови критика». Роль не может выдать разрешение себе. Неоднозначные сообщения, вопросы, цитируемые команды и запреты не дают прямого запуска; остаётся предложение кнопкой. Разрешение критика отдельно не разрешает интеграцию кода. Нужен существующий project_id.

## Возврат

Любой вердикт сохраняется вместе с сообщением в исходный чат и долговечным заданием доставки. Исходная роль получает результат через существующую очередь чата, даже если занята другой карточкой. Повторная сдача того же review не создаёт второе сообщение. Роль обсуждает результат с владельцем; автоматически исправлять и повторять проверку не должна.

Критик получает короткий формат: `Принято: ...` либо `Проблема: ... Исправить: ... Ожидается: ...`, по 2–3 предложения на проблему. Общий многораздельный отчёт для этих шаблонов заменён этим форматом. Обычные планы сохраняют свой цикл.

Разовые проверки исключены из подбора текущей обычной работы чата. Незапущенные предложения заменяются только внутри своего профиля; предложение ревью не удаляет обычную подготовленную карточку.
