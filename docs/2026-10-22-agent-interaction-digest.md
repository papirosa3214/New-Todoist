# Диgest: подходы к взаимодействию ИИ-агентов (собранные источники)

## Источники и факты

S1. MCP, спецификация 2025-11-25 (modelcontextprotocol.io/specification/2025-11-25, прочитано целиком). JSON-RPC 2.0, stateful-соединения, согласование возможностей. Сервер предлагает: Resources, Prompts, Tools. Клиент предлагает: Sampling, Roots, Elicitation. Дополнительно: конфигурация, progress, cancellation, error reporting, logging. Принципы безопасности: согласие и контроль пользователя, приватность данных, безопасность инструментов (описания инструментов считаются недоверенными, если сервер не доверенный), контроль LLM-sampling. Версии: 2024-11-05 legacy, 2025-06-18 stable, 2025-11-25 latest stable (в 2025-11 добавлены OIDC discovery, incremental scope consent, URL-mode elicitation, experimental Tasks).

S2. A2A, официальная документация (agent2agent.info/docs/introduction, прочитано целиком). Инициирован Google Cloud, с июня 2025 под Linux Foundation, v1.0 в 2026. Три участника: User, Client, Server (Host отдельно не выделен — в отличие от MCP). Ядро: AgentCard (JSON, путь /.well-known/agent-card.json — профиль возможностей и требований аутентификации), Task (состояние, история, артефакты), Artifact (неизменяемый результат), Message, Part. Модель общения: task-centric, полный жизненный цикл задачи, capability discovery через AgentCard, UX-negotiation. Транспорт — HTTP, SSE, JSON-RPC. Принципы: работа с агентами в естественных ненавязчивых сценариях без общего состояния; поверх существующих стандартов; secure by default; поддержка долгих задач (часы–дни, с участием человека); независимость от модальности. Поддержка 50+ технологических партнёров (Atlassian, Box, Cohere, LangChain, MongoDB, PayPal, Salesforce, SAP, ServiceNow).

S3. A2A — вторичные источники: tyk.io (жизненный цикл задачи как конечный автомат, состояния с префиксом v1.0; утилиты подписи AgentCard, проверка по открытому ключу издателя/реестру/x5c); finance.yahoo (A2A >150 организаций, поддержка в облачных платформах, A2A и MCP дополняют друг друга: A2A — между агентами, MCP — к инструментам); aigrowthagent (трёхслойная архитектура A2A, SSE-стриминг, декларированная модель аутентификации).

S4. AGNTCY: OASF (docs.agntcy.org/oasf) — расширяемая схема описания агента (навыки, интерфейсы, зависимости, ограничения) как «машиночитаемый ID»; не заменяет A2A/MCP, а описывает агентов поверх них. ADS (Agent Directory Service) — возможности, каталог, контент-адресуемое хранилище, криптографическая подпись, IETF Internet-Draft draft-mp-agntcy-ads-02 (обновлён 06.07.2026). Слой SLIM — безопасный транспорт, по которым едут A2A, MCP и ACP. Splunk: AGNTCY — «соединительная ткань»: OASF + каталог + идентичность + транспорт + наблюдаемость.

S5. Survey: «LLM-Based Multi-Agent Orchestration: A Survey of Frameworks, Communication Protocols, and Emerging Patterns» (MDPI Future Internet 18(6):326; препринт 202604.2147; литература до марта 2026). Таксономия: топологии — centralized, decentralized, hierarchical + ось адаптивности (dynamic). LangGraph нативно поддерживает supervisor, hierarchical и swarm + условные рёбра (dynamic). В списке протоколов: IBM ACP (2025) и его слияние с A2A под LF AI & Data (август 2025); Agent Network Protocol (ANP, arXiv 2508.00007).

S6. Openlayer, «Multi-agent system architecture: a comparison guide + best practices» (март 2026). Пять базовых паттернов: supervisor (orchestrator-worker), hierarchical, peer-to-peer, blackboard, swarm. Количественные утверждения источника: исследования агентных систем выросли с 820 работ в 2024 до >2500 в 2025; supervisor-паттерн поднял параллельные задачи Google на 80%, но ухудшил последовательное мышление на 70%; мультиагентные системы выигрывают на параллелизуемых задачах, но деградируют на 39–70% на последовательном мышлении; квадратичный рост координационных накладных расходов.

S7. Durable execution: Zylos Research (24.04.2026) — суть: персистить завершённые границы исполнения, восстанавливаться после сбоя без повторения вызовов инструментов, внешних мутаций, человеческих согласований и исходящих сообщений. Движки: Temporal, Restate, Inngest, Hatchet, DBOS, Cloudflare Workflows, AWS Lambda Durable Functions, Azure Durable Task. Актуально: OpenAI Agents SDK (апрель 2026) — внешнее состояние, снапшоты, sandbox-aware оркестрация, rehydration в свежие контейнеры. Inngest: HITL и durable execution совпадают — suspend/resume на часы/дни ожидания согласования; чекпоинты между вызовами инструментов, backoff, сохранение контекста при сбоях внешних API. MongoDB reference architecture: Temporal как durable-слой для agentic-воркфлоу.

S8. Изоляция и защита: Northflank (microVM Kata, gVisor, загрузка ~125 мс, <5 МиБ накладных, до 150 VM/сек на хост); E2B (Firecracker microVM, открытый runtime под Apache-2.0), Modal (gVisor), Vercel Sandbox (Firecracker); manveerc (для недоверенного кода общие контейнеры недостаточны — нужны microVM или gVisor); Check Point + Google Cloud (июнь 2026): AI Defense Plane + Gemini Enterprise — инвентаризация агентов, предразвёрточная политика, runtime-guardrails с детектированием prompt injection.

S9. Контекст и изоляция: arXiv 2604.14228 (разбор дизайна Claude Code) — graduated compression, cache-aware compaction, read-time projection, subagent summary isolation; CLAUDE.md-иерархия как «накопительный playbook»; различение context engineering (сборка контекста) и agent memory (устойчивые знания). morphllm — subagent context isolation как главный паттерн для больших задач; main-агент держит проектный контекст, subagent — свой контекст и свои права на инструменты; lazy loading определений инструментов — 95% сокращение контекста. richsnapp — субагент имеет свой контекст и свой цикл исполнения; compaction, retrieval, tool-use isolation, разделение диалога.

S10. Собственные материалы TaskFlow: docs/2026-10-04-multi-agent-handoff-patterns.md — AutoGen (pub-sub handoff), AG2 (GroupChat, выбор говорящего решает LLM), CrewAI (allow_delegation, менеджер в Process.hierarchical, маршрутизация решается LLM), LangGraph (Command(goto=…), Command.PARENT), OpenAI Swarm (transfer_to_xxx, stateless). Вывод: заимствовать — handoff как явный шаг с адресатом; маршрутизация через матрицу прав, а не через LLM-судью; правила для агентов в одном месте. docs/2026-10-10-agent-comms-research-sources.md — сравнение каналов: Factory Mission Control (hub-and-spoke, спавн свежих воркеров, валидация на чекпоинтах), A2A (P2P, Agent Card discovery, sync/SSE/async push), MCP, Claude Agent SDK (subagent spawn через Agent tool, 18 lifecycle-хуков, строгая изоляция контекста, resume по session_id), LangGraph (shared state graph, checkpointing, pause/resume, time-travel), CrewAI (event-driven flows; абстракция мутнеет при >5 агентах), AutoGen (устарел, maintenance с 10.2025), Microsoft Agent Framework 1.0 (MCP + A2A native), Google ADK (иерархическое дерево, A2A native), OpenAI Agents SDK (handoff-модель, sandbox tools), MQTT pub/sub с топиками task/{id}/role/{role}/slot/{slot} (масштабирование без каскадных сбоев). KB: обзор мультиагентных систем 16.09.2026 (3d243245) — 7 топологий, 7 принципов, 10 трендов, но без веб-доступа; карта взаимодействия агентов TaskFlow (62322941) — текущая схема as is, пробелы: семантическое согласование, полноценный durable execution, наблюдаемая маршрутизация.

S11. KB 2026-10-07 «agent-comms-chat-vs-step-pipeline»: в TaskFlow чат не является носителем работы — работа идёт конвейером шагов; эталонные системы строятся на pub-sub/actor-модели, где сообщение будит следующего исполнителя; в нашей системе канал агентов практически мёртв, основная активность — дежурные «принял, отвечу по message_id».

## Известные противоречия

C1. «Мультиагентность улучшает результат» (S6: +80% на параллельных задачах) vs «деградация на последовательном мышлении на 39–70%» (S6) — не противоречие, а зависимость от типа задачи; вывод: выбор топологии определяется структурой задачи.
C2. Онлайн-обзоры 2026 (S6, S7, S8) называют себя мартовскими–июньскими 2026, тогда как KB-заметки от 16.09.2026 (S10) строили картину без веб-доступа — часть фактов S10 (например, «AutoGen ушёл в maintenance, всё переведено в Microsoft Agent Framework 1.0») подтверждается свежими источниками, но цифры S6 и S10 могут расходиться.
C3. A2A: официальная документация (S2) говорит «50+ партнёров», вторичный пресс-релиз (S3) — «более 150 организаций»; даты и определения «поддержки» различаются, доверять нужно официальной спецификации.
C4. Распространённость OSI/KB-заметки про «Open Semantic Interchange» (2026) не подтверждена ни одним свежим источником в этом ходе — фиксировать как слабое подтверждение.
C5. Числа S6 (820→2500 работ, +80%/−70%, 39–70%) — единичный источник-компиляция, не рецензированный первоисточник; использовать как ориентир, не как факт.
