# Комнаты субагента в боковой панели сессии (iOS)

Задача: роль, вызванная Помощником или Оркестратором через `taskflow_call_role`,
работает в своей комнате-ветке. Владелец должен видеть эти комнаты **не в общем
списке сессий**, а в **боковой панели своей сессии** — по ролям, со статусом.

Серверная часть сделана (29.10.2026, коммит с миграцией `185_subagent_rooms`).
Осталось клиентское.

## Что уже есть на сервере

| Что | Как |
|---|---|
| Комната помечена | `chats.subagent_role_id` (вызванная роль), `chats.subagent_state` (`open` / `finished` / `failed`) |
| Комнаты скрыты из списка сессий | `GET /api/chats` отдаёт только `subagent_role_id IS NULL` |
| Список комнат сессии | `GET /api/chats/{chatId}/subagent-rooms` |
| Открытие комнаты | обычный `GET /api/chats/{roomId}` + `GET /api/chats/{roomId}/messages` — тот же экран, что у чата роли |
| Автозакрытие | когда выжимка ушла в главную сессию, сервер сам ставит `subagent_state='finished'` и `closed_at`; при сбое хода — `'failed'` |

### Ответ `GET /api/chats/{chatId}/subagent-rooms`

```jsonc
{ "rooms": [{
  "id": "…",                    // id комнаты — открывать этим
  "title": "Секретарь → Архитектор: Спроектируй схему…",
  "role_id": "role_architect",  // какая роль работает в комнате
  "role_name": "Архитектор",
  "state": "open",              // open | finished | failed
  "question": "Спроектируй схему хранения карточек",
  "answer_preview": "…",        // начало ответа, если он уже есть
  "message_count": 12,
  "unread_count": 3,
  "created_at": "2026-10-29T…",
  "closed_at": null             // null — комната открыта
}]}
```

## Как это выглядит у владельца

Модель субагента (владелец 29.10.2026): он **одноразовый** — набирает
контекст, сжимает его в выжимку, отдаёт вызывающей роли и исчезает. Поэтому
**комната новая на каждый вызов**: у роли их в сессии обычно несколько, и
шторка со списком — обычный путь, а не запасной.

1. **Главное меню чата**, справа — панель со списком ролей (уже есть).
2. Нажал на роль → **снизу поднимается шторка** со списком её комнат в этой
   сессии. В шторке — название (вопрос), статус, время.
   - Комнат несколько (обычный случай) — шторка со списком, выбор открывает
     нужную.
   - Комната одна (частный случай) — можно открыть её сразу, без шторки:
     нажал на портрет → сразу в комнату.
3. В комнате — тот же экран чата, что у обычной роли: видно, как роль
   работала (шаги, инструменты, текст) и её ответ.
4. **Статусы в шторке:**
   - `open` — «работает» (идёт ход роли; можно остановить кнопкой в карточке
     главной сессии);
   - `finished` — «завершена» (выжимка уже в главной сессии);
   - `failed` — «сбой» (ход роли не состоялся).
5. Комната закрывается **сама**, как только выжимка из неё попала в главную
   сессию. Закрытую комнату из шторки всё равно можно открыть и посмотреть.
6. Комнат может накопиться за сессию — сортировка сверху новые, у завершённых
   приглушённый вид и пометка «завершена».

## Что делать на клиенте

1. `APIClient+RoleChats.swift` — метод `subagentRooms(chatID:)` → `GET /chats/{id}/subagent-rooms`,
   модель ответа с полями выше.
2. Модель сессии/чата — хранить комнаты текущей сессии и обновлять их:
   - при открытии сессии — один запрос;
   - по событию `chat:new` в комнате — обновить статус и счётчик непрочитанного;
   - после того как ответ роли лёг в главную сессию — статус «завершена»
     (сервер уже поставил; клиенту достаточно перечитать или взять из события).
3. Экран комнаты — переиспользовать существующий экран чата роли
   (`RoleChatRoomScreen` / загрузчик по `chatID`), он уже умеет показывать
   историю и живой ход.
4. **Кнопки «открыть комнату» в coordination-карточке не делать** — владелец
   прямо отказался от неё (28.10.2026): комната и так достигается из панели
   роли, карточка в главной сессии остаётся просто «вопрос → ответ».

  комната не в списке сессий, есть в панели сессии со статусом и ролью,
  статус меняется `open → finished / failed`, чужая сессия — 404.
- Клиентских тестов в проекте по такой схеме нет — проверять вживую на
  устройстве: Помощник зовёт Архитектора → в панели роли появляется комната →
  статус «работает» → после ответа «завершена».
