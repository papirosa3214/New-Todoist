**Карточка:** 3e27dafe-ae7f-4449-8978-ba68d40f6aea · **Шаг:** f7f14da7 (layouts\_and\_interaction, designer) · **Дата:** 2026-10-14

**Канон в репозитории:** `docs/2026-10-14-widget-gallery-layouts-and-types.md`

**Основа:** визуальный язык `docs/2026-10-14-widget-visual-language.md` (палитра, иконки, шкалы, состояния, темы) и контракт расширения из карты устройства виджета (заметка `632ef8d4`).

**Что из этого следует.** У `metrics` всего три поля (`label`, `value`,

которое описано в карточке. `checklist` с единственным полем `text` теряет

Виджетов 112, а видов шесть. Дальше — что с этим делать.

## 2. Как выбирается виджет: тема → вид

Секретарь выбирает виджет по теме, а не по единственному доступному формату.
Правило выбора — из 12 групп рецептов:

| Группа рецептов | Тип | Почему этот, а не другой |
|---|---|---|
| 10.1 сводка по проектам, 11.1 моя сводка, 12.1 активность ролей, `task_stats` | `status_board` | сравнение по статусам: смысл держит цвет и иконка статуса, а не число |
| 5.1 события недели, 5.4 готовность к пятнице, 6.5 выходные дела, 4.2 план поездки | `calendar_grid` | вопрос «в какой день» — по сетке, а не по столбику |
| 5.5 дедлайны-горизонт, 11.3 мои просрочки, 2.5 следующий врач, 4.2 поездка | `timeline` | вопрос «когда и в каком порядке» — по оси дат |
| 10.2 готовность релиза, 3.2 прогресс курса, 6.2 ремонт, 2.1 шаги | `ladder` | этапы разной величины — лестницей, а не пятью одинаковыми полосами |
| 12.1 активность, 11.2 прогресс эпика, 7.2 серия дней, 1.2 расходы по дням | `heatmap` | вопрос «когда былоbusy» — по плотности сетки, а не по высоте столбика |
| 8.4 сравнение цен, 8.5 цены по магазинам, 2.3 вес за неделю | `compare` | ровно два значения, разница между ними и есть ответ |
| 5.3 неотвеченные приглашения, 10.2 этапы релиза, 4.3 сборы в поездку | `chain` | цепочка шагов с пройденным и оставшимся |
| 11.3 мои просрочки, 10.3 задачи по проекту, 7.3 привычки по дням | `bars_list` | список, где у каждой строки своя шкала и статус |

Правило одно: **у каждого типа есть хотя бы одна тема, которую нельзя
изобразить другим типом без потери смысла.** Если у нового типа такой темы
нет — тип лишний.

## 3. Проверка границы типа на живом коде

Прежде чем проектировать, проверено: не съест ли сервер имя нового типа.
Прогон выполнен на настоящем `server/src/lib/widgetNormalize.ts` (временный
зонд, удалён после прогона, состояние ветки чистое).

Причина риска: `canonicalizeWidget` для любого типа, которого нет в
`CANONICAL_TYPES`, идёт в ветку «старый формат секретаря» и ищет в корне
блока ключи `metrics`, `chart`, `checklists`.

**Результат прогона 15 кандидатов + 3 отрицательных контроля:**

| Блок | Тип после нормализации | Блок изменён | Итог |
|---|---|---|---|
| `status_board` | `status_board` | нет | проходит байт в байт |
| `calendar_grid` | `calendar_grid` | нет | проходит байт в байт |
| `timeline` | `timeline` | нет | проходит байт в байт |
| `ladder` | `ladder` | нет | проходит байт в байт |
| `heatmap` | `heatmap` | нет | проходит байт в байт |
| `compare` | `compare` | нет | проходит байт в байт |
| `chain` | `chain` | нет | проходит байт в байт |
| `bars_list` | `bars_list` | нет | проходит байт в байт |
| `ring`, `milestones`, `gauge`, `bignumber`, `split`, `icon_summary`, `sparkline_row` | без изменений | нет | проходят байт в байт |
| **контроль** `{type:"heatmap", chart:{…}}` | **`chart`** | **да** | имя типа потеряно |
| **контроль** `{type:"heat_cells", metrics:[…]}` | **`metrics`** | **да** | имя типа потеряно |
| **контроль** `{type:"steps_ladder", checklists:[…]}` | **`checklist`** | **да** | имя типа потеряно |

Отрицательные контроли независимо подтверждают вывод архитектора. Практический
вывод: **все восемь типов ниже спроектированы без корневых ключей `metrics`,
`chart`, `checklists`** — и потому проходят нормализацию без потерь. Проверка
обязательна тестом на сервере: если будущий тип введёт запрещённый корень,
тест должен падать.

## 4. Новые компоновки поверх шести действующих типов

Это не новые типы, а новые способы нарисовать уже существующие данные. Клиент
учится рисовать старый блок иначе; блок остаётся совместимым, старые 112
блоков продолжают работать.

### К1. `metrics` → плитки со смысловым цветом и иконкой

**Данные:** те же `items`, но у каждого появляется `tone` из смысловой таблицы
языка и необязательная `icon`.

**Источник:** `taskflow_project_tasks` + `taskflow_agents` — статусы задач и
роли; агрегат по статусам считает секретарь.

**Вид.** Тёмная тема: плитка `card2`, слева иконка 18 прикладного цвета,
справа число `tf-task-title` 20/600, под ним подпись `tf-micro` `dim`. Светлая
тема: то же самое, заливки плотнее (15/18/25 % против 12/15/18 %), цвет иконки —
прикладной токен светлой темы, а не тёмный.

```widget
{"type":"metrics","title":"Активность ролей · неделя","tone":"categorical",
 "items":[
   {"label":"Разработчик","value":"18","icon":"bot","tone":"blue","delta":"+4","trend":"up"},
   {"label":"Критик","value":"11","icon":"eye","tone":"purple","delta":"+2","trend":"up"},
   {"label":"Дизайнер","value":"5","icon":"palette","tone":"teal","delta":"+1","trend":"up"}
 ]}
```

**Чем отличается от обычного `metrics`:** появляется цвет и иконка, статус
виден без чтения подписи; совпадает с §1.4 языка.

**Состояния.** Загрузка — скелетон той же сетки 2×2. Пусто — иконка 18 `dim`
и «Данных пока нет», блок не отправляется. Ошибка — `ErrorBanner` внутри.

**Интерактив.** Тап по плитке раскрывает строку списка задач этой роли
(см. §7.1). Свайп по ряду не применяется.

### К2. `checklist` → строки со статусом и прогрессом справа

**Данные:** `items` получают необязательные `tone` и `meta`.

**Источник:** тот же список задач, что и сейчас, плюс `due_date` (см. раздел 6 —
на сегодняшний день ролевым инструментом не отдаётся).

**Вид.** Слева `StateMark` 21 с цветом статуса, по центру название в две
строки, справа — либо число дней просрочки цветом `red` с иконкой
`calendarSmall`, либо мини-шкала высотой 4. Тёмная тема: трек `card2`, заливка
прикладным цветом 18 %. Светлая: заливка 25 %, иначе шкала на белом не
читается.

```widget
{"type":"checklist","title":"Мои просрочки · 3","rows":true,
 "items":[
   {"text":"Оплата карты МТС","done":false,"tone":"over","meta":"−11 дней"},
   {"text":"Счёт поставщику","done":false,"tone":"over","meta":"−4 дня"},
   {"text":"Отчёт по проекту","done":false,"tone":"inprog","meta":"−1 день","progress":60}
 ]}
```

**Чем отличается:** силуэт строки меняется — у пункта появляется статус и
вторичная величина справа.

**Состояния.** Загрузка — скелетон из трёх строк по 36 pt. Пусто — «Просрочек
нет» зелёной галочкой (из языка §5.3).

**Интерактив.** Тап по строке раскрывает детали на месте (исполнитель,
проект, срок). Строка «ещё 8 просрочено» раскрывает список до 20 строк.

### К3. `chart` bar → горизонтальные полосы с подписью у края

**Данные:** те же `points`, рисуются повёрнутыми.

**Источник:** агрегат по статусам или по категориям расходов.

**Вид.** Подпись категории — слева, `tf-row` 14/400, обрезается с многоточием;
полоса справа, высота 8, радиус 9999, заливка прикладным цветом 18 %, конец
полосы — точка 6. Значение печатается справа от подписи, не на полосе: число на
заливке своего цвета не проходит контраст (язык §1.7). Тёмная и светлая темы
различаются плотностью заливки, геометрия одна.

**Чем отличается:** длинные названия категорий («Назначены, не взяты») больше не
режутся под углом вертикального столбика.

**Состояния и интерактив.** Как у обычного `chart`. Тап по полосе
раскрывает состав категории. Предел — 8 полос.

### К4. `progress` → шкала с делениями и вехами

**Данные:** те же `items`, но `note` может содержать дату вехи.

**Источник:** `release_progress` — процент по компонентам считается по задачам
с соответствующей меткой.

**Вид.** Шкала 8 высотой во всю ширину, сверху — деления в 25 % с подписями
`tf-micro` 10/500 `dim`, на шкале — ромб вехи цветом `purple` и подпись даты под
ним. Тёмная тема: деления `stroke`; светлая: деления чуть плотнее, иначе
исчезают на белом.

```widget
{"type":"progress","title":"Релиз v2.4","milestones":true,
 "items":[
   {"label":"Подготовка","value":100,"note":"готово"},
   {"label":"Сервер","value":65,"note":"в работе"},
   {"label":"Клиент","value":20,"note":"ждёт контракта"}
 ],
 "milestone":{"label":"Релиз","at":80,"date":"20.10"}}
```

**Чем отличается:** появляется привязка ко времени — на шкале видно, где цель,
а не только «сколько процентов».

**Состояния и интерактив.** Тап по строке раскрывает состав этапа.

### К5. `card` → шапка с цветной лентой статуса

**Данные:** те же поля плюс необязательный `tone`.

**Источник:** одна задача или проект целиком.

**Вид.** Лента 4 высотой во всю ширину сверху, цвет статуса, радиус карточки 16
и лента повторяет верхние углы. Заголовок 15/600, подзаголовок `tf-caption`
`sub`, тело `tf-row`, строки `label`/`value` через `Divider` 1 px `stroke`.
Тёмная и светлая темы используют один и тот же токен тона — лента остаётся
заметной в обеих.

**Чем отличается:** статус читается до чтения текста.

### К6. `metrics` → одна горизонтальная лента чисел

**Данные:** те же `items`, но показываются два-три значения в ряд.

**Источник:** любая сводка из трёх чисел.

**Вид.** Три плитки в ряд, между ними 1 px `stroke`, каждая: значение 20/600 и
подпись `tf-micro` `dim` под ним, без иконок. На узком экране (менее 360 pt по
ширине) переносится в две строки. Тёмная тема — то же самое, различие только в
поверхности `card`.

**Зачем.** `metrics` сегодня всегда 2×2 или ряд в четыре плитки — четыре
числа в ряд на телефоне не читаются. Лента из трёх — законная форма для
короткой сводки.

## 5. Восемь новых типов

Порядок — по убыванию готовности данных. **Из восьми типов три не требуют
правок сервера, кроме регистрации типа** (`status_board`, `chain`,
`bars_list`), остальным пяти нужны данные — см. раздел 6. Поправка внесена
14.10 после вопроса разработчика: в первой редакции документа здесь стояло
«пять», что противоречило таблице раздела 6.

### Т1. `status_board` — доска статусов

**Зачем.** Ответ на «где основная масса» сегодня даёт `metrics` (плитки без
цвета) или `chart` bar (высота столбика). Ни то, ни другое не показывает, что
просрочено, а что в работе. Доска показывает статус цветом, иконкой и подписью
одновременно.

**Данные и источник.**

| Поле | Тип | Обяз. | Диапазон | Пример | Откуда |
|---|---|---|---|---|---|
| `type` | string | да | `status_board` | `status_board` | — |
| `title` | string | нет | ≤ 60 знаков | `Сводка по задачам · 14.10` | — |
| `groups` | array | да | 2..8 | — | `taskflow_project_tasks` + `taskflow_my_tasks` |
| `groups[].label` | string | да | ≤ 24 знаков | `Просрочено` | статус задачи |
| `groups[].value` | number | да | ≥ 0 | `7` | счётчик статуса |
| `groups[].tone` | string | да | смысловая таблица §1.4 | `over` | `over`, `inprog`, `review`, `done`, `free`, `noasg`, `block`, `future` |
| `groups[].share` | number | нет | 0..100 | `12` | доля от общего, целое |
| `groups[].icon` | string | нет | словарь `LUCIDE_ICONS` | `calendarSmall` | словарь проекта |
| `note` | string | нет | ≤ 80 знаков | `из 58 всего` | — |

```widget
{"type":"status_board","title":"Сводка по задачам · 14.10","note":"из 58 всего",
 "groups":[
   {"label":"Завершено","value":21,"share":36,"tone":"done","icon":"check"},
   {"label":"В работе","value":12,"share":21,"tone":"inprog","icon":"activity"},
   {"label":"Назначены, не взяты","value":14,"share":24,"tone":"free","icon":"circle"},
   {"label":"Просрочено","value":7,"share":12,"tone":"over","icon":"calendarSmall"}
 ]}
```

**Вид в тёмной теме.** Блок `card`, поля 12. Каждая группа — строка высотой 44:
`StateMark` 21 слева цветом тона, название `tf-row` 14/400, справа число
`tf-row` 14/400 `tabular-nums` и под ним доля `tf-micro` 10/500 `dim`. Между
строками — `Divider` 1 px `stroke`. Под заголовком — полоса доли 4 высотой во
всю ширину, составленная из сегментов тона в порядке убывания `share`.

**Вид в светлой теме.** Геометрия та же. Менются три вещи: заливка сегментов
18 % → 25 % (на белом 15 % не читается), цвет тона берётся из светлой палитры,
`Divider` — `rgba(0,0,0,.09)`. Ни один элемент не исчезает; проверка по пункту
10 чек-листа языка.

**Отличие по §7 языка:** силуэт (строки с долями против плиток), ведущий
элемент (StateMark слева), привязка цвета (смысловая, не категориальная),
плотность (4 смысловые строки против 8 анонимных плиток). Отличается по
четырём признакам из пяти — проходит тест подписи.

**Состояния.**

| Состояние | Вид |
|---|---|
| Есть данные | как выше, 2..8 строк, предел 8 |
| Загрузка | скелетон четырёх строк 44 pt с `card2`, без мигания |
| Пусто | иконка 18 `dim` + «Данных пока нет», высота 44; блок не отправляется |
| Ошибка | `ErrorBanner` внутри блока, текст `tf-caption` |
| Частично | строка с известным именем и неизвестным значением остаётся, значение — прочерк `dim` |

**Интерактив.** Тап по строке раскрывает список задач этого статуса на месте,
максимум 5 названий, дальше «ещё N по тапу». Повторный тап сворачивает.

### Т2. `calendar_grid` — календарная сетка

**Зачем.** Вопрос «что в среду» сеткой читается, столбиком — нет. Ни один из
шести действующих типов не показывает расположение по датам.

**Данные и источник.**

| Поле | Тип | Обяз. | Диапазон | Пример | Откуда |
|---|---|---|---|---|---|
| `type` | string | да | `calendar_grid` | `calendar_grid` | — |
| `title` | string | нет | ≤ 40 знаков | `События · октябрь` | — |
| `month` | string | да | `ГГГГ-ММ` | `2026-10` | — |
| `first_weekday` | number | нет | 1..7 (1=пн) | `1` | константа |
| `cells` | array | да | ≤ 42 | — | события и сроки |
| `cells[].date` | string | да | `ГГГГ-ММ-ДД` | `2026-10-03` | календарь, `due_date` задач |
| `cells[].count` | number | да | ≥ 0 | `2` | счётчик событий дня |
| `cells[].tone` | string | нет | `over`/`inprog`/`review`/`free`/`future` | `over` | статус |
| `today` | string | нет | `ГГГГ-ММ-ДД` | `2026-10-14` | дата устройства |

```widget
{"type":"calendar_grid","title":"Дедлайны · октябрь","month":"2026-10","first_weekday":1,
 "today":"2026-10-14",
 "cells":[
   {"date":"2026-10-03","count":2,"tone":"done"},
   {"date":"2026-10-14","count":1,"tone":"inprog"},
   {"date":"2026-10-17","count":3,"tone":"over"}
 ]}
```

**Вид в тёмной теме.** Заголовок 15/600, слева название месяца, справа стрелки
`chevronLeft` / `chevron` 18 `sub`. Ниже подписи дней `tf-micro` 10/500 `dim`,
семь колонок. Ячейка 32×32, радиус 8, заливка — прикладной тон 18 % на
днях с событиями, пустые дни — `card2` 6 % белого. Число событий — по центру
`tf-caption` 11/500, при тоне `over` — цветом `red`. Сегодня обведён контуром
1 px `stroke` и подписан `dim`.

**Вид в светлой теме.** Геометрия та же; заливка ячеек 25 %, пустые дни 12 %
чёрного, контур сегодня `rgba(0,0,0,.09)`. Число в ячейке с тоном `over`

**Зачем.** «Когда было busiest» не читается ни столбиком, ни числом. Карта

**Состояния.** Загрузка — скелетон сетки ячеек, без градиента. Пусто — сетка

## 6. Готовность данных: где галерея упирается в инструменты

Часть типов нельзя наполнить сегодняшними ролевыми инструментами. Это не
дефект дизайна, а факт о данных — таблица нужна и разработчику, и критику.

| Тип / компоновка | Источник | Статус |
|---|---|---|
| `status_board` | `taskflow_project_tasks`, `taskflow_my_tasks` | **готов сейчас** — статус и агент есть в ответе |
| `chain` | `subtasks` через `taskflow_task` | **готов сейчас** — `done` и порядок приходят |
| `bars_list` | `taskflow_project_tasks` + `project_name` | **готов сейчас**, если группировать по проекту |
| К1 плитки с цветом | `taskflow_agents` + статусы | **готов сейчас** |
| `compare` | внешний источник цен | **нет источника** — тип рисуется, наполнять нечем (рецепты 8.4, 8.5) |
| `heatmap` | `task_events.created_at` | **нужен инструмент** — ролевых ответа с историей по дням нет |
| `calendar_grid` | события по дням | **нужен инструмент** — маршрут календаря есть, ролевого инструмента нет |
| `timeline` | `due_date` задач | **нужен инструмент** — см. ниже |
| К2 строки со статусом | `due_date` | **нужен инструмент** — см. ниже |

**Ключевая находка по срокам.** `taskflow_project_tasks` и
`taskflow_my_tasks` отдают задачи через `short()`
(`server/src/runtime/inProcessRun.ts:131`), а он возвращает только `id`,
`название`, `статус`, `работа`. **Поля `due_date` и `priority` в ролевом ответе

Следствие: рецепты, которым нужен срок (`my_overdue`, `11_3_my_overdue_ext`,
`5_5_deadlines_horizon`, `2_5_next_doctor`), сегодня рисуют дни просрочки

**Что нужно разработчику (три точечных правки, не переделка):**

1. Дополнить `short()` необязательными `due_date` и `priority` — либо отдавать

2. Добавить агрегатор по дням для `heatmap` и по датам для `calendar_grid` —

3. Ролевой инструмент календаря: маршрут `GET /api/integrations/google/calendar-events`

Пока эти три правки не сделаны, секретарь будет рисовать `timeline` и
`calendar_grid` выдуманными датами — а это хуже, чем шесть типов.

## 7. Нативный интерактив

Интерактив живёт в рендере, а не в странице внутри чата: html-блоки клиент
режет по высоте, и ничего, что требует прокрутки или внешних ресурсов, в виджет
не попадает.

### 7.1 Тап раскрывает

- Тап по строке, ступени, дню, ячейке или звену раскрывает детали **на месте**,
  под элементом, а не модальным окном и не переходом.
- Раскрывается **одна** строка одновременно: новая открытая закрывает прежнюю.
  Две открытые строки в виджете 320 pt не помещаются.
- Высота раскрытия ограничена: список внутри — максимум 5 строк по 36 pt плюс
  строка «ещё N по тапу». Внутренняя прокрутка запрещена.
- Анимация — раскрытие по высоте 180 мс, ease-out; при
  `prefers-reduced-motion` переход мгновенный.
- Тап-зона — вся строка, не только иконка: минимум 44×44 pt.
- Повторный тап по раскрытому элементу сворачивает его.
- Голосовое объявление: у строки одна метка целиком, например
  «Просрочено, Оплата карты МТС, −11 дней, раскрыть»; при раскрытии
  добавляется «свёрнуто» — иначе VoiceOver не скажет, что состояние изменилось.

### 7.2 Свайп переключает

- Свайп **горизонтальный** переключает период или страницу данных: у
  `calendar_grid` — месяц, у `heatmap` — 4 недели, у `compare` — пару
  источников, у `timeline` — диапазон.
- Порог срабатывания — 40 pt по горизонтали при скорости до 600 pt/с;
  вертикальный жест виджет не перехватывает, иначе лента чата перестаёт
  скроллиться.
- Свайп никогда не меняет высоту блока больше чем на ±8 pt: смена периода
  перерисовывает содержимое, а не добавляет строку.
- Во время свайпа применяется тот же запрет из §1.8 языка: никакого
  «веерного» перелистывания со сдвигом фона — только смена данных.
- Индикатор периода обязателен: подпись месяца или диапазона в шапке обновляется
  вместе с данными, иначе владелец не понимает, что смотрит на другой месяц.

### 7.3 Длинное сворачивается

- Предел целиком (§3.4 языка) — 5 элементов на тип, кроме `heatmap` (сетка) и
  `calendar_grid` (сетка).
- Больше предела → блок рисует первые пять и строку `«ещё 8 просрочено»`
  `tf-caption` `sub` с иконкой `chevronDown` 18 `dim`. Эта строка — тап-зона 44.
- По тапу список раскрывается до 20 строк; дальше — тот же предел и новая
  строка. Рекурсивного «показать всё» без предела не бывает: это вернуло бы
  прокрутку внутри блока.
- Блок выше 320 pt не растёт никогда.

### 7.4 Чего интерактив не делает

- Не открывает веб-страницу внутри виджета и не встраивает html.
- Не требует сети: все данные приходят в блоке.
- Не использует длинное нажатие как единственный способ что-то узнать.
- Не перехватывает вертикальный свайп — лента чата должна скроллиться.

## 8. Контракт для клиента на Mac

Формат — по требованию карты устройства виджета (раздел 7). Первые три пункта
обязательны.

### 8.1 Реестр типов

Клиент получает один `WidgetRenderer` с реестром `type → компонент`:

| `type` | Компонент | Статус |
|---|---|---|
| `status_board` | `StatusBoardView` | новый |
| `calendar_grid` | `CalendarGridView` | новый |
| `timeline` | `TimelineView` | новый |
| `ladder` | `LadderView` | новый |
| `heatmap` | `HeatmapView` | новый |
| `compare` | `CompareView` | новый |
| `chain` | `ChainView` | новый |
| `bars_list` | `BarsListView` | новый |
| `metrics` | существующий + вариант `tone`/`icon` | правка |
| `checklist` | существующий + `rows` | правка |
| `chart` | существующий + горизонтальные полосы | правка |
| `progress` | существующий + веха | правка |
| `card` | существующий + лента статуса | правка |

Парсер блока не должен знать про типы: добавление типа — одна запись в
реестре. **Новый тип обязан быть добавлен до того, как сервер начнёт его слать**
(порядок из карты устройства виджета, раздел 6.3).

### 8.2 Общие ограничения для всех восьми

| Параметр | Значение |
|---|---|
| Максимальная высота без прокрутки | 320 pt |
| Внутренняя прокрутка | запрещена; исключение — горизонтальный ряд с видимым краем следующего |
| Минимальная ширина содержимого | 320 pt (iPhone SE) |
| Размер блока | до 8 КБ; больше — текстовый запасной вариант |
| Внешние ресурсы | запрещены: ни картинок, ни шрифтов, ни сети |
| `link.url` | только `https` |
| Смена темы | на лету, без пересоздания сообщения и без смены высоты |
| `prefers-reduced-motion` | гасит раскрытие, скелетон и переходы |
| Динамический тип | высота держится до 130 %; дальше строки переносятся, обрезки нет |
| Неизвестное значение | прочерк `dim`, не ноль и не `≈` |

### 8.3 Текстовый запасной вариант

Старые клиенты новых типов не знают, и сообщение без расшифровки просто
пропадёт. Клиент собирает текст детерминированно из тех же полей — писать его
руками в рецептах нельзя.

| Тип | Текст при недоступном рендере |
|---|---|
| `status_board` | «Завершено 21, в работе 12, просрочено 7 — из 58 всего» |
| `calendar_grid` | «Октябрь: событий 2, 1, 3; всего 6» |
| `timeline` | «17.10 Счёт поставщику (просрочено 3 дня); 24.10 Релиз v2.4» |
| `ladder` | «Релиз v2.4: готовность 62%. Дизайн 100, Сервер 65, Клиент 20» |
| `heatmap` | «Активность за 12 недель: всего 312, пик 9 за день» |
| `compare` | «DNS 29 490 ₽, OZON 38 990 ₽. Дешевле в DNS на 9 500 ₽» |
| `chain` | «Поездка: билеты готовы, отель готов, виза заблокирована, 3 из 5» |
| `bars_list` | «TaskFlow: 3 из 12 просрочено; Финансы: 1 из 8» |

### 8.4 Поведение при плохих данных

| Ситуация | Что показывает клиент |
|---|---|
| Пустой `groups` / `items` / `links` | пустое состояние по §5.3 языка, не «виджет не разработан» |
| Неизвестный `tone` | `dim`, без цвета; подпись остаётся обязательной |
| `value` вне диапазона | значение в допустимом диапазоне, под ним прочерк `dim` |
| `date` не разбирается | строка с названием остаётся, дата — прочерк `dim` |
| Больше предела | первые 5 + строка «ещё N по тапу» |
| Неизвестный `type` | текстовый запасной вариант из 8.3, а не заглушка |

Последняя строка — обязательное поведение: сегодня неизвестный тип даёт
«виджет не разработан», и это молчаливая поломка на стороне пользователя.

## 10. Как отличить новый тип от старого

Правило §7 визуального языка: виджет отличается, если отличается **хотя бы
двумя** из пяти признаков. Проверка по этой таблице:

| Тип | Силуэт | Ведущий элемент | Цвет | Форма шкалы | Плотность | Отличий |
|---|---|---|---|---|---|---|
| `status_board` | строки с долями | StateMark | смысловая | полоса доли | 4–8 смысловых | 4 |
| `calendar_grid` | сетка 7×6 | число в ячейке | смысловая по дню | нет | плотная | 4 |
| `timeline` | вертикальная ось | точка на оси | смысловая | ось времени | редкая | 3 |
| `ladder` | ступени | процент готовности | смысловая | лестница | средняя | 4 |
| `heatmap` | мелкая сетка | плотность | количественная | нет | очень плотная | 4 |
| `compare` | две величины | крупное число | нейтральный | полоса разницы | редкая | 3 |
| `chain` | горизонтальная цепочка | круг с иконкой | смысловая | дискретные звенья | средняя | 3 |
| `bars_list` | двухуровневые строки | дробь «3 из 12» | смысловая | полоса в строке | 6 строк | 3 |

Три теста из языка:

1. **Тест подписи.** Закройте заголовок: `status_board` не спутать с `metrics`,
   `calendar_grid` — со столбиком, `ladder` — с горизонтальной полосой.
2. **Тест темы.** Ни один тип не схлопывается в одноцветное пятно: у
   `heatmap` пять ступеней одного тона — это пять различимых уровней, у
   остальных цвет несёт второй носитель — иконку или подпись.
3. **Тест честности.** Каждый тип читается на неравных данных: `status_board` на
   2 и 47, `ladder` на 100 и 5, `heatmap` на пике 9 и фоне 0.

## 11. Светлая и тёмная тема: что меняется, а что нет

Общее для всех типов (из языка, §6): только токены, ни одного hex; смена темы
на лету без пересоздания сообщения; ничего не пропадает.

| Что | Тёмная | Светлая | Причина |
|---|---|---|---|
| Поверхность блока | `card` `#242424` | `card` `#ffffff` | токен, не константа |
| Заливка тона | 18 %, тревожная 20 % | 25 % | на белом 15 % даёт 1.41:1 |
| Пустая ячейка сетки | 6 % белого | 12 % чёрного | та же причина |
| Линии и разделители | `stroke` 9 % белого | `stroke` 9 % чёрного | переключается сам |
| Цветной текст | см. §1.7 языка | AA для всех прикладных | в тёмной `red` и `green` дают 3.8:1 и 4.1:1 |
| «Просрочено» | `red` на плашке | `red` как текст | осознанное исключение, тревога обязана читаться цветом |

Проверка на каждый тип — восемь кадров: заполнено, пусто, загрузка, ошибка в
обеих темах, на настоящем iPhone. На сервере это проверить нечем: рендера
виджетов в веб-клиенте нет (`src/screens/ChatScreen.tsx:80`).

## 12. Пределы и честные ограничения

1. **Ни один из восьми типов не показан в живом чате.** Рендер живёт в
   нативном клиенте на Mac, исходников на этом сервере нет. Показ на телефоне —
   за Codex владельца на Mac (критерий приёмки 4 карточки).
2. **Три типа сегодня нечем наполнить**: `heatmap` и `calendar_grid` требуют
   агрегатора по датам, `timeline` и К2 — поля `due_date` в ролевом ответе.
   Таблица в разделе 6 — не формальность, а блокер наполнения.
3. **`compare` остаётся без источника.** Маршрут цен в TaskFlow отсутствует,
   рецепты 8.4 и 8.5 полагаются на внешние сервисы, которые в объём карточки
   не входят. Тип спроектирован и будет работать, когда появится источник.
4. **Горизонтальная прокрутка — исключение, а не правило.** Она разрешена внутри
   блока только ряду-карусели с видимым краем следующего элемента
   (`chain` при шести звеньях). Для всего остального действует запрет из
   памяти команды: длинный html-блок клиент режет по высоте, и виджет,
   требующий прокрутки, до владельца не дойдёт.
5. **Из восьми типов три готовы сегодня** — `status_board`, `chain`,
   `bars_list`; остальным пяти нужны данные из раздела 6. `compare`,
   `heatmap` и `calendar_grid` без источника — пустые блоки, а секретарь по
   §5.3 языка не должен отправлять пустой виджет вовсе.
6. **Иконки ограничены словарём проекта.** Иконок `wallet`, `ban`, `flame`,
   `droplet` в `LUCIDE_ICONS` нет — проверено. Для денег взята `tag`, для сбоя
   `x`. Если владелец решит, что нужны свои, они добавляются в словарь один
   раз, а не в каждом виджете.
