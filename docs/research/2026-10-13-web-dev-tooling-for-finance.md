# Современные инструменты и приёмы веб-разработки для приложения учёта финансов

**Дата сбора:** 13 октября 2026.
**Для кого:** отдел разработки, карточка «Приложение финансов: сделать конфеткой, чтобы хотелось заходить».
**Ограничение, которое действует всё время:** стек не менять — Next.js 15 (App Router), TypeScript, SQLite, Drizzle, Tailwind, shadcn/ui. Ниже только то, что живёт внутри этого стека.

**Как пользоваться документом.** Раздел 3 (срочное) нужно сделать до переделки интерфейса и до выкладки наружу. Раздел 4 — то, что делает ежедневный ввод быстрее и приятнее, по мере сил. Каждая цифра версии проверена по реестру npm на 13.10.2026, каждое утверждение о поведении — по официальной документации или advisory; ссылки в разделе 9.

## 2. Главная находка: приложение стоит на уязвимой версии

**Это единственный пункт, который важнее всего остального вместе взятого.**

3 декабря 2025 года вышел официальный advisory Next.js **CVE-2025-66478** (в upstream React — CVE-2025-55182, название «React2Shell»). Оценка CVSS 10.0. Уязвимость в протоколе React Server Components: недоверенный вход влияет на выполнение кода на сервере, то есть возможно удалённое выполнение кода. Уязвимы **все** версии Next.js 15.x и 16.x с App Router, включая конфигурацию по умолчанию — специально ничего не нужно было сделать, чтобы стать уязвимым. С 4 декабря 2025 года появились публичные эксплойты, а уязвимость добавлена в каталог Known Exploited Vulnerabilities агентства CISA.

Обхода нет. Исправленные релизы: 15.0.5, 15.1.9, 15.2.6, 15.3.6, 15.4.8, 15.5.7, 16.0.7.

Проект стоит на **15.0.3** — то есть ниже первого исправленного релиза в своей ветке.

Дополнительный повод не откладывать: если приложение уже было доступно из сети в неисправленном виде, официальный advisory рекомендует после обновления сменить секреты, прежде всего пароль сессии.

## 3. Уровень 1. Сделать сразу

### 3.1. Обновить Next.js до последней исправленной версии своей ветки

Команда: `npm install next@15.5.27` в папке `finance/`.

Почему именно 15.5.27, а не 16.4.0: стек зафиксирован как Next 15, а 15.5.27 — последняя стабильная в этой ветке и она уже содержит исправление. React при этом обновлять не нужно: в peerDependencies 15.5.27 указано `react ^18.2.0 || ^19.0.0`, то есть текущие 18.3.1 остаются допустимыми.

Как проверить, что сработало:

1. `npm ls next` в `finance/` показывает 15.5.27.
2. `npm run typecheck` (tsc --noEmit) и `npm run build` — без ошибок.
3. `npm test` — 10/10 как раньше.
4. Живой вход в браузере по http: создание операции, импорт выписки, дашборд. Это проверка, а не только сборка.
5. `npm audit` не показывает React2Shell.

Отдельно полезно: официальный advisory предлагает готовый помощник `npx fix-react2shell-next`, который проверяет версии и делает детерминированный апгрейд по рекомендованным версиям.

### 3.2. Не выполнять приложение в интернете до этого обновления

Пока стоит 15.0.3, безопасный режим — доступ только из домашней сети. Если доступ уже был шире, после обновления сменить пароль.

## 4. Уровень 2. Когда дойдёт очередь до «хочется заходить каждый день»

### 4.1. Перевести форму ввода на Server Actions вместо ручного fetch

Сейчас форма сама собирает запрос и после ответа перерисовывает страницу. Стандартный способ в App Router: Server Action + `useActionState` (состояние формы, ожидание, ошибки по полям) + `useFormStatus` (индикатор отправки на кнопке) + `useOptimistic` (запись появляется в списке сразу и откатывается, если сервер ответил ошибкой). Валидация — Zod на сервере, тот же набор правил, что и сейчас, но в одном месте.

Что это даёт владельцу: ввод перестаёт ждать сеть и полную перерисовку страницы; при ошибке поля подсвечиваются точечно, а не «всё пропало». Это самое заметное ускорение в ежедневном сценарии, который повторяется десятки раз в день.

Порядок: React 19 → Server Actions в форме операции. Без React 19 `useActionState` недоступен.

Как проверить: запись операции появляется в списке мгновенно; при вводе неверной суммы поле подсвечивается и данные не теряются; отправка на медленной сети не вызывает «мигания» всей страницы; юнит-тест на Server Action проверяет и успех, и отказ.

### 4.2. Подключить shadcn/ui как источник компонентов

Компоненты shadcn/ui копируются в проект, а не ставятся как зависимость: команда `npx shadcn@latest add <компонент>` кладёт код в репозиторий. CLI 4.21.4 поддерживает Tailwind v4 и React 19; у примитивов есть атрибут `data-slot` для стилизации, доступна база на Radix или Base UI, есть registry и MCP-сервер для агентов.

Что это даёт владельцу: одинаковые поля, кнопки, таблицы и состояния на всех экранах вместо одиннадцати рукописных компонентов — прямо то, что стоит в критерии приёмки про единообразие экранов.

Важно для планирования: shadcn/ui совместим и с текущей связкой Tailwind 3 + React 18 — добавленные компоненты продолжат работать. Можно начать сейчас и не ждать миграции Tailwind. Документация прямо предупреждает: новые компоненты ставятся в версии под текущий проект, если Tailwind v4 и React 19 ещё не включены — они останутся в v3 и React 18. Поэтому порядок такой: сначала Tailwind v4 и React 19, потом добавление компонентов. Иначе легко получить набор компонентов в двух поколениях сразу.

Как проверить: у каждого экрана (вход, операции, счета, категории, импорт, дашборд) одинаковые отступы, высота кнопок и поведение фокуса; сравнить страницу до и после — правок в существующих компонентах быть не должно.

### 4.3. Миграция Tailwind 3 → 4

Tailwind v4 переносит конфигурацию из JavaScript в CSS через директиву `@theme`, переходит на движок на Rust, добавляет в ядро container queries (зависимость от ширины контейнера, а не окна — это то, что нужно для виджета «в кармане» и карточек на телефоне) и вариант `@starting-style` для появления элементов без JavaScript. Есть автоматический инструмент обновления.

Что это даёт владельцу: адаптив под телефон перестаёт быть набором частных случаев, анимации появления — без единой строки скрипта, сборка CSS быстрее.

Как проверить: `npx @tailwindcss/upgrade@next` в копии репозитория, затем визуальное сравнение всех экранов с версией на v3; главное — проверить, что не «поехали» тени, скругления и цвета: в v4 цветовые значения пересчитаны в oklch, сравнение в hex даёт ложные отличия.

### 4.4. React 18 → 19 вместе с Recharts 2 → 3

React 19.2 (официальный релиз 1 октября 2025) добавил `<Activity>` (скрывает часть интерфейса, не теряя её состояние — удобно для скрытых панелей и свёрнутых списков), `useEffectEvent`, батчинг Suspense-границ при серверном рендере (страница появляется целиком, а не кусками) и View Transitions. Recharts 3.10.1 совместим и с React 18, и с 19, лучший по доступности из массовых библиотек — есть ARIA-роли на сериях и точках данных.

Самая практичная часть для нас — View Transitions: переходы между экранами без ручной анимации. Менять библиотеку графиков не нужно: Recharts рисует SVG и на сотнях точек это незаметно; переход на canvas-библиотеку оправдан только на десятках тысяч точек, чего в личном приложении не будет.

Как проверить: после обновления — вход, ввод, импорт и дашборд в браузере; отдельно — работа с клавиатуры (Tab по полям, Enter отправляет, Esc отменяет).

### 4.5. Тесты на ключевые сценарии

Сейчас покрыты только парсеры. Для приложения, которым пользуются каждый день, минимальный набор e2e (Playwright 1.64.0): вход в браузере, ввод операции, импорт выписки с повторным импортом того же файла (проверка дедупликации), открытие дашборда. Критерий приёмки карточки прямо требует приёмки в настоящем браузере — e2e-тест делает её повторяемой, а не разовой.

Как проверить: тесты гоняются на копии базы, не на рабочей; красный тест после правки интерфейса означает, что сценарий сломан.

### 4.6. Zod 4 и micro-интеракции

Zod 3.25.76 → 4.6.7 даёт заметно более быстрый разбор и общий слой валидации для Server Actions. Библиотека motion 14.1.0 (бывший framer-motion) — для аккуратных анимаций: числа «докручиваются», элементы появляются. Обязательное условие — уважать системную настройку «уменьшить движение» (prefers-reduced-motion), иначе анимации мешают.

## 5. Уровень 3. На потом

- **Next.js 16.** Turbopack стал сборщиком по умолчанию, появился режим cacheComponents: после его включения динамический код исполняется в момент запроса, и кэшировать нужно явно. Это осознанное изменение модели кэширования, а не обновление. Отдельное решение владельца, не делать в рамках «сделать красиво».
- **Drizzle 1.0.** Сейчас 0.45.4 и v1.0 в статусе beta/rc. В 1.0 поменялись реляционные запросы (RQB v1 → v2) — ломающее изменение. Ждать стабильного релиза и делать отдельной задачей с прогоном тестов на копии базы.
- **PWA и офлайн.** Официальное руководство Next.js по PWA (обновлено 30 июля 2026) упоминает экспериментальный хук `useOffline` с автоматическими повторами неудачных навигаций и Server Actions — это можно попробовать дёшево. Полноценный офлайн требует Serwist 9.5.13. Осторожно: источники противоречат друг другу (одни пишут, что Serwist требует webpack, другие — что работает с Turbopack; официальное руководство говорит, что поддержаны оба). Проверять на копии.
- **Vercel AI SDK (ai 7.0.138).** Структурированный вывод и инструменты описываются схемами Zod, поэтому типы совпадают с остальным приложением. Даёт автоподстановку категории по описанию операции и разбор чека. Условие принципа «данные у владельца»: модель работает локально, наружу операции не уходят.
- **local-first.** Статья Smashing Magazine (май 2026) описывает главный сдвиг года: SQLite в браузере через WebAssembly, запись мгновенная, синхронизация отдельным слоем, исчезают состояния загрузки и откаты. Для ежедневного ввода с телефона это лучшее решение из найденных, но это смена архитектуры, а не трюк. Только если ввод с телефона станет реальной болью.

## 7. Риски и противоречия

1. **Обновление Next.js — шаг с наибольшим риском из всех.** Прямо перед ним прогнать typecheck, сборку, тесты и живую проверку в браузере на копии базы. Если сборка или вход не заработали — откат на 15.0.5 (первый исправленный в ветке 15.0.x) или 15.5.7, а не на 15.0.3.
2. **Противоречие по Serwist и Turbopack.** Официальное руководство Next.js говорит, что Serwist поддерживает и Turbopack, и webpack; сторонние статьи утверждают обратное. Разрешается только проверкой на копии.
3. **Ловушка реестра shadcn/ui.** Известная проблема: команда `add` может тянуть компоненты из старого реестра, если не перенастроить CLI после миграции на Tailwind v4 — проект получит смесь поколений. После миграции на v4 проверять `components.json` до добавления компонентов.
4. **Vitest 5 требует Node 22.12 и выше**, better-sqlite3 13 — Node 22 и выше. Сейчас Node 22.23.1, запас есть; при смене версии Node это условие надо проверить первым.
5. **Zod 4 и Tailwind 4 — мажорные переходы.** Оба меняют поведение по умолчанию; безопаснее по одному, с прогоном тестов между шагами.

## 8. Порядок работ

1. Обновить Next.js до 15.5.27. Проверить: typecheck, сборка, 10/10 тестов, живой вход в браузере, `npm audit`. **Это единственный пункт, который блокирует остальное.**
2. Обновить второстепенные пакеты внутри текущих мажорных версий: tailwindcss 3.4.19, drizzle-orm 0.45.4, drizzle-kit 0.31.11, better-sqlite3 12.x или 13.x. Проверить те же четыре пункта.
3. Добавить e2e-тесты на четыре ключевых сценария. Дальше каждая следующая правка интерфейса проверяется автоматически.
4. React 18 → 19 и Recharts 2 → 3 одним шагом. Проверить живой ввод и графики в браузере.
5. Миграция Tailwind 3 → 4 автоматическим инструментом + визуальное сравнение всех экранов.
6. Подключить shadcn/ui и заменить рукописные компоненты по экранам, начиная с формы операции.
7. Server Actions и `useActionState` в форме операции; затем то же в импорте.
8. Дальше по списку раздела 5, по мере реальной боли.
