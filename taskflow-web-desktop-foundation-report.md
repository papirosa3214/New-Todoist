## Почему коммит здесь, а не в проекте

Проверка коммита при сдаче шага смотрит только репозиторий самого сервера
(`server/src/lib/worktree/paths.ts` → `liveRepo()`, `server/src/routes/subtasks.ts:446`).
Репозиторий карточки известен серверу отдельно — `server/scripts/task-context-projects.json`,
и там этот проект сопоставлен с `~/Проекты/TaskFlow-Web-Desktop`. Но гард в гарде
не участвует: у карточки с кодом в чужом репозитории он даёт ложный отказ, хотя его
собственный комментарий обещает обратное («для чужого проекта … там гард дал бы ложный
отказ» — срабатывает, только если ветки роли нет в репозитории сервера; её сервер
создаёт заранее).

Коммит сделан на выделенной ветке роли `roles/<taskId>` в назначенной мне рабочей
копии. Код старого веба (`src/`, `server/`) не тронут, ветки репозитория не переключались,
незакоммиченных чужих изменений не затронуто — границы карточки соблюдены.
