# Рабочая копия роли: восстановление и проверка

Ситуация (проверено 22.10.2026, карточка c14e6335): рабочая копия роли —
git-worktree в `/home/maksim/.local/state/taskflow-runs/worktrees/<id карточки>`.
Сторож уборки копий удалил её между ходами. Инструменты файлов и bash при этом
падают с «Working directory does not exist», а чтение вне копии запрещено.

## Порядок

1. **Проверить, что папка действительно исчезла.** Через bash не выйдет — cwd
   отсутствует. Создай каталог через инструмент записи (Write в путь внутри
   копии) — это возвращает bash в рабочий режим; затем удали пробный файл.
2. **Пересоздать worktree из канонического репозитория** (в нём лежит и main,
   и все ветки ролей):
   ```
   cd /home/maksim/Проекты/New-Todoist
   git worktree add -b roles/<id карточки> \
     /home/maksim/.local/state/taskflow-runs/worktrees/<id карточки> main
   ```
   Если ветка роли уже была — создай заново (`-b` перезапишет) только если её
   коммитов нет ни в одном ref; иначе добавь worktree на существующую ветку
   (`git worktree add <путь> roles/<id>`).
3. **Подключить зависимости.** `node_modules` в копии нет (они в .gitignore).
   Симлинками на канонический репозиторий:
   ```
   ln -s /home/maksim/Проекты/New-Todoist/node_modules node_modules
   ln -s /home/maksim/Проекты/New-Todoist/server/node_modules server/node_modules
   ```
   Симлинки не коммитить.
4. **Проверить, что дерево живое**: `cd server && npx tsc --noEmit` и
   `npx vitest run <целевые тесты>`; для веба — `npx vitest run` по своим
   тестам и `npx vite build`.
5. **Перед `git add`** — `git status`: симлинки node_modules и пробные файлы
   в коммит не идут.

## Грабли

- Уборка копий срабатывает не только на «зависшей» карточке: если карточка
  уже слита (`tasks.merged_at` стоит), сторож `sweepMergedWorkspaces` сносит
  копию и ветку роли при ближайшем проходе обслуживания — то есть повторный
  ход по уже слитой карточке может потерять копию через несколько минут
  после восстановления. Проверяй `git branch --list "roles/<id>"` перед
  работой: если ветки нет — создай её заново от `main` и закоммити правку
  сразу, иначе уборка придёт снова.
- Пока копия пуста и ветки нет, любой вызов bash падает с «Working directory
  does not exist». Лечится созданием каталога через инструмент записи
  (Write) с любым файлом внутри — bash оживает, дальше удали пробный файл.
- `npx tsc` в одноразовой проверке другого worktree может подхватить пакет
  `tsc` вместо TypeScript («This is not the tsc command you are looking for»).
  Тогда добавь симлинк корневого `node_modules` и повтори.
- Полный прогон сервера даёт чужие падения (28 файлов, 71 тест на main,
  22.10.2026). Чтобы отличить свои регрессии, сними базовый прогон на чистом
  main в отдельном worktree и сравни списки падающих файлов.
- Длинные прогоны (>60 с) — только в фоне: `nohup bash -c "…" > /tmp/x.log 2>&1 &`,
  проверка по хвосту лога короткими вызовами.
