# Массивы в аргументах инструментов TaskFlow доходят искажёнными

## Признак

Сервер отвечает отказом, хотя с твоей стороны всё по схеме:

```
arguments.artifact.evidence: ожидается массив; получен объект {"item":[{...}]}.
arguments.items: ожидается массив; получен объект {"item":{...}}.
arguments.base_revision: ожидается число; получен строка "0".
```

Массив приезжает завёрнутым в ключ `item`; пустой массив — пустой строкой; массив из
одного элемента — самим элементом. Числа приезжают строками. Это делает MCP-обёртка на
пути к серверу, а не серверная валидация: правкой данных это не лечится, и повторять
тот же вызов бессмысленно.

## Что делать

1. **Не повторять тот же вызов** — отказ будет тем же. Сначала понять, где именно
   искажение: названное в сообщении поле (`arguments.<путь>`).

2. **Массив в свободном объекте (`payload`, `arguments`) доходит как есть.** Схема
   `payload: {}` («любое значение») не подсказывает обёртке форму — и вложенные туда
   массивы остаются массивами. Проверено на сдаче шага с контрактом `fix_pack`:
   `payload.change_refs`, `payload.evidence`, `payload.known_limitations` дошли
   нетронутыми.

3. **Массив, объявленный в схеме (items, evidence), не проходит.** Способы:

   - **Перенести данные внутрь `payload`** и оставить в `artifact.evidence` то, что
     схема примет. Для `fix_pack` поля payload обязательны: `change_refs`,
     `root_cause_summary`, `build_id`, `test_report`, `deployment_notes`,
     `known_limitations`; ссылки на коммиты и протоколы проверок кладутся в
     `payload.evidence`.
   - **Убрать поле совсем**, если оно необязательное: у `artifact` обязательны только
     `summary`, `payload`, `report_markdown`.

4. **`taskflow_work_plan` (чек-лист хода) через обёртку не пишется** — `items`
   объявлен массивом в схеме. Сдаче это не мешает: сервер закрывает последний пункт
   чек-листа сам после подтверждённой сдачи. План тогда ведётся в заметках хода
   (taskflow_doc_write) или в своей папке роли, а в отчёте честно отмечается, что
   чек-лист инструмента не обновлялся из-за дефекта транспорта.

5. **Прямой вызов REST-API** — обход для коллеги, у кого есть свой токен: сервер
   TaskFlow слушает `http://localhost:3001`, учётка роли — в
   `/home/maksim/taskflow/roles/<роль>/scripts/`. У роли builder своего токена в
   окружении нет (21.10.2026), поэтому этот путь ему недоступен.

## Проверка

Отказ с текстом «ожидается массив; получен объект {"item": …}» — это транспорт, а не
схема: твой вызов был правильный. Отказ с любым другим текстом («поле обязательно»,
«нет такого значения») — это уже данные, их надо чинить.
