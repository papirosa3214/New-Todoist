# Счётчик потерь тревог: журнал ~/.claude/alert-undelivered.log

## Признаки

- В сводке «у отправителей НЕ УШЛО N», хотя сеть и n8n живы, а тревоги Максим видел.
- Или наоборот: «потерь нет», а в те же часы сторож молчал, а канал лежал.
- Или в журнале есть строки с непустым `error` и `reserve: "дошёл"`.

## Причина (договор поля `reserve`)

Поле `reserve` в журнале несёт ТРИ смысла, и раньше два из них были одним значением:

| Значение | Что означает | Потеря? |
|---|---|---|
| `дошёл (через n8n)` | дошла сама тревога (основной канал) | нет |
| `дошёл (запасной дорогой)` | дошла сама тревога, уведена мимо n8n (17.10.2026) | нет |
| `дошёл` / `не дошёл` / `промолчал` | судьба ДОКЛАДА о сбое из `report_failure()` | **да** |
| `своя дорога` | `journal_loss()` — тревога потеряна, отправитель доложил сам | да |
| пусто / нет поля | неизвестно — считать потерей | да |

Правило в `delivery_watch()` (autonomy-report.py), простое в применении:

```python
def _доставлена(r):            # тревога дошла?
    if not str(r.get("error") or "").strip():
        return True             # строка успешной отправки
    return str(r.get("reserve") or "").startswith("дошёл (")
```

Пустой `error` — доставка состоялась даже если первая попытка сорвалась (таких строк
в журнале единицы). Непустой `error` + `дошёл (`…`)` — дошла со второй попытки или
запасной дорогой. Непустой `error` + голое `дошёл` — дошёл только доклад.

## Грабли

- **Различать по источнику нельзя.** `infra-vpn-watch` всегда зовёт `send(..., reserve_full=True)`,
  а `traycer-link-watch` и `vnc-desktop-watch` в ветке «… ослеп» (сбой самого сторожа) —
  `send()` БЕЗ `reserve_full`, то есть доклад. Один и тот же сторож даёт оба смысла.
  Единственный разделитель — сама пометка в поле `reserve`.
- **Одно значение на два смысла — источник половины ложных «НЕ УШЛО»** (16.10 и 17.10.2026).
  Новый смысл всегда получает НОВОЕ значение с прочерком в скобках, а не переиспользует
  существующее.
- **Счётчик «без предупреждения запасной дорогой» смотрит на `startswith("не дошёл")`
  или на пустое значение.** «промолчал» — заглушка по частоте (доклад уже уходил
  15 минут назад), её надо считать отдельной строкой, а не молча ронять.
- **Журнал принадлежит maksim, агентский сеанс (tfrole) его не пишет.** Правку старых
  строк готовишь скриптом с `--dry-run`, проверяешь на копии и отдаёшь одну команду
  владельцу. Код в ~/infra-ops сеанс правит и коммитит сам (там есть ACL на tfrole).
- **Проверяй настоящей функцией на живом журнале, а не чтением кода.** Импорт файла с
  дефисом в имени — через `importlib.util.spec_from_file_location`; окно подменяешь
  через `ar.UNDELIVERED` и `ar.RELAY_JOURNAL`.

## Как чинить (порядок)

1. Найти коллизию: `grep -n reserve ~/infra-ops/alert_send.py` и `grep -n "дошёл\|не дошёл" ~/infra-ops/autonomy-report.py`.
2. Новый смысл → новое значение в том месте, где он пишется (обычно `alert_send.py`).
3. Правило чтения — в `delivery_watch()`, с правилом на каждое значение и пустое.
4. Старые строки журнала: переименовать только те, где доставку можно доказать по коду
   отправителя (один вызов `send()`, всегда `reserve_full=True`), с резервной копией.
5. Запустить настоящую функцию на живом журнале: окно сбоя, окно 36 ч, вся история.

## Как проверить

- `python3 -m py_compile` обоих файлов.
- Синтетика на живой функции с подменёнными каналами (n8n → мёртвый порт,
  `send_direct`/`report_failure` подменены, журнал в /tmp): тревога уведена и дошла →
  «потерь нет»; уведена и не дошла → потеря; дошёл только доклад → потеря.
- Окно сбоя: в сводке только настоящие потери, доставленные тревоги сторожей с
  `reserve_full` не мелькают.
- Текущие 36 ч: «потерь за 36 ч нет (доставлено N)».
- Вся история: потери + доставленные = число строк журнала.
