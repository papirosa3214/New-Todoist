# Списки роли: проверять содержимое, а не «массив ли»

Прецедент (26.10.2026, карточка e11eae7a): эндпоинт панели отдавал 200 и пустой список навыков,
а явный вызов настоящего навыка отклонялся как «не найден» — функция читала составной слой
инструкций без регистрации блоков, падала в TypeError, а ошибка глоталась `.catch(() => [])`
в двух местах. Дефект проявлялся только у роли без предыдущего хода.

## Порядок проверки

1. Искать `.catch(() => [])` и пустые fallback'и вокруг списков: проглоченная ошибка неотличима от «ничего не нашлось».
2. Гонять сценарий на «свежей» роли (без предыдущего хода) — состояние после первого хода маскирует дефект.
3. Проверять успех на настоящем имени, а не только отказ на неизвестном.
4. Искать «функция есть, вызовов нет» (grep по имени): функция сброса, которую никто не зовёт, — и сброс не работает.

## Форма отчёта

Дефект писать с воспроизведением: запрос → ожидаемое → фактическое → где в коде.
