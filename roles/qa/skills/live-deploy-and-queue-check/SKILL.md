# Живая проверка выкладки и очередей TaskFlow (.110)

## Зачем

Карточка может быть «зелёной по коду» и при этом ничего не менять в живом
сервере: правка лежит в main, а живой процесс работает на старой сборке.

## Порядок (правды здесь, а не в main)

1. **Что выложено.** `cat ~/.local/state/taskflow-deploy/deployed` — SHA последней
   выкладки; сравнить с `git -C ~/Проекты/New-Todoist rev-parse main`.
2. **Есть ли правка в выложенной сборке.** Искать след в `server/dist`, а не в
   `server/src`: например `grep -c "queue_duplicates_collapsed"
   server/dist/runtime/roleRunQueue.js`. Нет следа — правки в живом сервере нет.
3. **Живой сервер отвечает.** `curl -s http://127.0.0.1:3001/api/health` (API
   слушает 3001; веб на 5180 — https с самоподписанным сертификатом, `curl -k`).
   200 на старой сборке — не доказательство, что правка выложена.
4. **Журнал сторожа выкладки.** `tail -40 ~/.local/state/taskflow-deploy/deploy.log`.
   Два вида строк: «занято: попыток N, в очереди M — жду» (живые ходы ролей и
   свежие доставки чата — считает сам QA) и «в server/ незакоммиченные правки —
   жду» (в рабочем дереве main висят чужие правки; затор снимает автор правок
   или ответственный за интеграцию).
5. **Очереди на живых данных.** Снимок живой базы (`sqlite3 LIVE_DB ".backup
   'copy.db'"` — только чтение) и счётчики: `role_run_jobs` по статусам,
   `chat_message_queue` по статусам и возрасту. Признак лавины — задания в
   `queued`/`retry_wait`; если их ноль, лавина уже схлопнута.

## Что проверять функционально (на копии)

- Свёртка дублей: восстановить лавину из живых строк на копии (вернуть
  историческим заданиям статус `queued`) и прогнать функцию из main через
  `tsx` с `DB_PATH=копия`. Группы считать по правилам самого кода
  (`roleRunJobGroup`), иначе «дубли» в отчёте будут ложными.
- Срок жизни доставки: на копии живых данных доставки старше порога у роли без
  живой попытки должны закрыться, а у роли с живой попыткой — остаться.

## Грабли

- Импорт `server/src/runtime/chatQueueRecovery.ts` обычным `tsx` падает: тянет
  `routes/chats` → пакет pi-coding-agent без `exports`. Рабочий путь — vitest с
  собственным `setup.ts` (DB_PATH на копию) и импортом по абсолютному пути.
- Роль работает под отдельным пользователем: `server/scripts/role-routing.yaml`
  может быть нечитаем → два тестовых файла не стартуют. Это ограничение
  окружения, а не дефект продукта.
- Пока идёт ход роли, сторож выкладки видит «занято» (живая попытка). Выкладка
  не может наступить внутри хода роли — структурное ограничение, не поломка.
