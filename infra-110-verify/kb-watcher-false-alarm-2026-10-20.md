## Признаки

- Сводка `autonomy-110` пишет: `база знаний: ВИДНО НЕ ВСЁ — 1539 документов из 1540`.
- При этом поиск и выдача уроков работают, в RAGFlow всё на месте.
- Числа расходятся на 1–2 документа и «прыгают» от дня к дню.

## Причина

`kb_reachable_watch()` в `infra-ops/autonomy-report.py` сравнивала два НЕЗАВИСИМЫХ
замера, сделанных в разное время:

1. `total` — сумма `total` из `/api/v1/datasets/<id>/documents?page_size=1` по трём датасетам;
2. `len(list_documents())` — постраничный обход тех же датасетов (page_size=200).

Между замерами (10–20 секунд) база меняется: `kb_add.py` перезаписывает урок, и на
один замер документов приходится больше, чем на другой. Расхождение в один документ —
это движение базы, а не «обрезка выборки», но проверка читала его как поломку.

Второй дефект, тот же код: проба печатала `print(total, len(docs), len(t))`, а разбор
делал `int(out[0]), int(out[1]), int(out[2])`. Любой лишний или пропавший вывод ронял
разбор на `IndexError` — владелец видел `база знаний: не проверить (list index out of
range)` вместо отказа базы. Наблюдалось 28.09, 03.10 и 09.10.2026.

## Как проверить, что база цела (без токена RAGFlow)

Токен лежит в `~/kb/.env` с правами 600, агентская сессия его не читает. Но счётчики
можно снять напрямую из MySQL — RAGFlow v0.25.5, контейнер `docker-mysql-1`:

```
docker exec docker-mysql-1 mysql -uroot -pinfini_rag_flow -N -D rag_flow -e "
SELECT kb_id, run, COUNT(*) FROM document
WHERE kb_id IN ('c9089956901f11f1be69a9ef96f0a9d6',   -- База знаний — уроки
                'aad90ec0901f11f1be69a9ef96f0a9d6',   -- Память — заметки
                'd35865de983b11f18d6bd74745db279b')   -- Ресёрч и документация
GROUP BY kb_id, run;"
```

`run`: 0 UNSTART, 1 RUNNING, 2 CANCEL, 3 DONE, 4 FAIL. Документы в `run=4` не находятся
поиском — они есть в списке, но бесполезны. Таблица метаданных — `document`,
колонка датасета — `kb_id` (НЕ `dataset_id`).

## Как чинить

Считать «сколько всего» ДО и ПОСЛЕ обхода списка; беда — когда список короче ОБОИХ
замеров. Расхождение замеров означает, что база двигалась под проверкой.

```python
before = count(cfg)
docs = k.list_documents()
after = count(cfg)
...
if seen < min(before, after):   # настоящая обрезка
    ...тревога...
```

Плюс: проба печатает `KEY=VALUE`, разбор идёт по словарю, сбой называет последнюю
строку stderr. Содержимое проверять по одному документу ИЗ КАЖДОГО датасета, а не по
одному первому — иначе один битый документ превращает проверку в ложную тревогу
(в базе есть такой: `taskflow__typesafe-jev-docs-full-2026-10-16.md`, `run=4` с 16.10).
