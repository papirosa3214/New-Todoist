# Правка ~/infra-ops, которую применяет владелец

## Признаки

- Утренняя сводка `autonomy-110` пишет одно и то же «у отправителей НЕ УШЛО N» или
  «сорвалось у посредника: N» несколько дней подряд, а по факту уведомления доходят.
- Карточка на диагностику заводится каждое утро из тикета `inbox/…/_diagnostic/…`.
- `git status` в `/home/maksim/infra-ops` показывает, что нужный файл НЕ изменён:
  прошлая правка лежала патчем и не была выполнена.

## Что делать

1. **Сначала проверить, не повтор ли это.** Сравнить дату правки файла с датой прошлой
   карточки в базе знаний и посмотреть `git status` по конкретному файлу. Повторный
   разбор — это не новая диагностика, а проверка «применена ли прошлая правка».
2. **Отличить счётчик от потерь.** Журнал `~/.claude/alert-undelivered.log` пишется на
   КАЖДУЮ отправку, включая успешную (`error=""`, `reserve="дошёл (через n8n)"`).
   Потеря — это запись, где отправка сорвалась: непустая причина И тревога не ушла
   второй попыткой (журнал хранит причину первой), либо `reserve == "не дошёл"`.
   Подтвердить по журналу посредника `~/.claude/alerts/relay-undelivered.log`: там
   только сбои (`lost`) и «дошло с повтора» (`recovered`).
3. **Править функцию, а не текст тревоги.** Меняется счётчик в проверке; маркер
   «НЕ УШЛО» остаётся только для настоящих потерь.
4. **Готовить передачу, а не ждать.** Правка `~/infra-ops` недоступна агенту: сеанс
   работает от `tfrole` (uid 997), в группу `maksim` не входит, `sudo` без пароля даёт
   только служебные команды Mint. Проверять это ДО подготовки, а не после.
5. **Передать одну команду.** Скрипт в `/var/tmp` (не `/tmp` — его чистят), который сам
   делает резервную копию, `git apply --check`, `git apply`, `py_compile` и печатает
   результат проверки. Рядом — патч и README с проверками.

## Как проверить до передачи

- `git apply --check` патча на живом файле — применяется чисто.
- `python3 -m py_compile` копии с патчем.
- Прогон скрипта на копии репозитория: патч применён, откат `git checkout --` чистый.
- Живые журналы через патченную копию: было «НЕ УШЛО N» → стало «потерь за 36 ч нет —
  тревог отправлено: N».
- Синтетика на временном HOME: успешные отправки → тревоги нет; настоящая потеря →
  тревога поднята; сбой первой попытки при успешной второй → тревоги нет; `lost` у
  посредника → тревога поднята.
- Чужие незакоммиченные правки в `~/infra-ops` не трогать, `reset`/`stash` не делать.

## Грабли

- Модуль из `~/infra-ops` при загрузке под чужим HOME разворачивает `~` в `/home/tfrole`
  и молча читает несуществующий журнал: счётчик показывает ноль. Живые данные брать по
  абсолютному пути или с `HOME=/home/maksim`.
- Навык не запишется в `~/taskflow/roles/infra_engineer/skills/` — папка закрыта. Класть
  в рабочее дерево задачи и говорить владельцу, куда скопировать.
- Закрывать карточку, пока правка не применена, не стоит: на следующее утро тревога
  вернётся и разбор начнётся заново.
