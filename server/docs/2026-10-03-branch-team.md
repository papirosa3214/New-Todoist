# Одна команда для ветки задач

## Контракт

Участник — существующая роль с устойчивым `role_<key>`, а не отдельный рабочий слот. API общего плана отдаёт `branch_team`: одна запись на роль, адреса её поручений, номера карточек, состояние. `nodes/edges` остаются точным графом исполнения для подзадач, артефактов, редактирования и доработки. После подключения Критика его этапы показываются одной аватаркой этой роли. Согласование допускает до шести уникальных ролей, включая финального Критика; седьмая требует пересмотра назначений, а не скрывается.

Для автоматического предложения существующей дочерней карточки используется одно поручение вместо повторного полного `product_feature`. Назначение по формулировке заголовка: проверки → QA, исследования → Исследователь, стандарты/описания → Аналитик, внедрение → Разработчик; неоднозначное назначение остаётся доступным владельцу для изменения до согласования. Явные ручные планы не сокращаются.

Сдача новых поручений требует `card_result` с `summary`, `evidence`, `document_refs`. Подготовка результата дочерней карточки, проверка, зависимости, слоты исполнения и возвраты не заменены группировкой интерфейса.

## Номера

`branch_cards.tab_number` — общий порядок закладок: корень 0, дочерние по уровням, новые первыми, равные даты упорядочены по ID. Нативный клиент использует этот же словарь для закладок и номеров на аватарках. Номера не зависят от последовательности открытия карточек.

## Текущий черновик

`rebuild-branch-team.ts <root-id>` показывает изменения; `--apply` создаёт новые revisions только для нетронутых импортированных листовых шаблонов (`version=1`, `origin=linear_import`, без рабочих слотов). Старые revisions сохраняются, ручные изменения и начатая работа исключаются. Семь повторных шаблонов заменены конкретными поручениями: 11 карточек, 12 рабочих слотов, пять рабочих ролей + финальный Критик. Корневой Архитектор и существующая передача Исследователь → Аналитик сохранены.
