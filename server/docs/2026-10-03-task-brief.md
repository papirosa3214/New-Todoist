# Единый формат постановки задач — 03.10.2026

## Проблема и изменение

Инструмент `taskflow_create_task` принимал одно название без описания. Агент не получал общего стандарта постановки. Теперь общий серверный контракт сообщает формат: «Работа», «Результат», «Критерии приёмки», «Границы». Для простой задачи — короткий текст, без придуманных сроков и ограничений.

Один источник: `server/shared/task-brief.json`. Контракт добавляется к инструкции MCP при подключении, описанию инструмента и общей подготовке задач. Внутренний SDK-инструмент получает его через `composeLayer`; ручной override остаётся, но не скрывает общий контракт.

## Две структуры работы

Дочерние карточки описывают части работы со своим результатом; возможны дети любого уровня. Не нужно дробить механические действия на карточки.

**Узлы командного плана обязательны.** При подготовке и запуске команды они создаются как subtasks и несут исполнителя, состояние, прогресс, результат и передачу артефактов. Эта доработка не отключает их генерацию и не меняет жизненный цикл. Инструкция не расписывать подшаги относится к ручному чеклисту при первичной постановке, а не к узлам плана. Подготовленный `preparation=role_plan` и `card.subtasks` передаются без удаления.

## Инструмент

Внешний MCP принимает `brief` с четырьмя строковыми полями `work`, `result`, `acceptance`, `boundaries` и собирает Markdown сам. Совместимый путь: `description` с четырьмя непустыми разделами в правильном порядке. Неполная постановка возвращает пояснение до запроса записи в API. Добавлен `parent_id` для создания дочерних карточек.

Внутренний SDK-инструмент сохраняет своё поле `description`; получает тот же формат в инструкции. Обычное ручное создание через API и текст существующих импортируемых карточек Linear не переписываются. Проверка формы не доказывает смысловую полноту текста; соблюдение условий владельца остаётся обязанностью агента.
