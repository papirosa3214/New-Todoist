# Разделение инструкций и личности ролей — 23.10.2026

Общие рабочие инструкции редактируются в одном каноне `server/scripts/role-system-prompt.md`. Файлы `SYSTEM.md` ролей — генерируемые проекции с подстановкой роли и путей. В API канон имеет стабильный слой `role.system`; редактор без выбора области меняет документ всей команды.

`AGENTS.md` — персональные рабочие инструкции, слой `role.prompt`. Исторический resource-хеш пути AGENTS нормализуется в тот же слой; отдельного дублирующего редактора нет. `ROLE.md` — личность, слой `role.persona`. Гендер хранится отдельно и добавляется явным последним правилом самоописания; он не меняет озвучивающий голос или полномочия.

## API

Только владелец, только известная роль.

- GET `/api/roles/:role/behavior` → `{role,text,gender,version,templates}`.
- POST `/api/roles/:role/behavior/templates`, тело `{name,text,gender}` → один шаблон `{id,name,text,gender,builtin:false}`. Сохранение не применяет шаблон.
- PATCH `/api/roles/:role/behavior`, тело `{text,gender,expectedVersion}` → GET-envelope. Нет версии — 428, устарела — 409; неправильные поля — 422.
- Пол — `male` или `female`; текст — непустой, до 64 КиБ; имя — до 120 символов; до 100 пользовательских шаблонов на роль. Встроенные шаблоны поставляет каталог, новые роли получают общий набор.

Активный пол по умолчанию женский у secretary, мужской у остальных. Явная настройка имеет приоритет над грамматикой текста шаблона.

## Хранение и конкуренция

Текст — ROLE.md; метаданные и пользовательские шаблоны — behavior.json внутри папки конкретной роли. Монотонная версия одинакова в редакторе ROLE и behavior API. Внешняя правка ROLE обнаруживается по SHA256 и повышает версию. Сохранение шаблона версию активной личности не меняет.

Операции записи синхронные, с fsync файла и каталога, atomic rename. Применение сохраняет write-ahead журнал behavior.pending.json до двух файлов; следующее чтение завершает прерванную запись идемпотентно. API применяет личность через общий resolver, сохраняя историю. Reset файлов восстанавливает исходный текст истории v0; restore создаёт новую версию. История общего SYSTEM читается в общей области.

## Фактические пути

- roleInstructionText: задачи и консультации получают ROLE и пол один раз.
- chatSystemPrompt и прежний CLI chatInstructionArgs добавляют ROLE и пол один раз.
- Task ResourceLoader не дублирует AGENTS, уже присутствующий в system prompt.
- Unix secretaryVoiceBridge включает те же SYSTEM/AGENTS/ROLE и пол в instructions реального голосового воркера.
- Манифест voice также отражает слой личности.

Фокусные тесты проверяют изоляцию ролей, save/apply, конфликт версий, прямые файловые изменения, восстановление write-ahead журнала, HTTP owner auth, общий SYSTEM и его историю, старый AGENTS alias, task/chat prompt и реальный Unix voice socket.

Изменения источников сами по себе не подтверждают обновление живого сервиса. Перед перезапуском нужна отдельная миграция существующих ролей с резервными копиями. В рамках серверного подзадания restart и push не выполнялись.

Финальный фокусный прогон: roleBehavior.test.ts, runtimeContext.test.ts, roleContextControl.test.ts — 25/25, 23.10.2026. TypeScript npm run build — успешно. Более широкий secretaryVoiceBridge.test.ts имеет три сбоя POST-контракта (403 при отсутствии обязательного chat_id); участок POST в этой работе не менялся.
