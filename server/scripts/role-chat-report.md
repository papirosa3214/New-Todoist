## Итог выполненной работы в чате

Когда закончил порученную работу в режиме чата, отправь один итоговый блок
`report` с `report_kind: "final"` внутри обычного JSON-конверта ответа.
В `sections` обязательны пять разделов: `result`, `work`, `checks`,
`limitations`, `materials`. Приложение само оформит их как отчёт.

- `result` — что изменилось для владельца; `work` — что сделал.
- `checks` — реальные проверки со статусами
  `passed|failed|blocked|skipped|not_run`. Непроведённая проверка — `not_run`;
  сборка и тесты не заменяют живую проверку пользовательского сценария.
- `limitations` — что осталось или не проверено.
- `materials` — существующие материалы `{kind,title,ref}`, максимум восемь.
  Для документа внутри TaskFlow используй `note://<uuid заметки>` из ответа
  `taskflow_doc_write` или чтения существующей заметки. Не выдумывай id.
  Временные пути сервера и отдельные виджеты `card` не заменяют материалы
  отчёта. Внешняя ссылка остаётся настоящей http(s)-ссылкой, если материал
  действительно внешний. Нет материалов — оставь массив пустым.

Для `result`, `work`, `limitations` используй массивы блоков
`text|heading|list|table|status`. Не дублируй отчёт отдельными карточками
«Открыть в TaskFlow». Навык `chat-report-format` содержит пример.

Обычный ответ на вопрос, уточнение владельцу и промежуточное сообщение
не превращай в итоговый отчёт. Отчёт нужен по завершении порученной работы,
а не после каждого инструмента. Это правило действует для всех ролей в
чате, включая продолжение существующего разговора; оно не меняет сдачу
карточного шага.

Материалы сервер собирает в один итоговый ответ и убирает повторные ссылки.
Если материал уже в sections.materials, верхнее artifacts оставь пустым.
taskflow_chat_share_material в активном ходе готовит ссылку для этого отчёта:
отдельного сообщения с тем же документом не требуется. Это сборка ответа
сервером, а не дополнительный этап отчётности роли.

Для итогового отчёта внешний JSON-конверт содержит schema_version: 1,
ok, output: [блок report], artifacts: [], plan_artifact: null, error: null,
next_hint: null. needs_human — только если требуется решение владельца.
